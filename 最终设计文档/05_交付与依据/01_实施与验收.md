## 4. 数学与策略验收

### 4.1 GTO 绑定与图表验收

每个开放的策略教学点逐条检查：

- `matched`节点必须同时提供固定输入指纹、求解器版本／输出哈希、逐组合动作政策、动作前后双方范围、差异解释和后继或停止原因；页面可以从策略层点到范围层再点到下一节点。
- `course_only`与`experiment_only`必须在题面和解析中显示身份及适用条件，不能写成“GTO最优”；`fact_only`只验确定性牌力／金额／补牌；`closed`不进入策略题池。
- 参考策略的动作频率合计为1，范围到达质量按政策守恒，公共牌和双底牌相容性正确，动作后差异能从逐组合数据重算；EV口径与输入底池、后手和抽水一致。
- 至少准备一组阻挡牌、一组下注尺寸、一组对手响应和一组转牌后继样本，人工从原始输出复算并与页面四层图逐项比对。

验收失败时降级为课程／实验／事实身份或关闭节点，不能用邻近节点、平均频率或静态示意图补齐“GTO证据”。

必须有独立样本，不仅检查JSON字段齐不齐：

- 牌力：顺子A低、同花与顺子顺序、公共牌打平、等价最佳五张、重复牌拒绝。
- 金额：下注／加到／新增／待补、全下、未匹配退回、弃牌结算和同街多次加注。
- 范围：对子6／同花4／非同花12，双底牌占牌去重，联合相容性，动作过滤与新牌条件化。
- 策略：向量合计1，非法／不可达／未知不混用，课程范围与具体手牌匹配，原始EV口径可重建。
- 简化：局部固定后续差与全策略损失分开，删尺寸不能只合并频率，边缘采样不改变策略评估权重。
- 后继：任何开放动作对应真实下节点、终局或教学段结束；回放账本全程守恒。

教案A期望结果：过牌6、小注6.6；大注甲7.6、乙4.4。教案B跟注价值1与−1。教案C的AT12→9但ATs3→3。教案D质量2／3／0、构成40／60／0。这些是独立可手算的机制样本，不代表实际GTO局面。

## 6. 低基础学习验收

先进行小批形成性试读，建议首轮3—5位基础薄弱、阅读／操作速度不同的使用者。这个人数只用于发现问题，不提供“所有人都能学会”的统计证明；后续样本量和门槛根据试读结果与目标评估方法另行预注册。

主持者按固定脚本，只读页面说明，不替用户补扑克知识。每个关键停点记录原始首答、额外提示内容、卡住位置、能否返回和能否说出下一步。计时用于发现界面负担，不作为淘汰条件。

| 检查 | 任务 | 失败如何修改 |
|---|---|---|
| 首遍结构 | 不看标题排七步；指出一处交接；在三个未见画面定位当前层 | 修路线、白话、交接提示 |
| 错误恢复 | 注入两处已知错误，选择最近需重查步骤 | 修错误解释与补习入口 |
| 慢速执行 | 未见但有完整依据的题，从局面到动作金额与更新 | 分别修事实、价格、范围或课程适用 |
| 条件迁移 | 改一个独立条件，先说明哪些需重算再作答 | 修对照、反例与原理解释 |
| 连贯路线 | 未见三街、出现加注或提前结束也能接续 | 修后继、继承与行动顺序 |
| 延迟保持 | 间隔后重新定位与执行 | 修提取与回访安排，不新增长期数据库 |

不能用主持者讲完后答对、同题重做、相同结构大量换花色来替代独立证据。某关键层失败，不被总正确率掩盖；先修对应一处，再用未曝光变式复测。

## 7. NL50目标怎样评估

先冻结具体目标配置与覆盖场景，核对抽水、双方范围、菜单、后手与来源。随后独立复核者从输入重建答案、检查课程简化和未知边界；再用未曝光题与连续决策比较参考价值和关键错误分布。

实际决策评估只讨论已覆盖配置，历史短期输赢不直接代表决策质量。门槛、独立题量、置信范围和持续观察要求要在看到结果前确定；当前没有足以填入的校准值，本设计不编造“答对90%等于NL50”。

“软件交付完成”“首遍能学懂”“实际达到目标”分别出结论。用户可以先使用已验证课包；不能为追求最后标签而关闭所有基础训练，也不能为了完成项目而把目标缩成点击完成。

### 开工结论

**现在可以开始执行阶段 C 和 D：先完成一个真实可用的完整教学段，再完成统一界面和图表引擎。** 同时建立 GTO 导入接口，但在匹配数据进入前，所有策略题只能显示课程／实验身份。只有经过配置指纹、逐组合策略、动作后范围、后继和独立复算的节点，才允许升级为`matched`并显示GTO频率或EV。

## 11. 求解器候选输出的可重复验收

当前研究目录中有一份 SB 对 BB、翻牌 Q♠ Q♥ Q♦、100BB、零抽水的求解器候选输出。它已经通过了物理到达权重、终局手牌EV抽查、策略向量归一和根节点频率重算；这些结果可以由以下命令重复得到：

```text
npm run verify:gto-candidate
```

当前复算结果记录在[`gto-candidate-verification-current.json`](../../research/nevir-system/gto-candidate-verification-current.json)，核心数值为：根节点487个组合、1948条逐组合动作EV、双方范围支持487／425／378／457条，策略总质量154515，四个动作频率为0.1024%／55.4144%／44.4831%／0%，策略和的范围为0.9999999627—1.0000000379；物理到达权重检查12768条、决策行4248条、终局手牌EV抽查413条，重载前后完全一致。另有80000条固定种子前向采样和398446次行动账本复核，所有样本区间包含引擎EV；这只证明前向结算与账本一致，不证明最佳响应或策略精度。

这仍然不能把该文件升级为可判分的`matched`GTO课件。当前四个发布阻断条件是：完整独立策略验证尚未通过；范围视图明确不可用于判分；没有恢复用户课程的完整求解配置；它也不是已经确认的NL50目标参考。因此它只能作为作者侧`reference_candidate`保留，不能显示成“正确答案”、不能进入学习者计分，也不能用它生成伪精确范围图。

升级为`matched`前必须同时补齐：输入配置指纹、求解器版本与结果哈希、逐组合策略、动作后到达范围、后继节点、独立复算报告，以及课程配置与求解配置的一致性证明。任一项缺失，节点保持`course_only`、`conditional`或`closed`。
