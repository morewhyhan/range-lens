版本：1.6｜日期：2026-11-01｜用途：指导现有 React／Windows 桌面训练器重新设计与改型。

本目录是新的设计正文。它把此前分散研究收拢成一套可阅读、可实现、可验收的设计，不要求开发者先阅读旧的两百余份文档。正文直接给出规则、页面行为、算法和边界；旧研究只作为证据链接。当前状态是**设计基线与本轮前置条件核验已完成；正式界面改型和未有可靠来源的精确策略数据仍按明确边界推进**。

## 2026-11-01 用户修订与当前实现

翻后以求解器为学习对象，课程只帮助设计训练方法与覆盖，不再以课程文字作为正式策略题的答案键。主界面固定双方范围图；同一决策点可以“换手牌，练这里”，也可“继续这手牌”，不再要求用户选择概念专项或先走强制七步菜单。下文旧的课程／首遍编排只作为历史设计背景；冲突以本条用户修订为准。

当前已实际求解并接入BTN–BB和SB–BB的A72普通牌面完整有限三街树，尚未覆盖全部场景。数学、软件、学习效果分别验收。具体状态与缺口集中记录在[求解工作区实施状态](04_界面与软件/03_求解工作区实施状态.md)。

## 1. 整个产品只做一件事

让扑克基础很弱的人，看得见一手牌中发生了什么，沿固定顺序学习判断，逐渐能在陌生牌局中慢速独立执行，再通过有依据的课程与参考策略训练提高水平。NL50是最终能力目标，不是看完第一遍或答对练习题就自动获得的称号。

学习者脑中先保留四句话：

> 看清现在 → 比较选择 → 做出动作 → 更新后再看。

详细思考只有七步：

> ①认局面 → ②读牌 → ③看范围 → ④比较动作 → ⑤执行 → ⑥更新 → ⑦结束与回看。

知识按当前步骤展开。不会认顺子，就在读牌中补；看不懂阻挡，就在范围或动作比较中展开；补完回到原来的这手牌。首页不摆满知识点。

## 3. 本套文档的约束关系

1. 用户已经明确的要求优先于本设计；材料里的教学建议不能自动成为产品要求。
2. 产品定义决定范围；教学层决定学习过程；数据层决定答案能否成立；软件层负责忠实实现；验收层负责检查实际结果。
3. 某章节存在缺失证据时，在对应节点标注，并交代对用户的影响。不能通过另写一份“合同”宣称缺口已经补齐。
4. 后续修订直接修改对应正文，并在下表记录。保持这12份正文、本入口和一份执行GOAL提示词，不再按每轮讨论新增编号报告。
5. 旧的 L0—L8、P0—P8、C0—C9、U0—U7 等编号均不作为用户导航。本套文档只使用“准备进入一手牌”与七步循环；旧编号只在迁移时查用。

## 5. 本轮前置条件结论（2026-10-23）

本轮只处理开发和数据前置条件，不把“低基础用户能看懂并迁移”提前宣称为已验证。

| 项目 | 结论 | 可核对证据 |
|---|---|---|
| 开发基线 | 已实际验证 | `npm run build` 成功；React/Vite/Electron入口和离线资源可构建 |
| 数据、公式、判分与会话模块 | 已实际验证 | `npm test` 共42项通过；含牌力、听牌、底池赔率、EV、范围后验、题目合法性、范围图定位、计分隔离和无持久化检查 |
| 翻前与读牌材料 | 已核对并接入当前生成器 | 15张图、2535个169格、20个BB位置／尺度映射、九种牌力排序、最佳五张、顺子／同花听牌与摊牌比较均有测试；原工作簿哈希登记在[来源与决策](05_交付与依据/02_来源与决策.md) |
| 翻后局面与可靠答案 | 已做节点级封闭登记 | 58个来源节点全部登记：41个课程规则、12个带明确前提的条件规则、5个资料明确待补并关闭；关闭节点为O01、O02、S06、P01、P07 |
| 范围变化与后继 | 已冻结计算契约和可开放边界 | 每个翻后节点都有范围更新契约和后继状态；有精确后继的只进入已登记教学路线，其余在来源边界收束，不用缺资料伪造范围变化或三街答案 |

本版新增一条贯穿全目录的设计约束：教学图表必须能说明自己在证明什么。牌力／听牌／金额使用确定性图，机制练习使用给定模型图，课程打法使用资料规则图，策略结论才使用同配置、可追溯的GTO参考图；策略图必须能继续点到动作后的范围与后继。没有匹配数据的节点明确降级或关闭，不能用一张漂亮的13×13图替代证据。

因此，下一阶段可以依据本目录直接推进软件改型。推进时只能打开有答案身份、来源、判分任务和后继状态的节点；补充新的精确范围或后继，必须先经过同一登记与独立核算。
