# GTO参考、课程规则与简化流水线

上层：[产品边界](../01_产品与总结构/01_产品定义.md)。计算：[状态与公式](01_状态范围与公式.md)。使用：[出题与判分](03_自动出题与判分.md)。

## 1. 本系统的正确性逻辑

用户资料提供人可执行的简化；匹配求解参考用于观察完整策略、解释为什么这样简化、检验删减的影响。二者分别保存，并为每道题明确“按课程”还是“按参考”回答。

课程明确写出一条规则且范围清楚时，可以按课程规定练习，不能把“尚未和GTO校准”变成整套课程永远关闭的理由。但这条题只能证明按课程执行，不能声称参考最优或已经验证简化损失。

若资料含糊、互相矛盾、牌张非法或适用配置不足，则关闭该策略节点；保留清楚的事实／实验教学。不能根据觉得合理替原课补唯一正确动作。

## 1.1 GTO 图表绑定合同

“和 GTO 结合”不是给每个页面贴一张 13×13 图，而是给每个教学点声明它能由哪一种证据回答。策略结论必须能从同一输入指纹下的参考策略、课程覆盖层和范围变化重建；没有匹配参考时，页面必须明确写“课程规则”或“给定实验”，不能使用“GTO 最优”字样。

每个教学点至少登记以下字段：

```ts
type GtoBinding = {
  status: 'matched'|'course_only'|'experiment_only'|'fact_only'|'closed';
  solver?: { name: string; commit: string; outputHash: string };
  configFingerprint?: string; // 玩家、位置、历史、牌面、后手、抽水、菜单、范围版本
  nodeId?: string;
  views: Array<'policy'|'reach_before'|'reach_after'|'delta'|'ev'|'successor'>;
  courseOverlay?: string;       // 课程动作／尺寸／频率版本
  claim: 'gto_reference'|'course_rule'|'given_model'|'fact'|'unavailable';
};
```

只有`status=matched`才允许显示“参考策略／GTO频率”和对应的EV。`course_only`可以照用户资料训练，但必须同时显示适用条件；`experiment_only`只回答实验中规定的因果关系；`fact_only`用牌力、补牌、金额或摊牌计算，不伪造策略图；`closed`不进入策略题池。求解器版本、配置指纹或逐组合输出缺一项，都不能升级为`matched`。

策略图的最小证据链固定为：**动作政策 → 动作后到达范围 → 与动作前的组合差异 → 下一节点或停止原因**。范围质量与相对构成分开显示；阻挡牌也必须落到具体组合被删／变薄、对手响应和动作频率，不能从“A高”直接推导诈唬结论。课程覆盖层与参考策略并列保存，差异记录必须说明是展示、频率、尺寸、组合条件还是对手模型造成的。

## 2. 仓库具体负责什么

| 组件 | 本项目用途 | 不提供什么 |
|---|---|---|

| b-inary/holdem-hand-evaluator | 最佳五张排名、牌型与结算独立核对候选 | 不给下注尺寸或频率 |
| b-inary/postflop-solver | 作者侧离线求解两名活跃玩家的有限行动树，导出组合策略、EV与后继 | 不自动恢复课程隐藏配置、不负责低基础教学 |
| b-inary/wasm-postflop、desktop-postflop | 参考范围展示、节点导航和输出结构 | 不照搬求解器操作台作为训练页面 |
| b-inary/poker-cfr | 算法与小模型研究补充 | 不作为完整翻后课程的主策略数据 |

源码与公开README核对日期为2026-10-23。postflop-solver说明使用Discounted CFR、合并等价机会分支，并注明公开开发暂停；因此固定提交，不能只依赖未锁版本的main。支持已弃玩家的bunching不代表支持六名活跃玩家同时均衡求解。依据：[README](https://github.com/b-inary/postflop-solver#readme)、[权益计算器README](https://github.com/gto-wizard/equity-calculator#readme)。

运行时读取静态课包，不要求用户电脑在答题时求解巨大树。沿用Electron封装不等于把Rust引擎直接嵌进EXE。源码复制／链接／分发前单独记录许可与版本；当前权益仓库许可待确认，postflop-solver为AGPL-3.0、牌力评估器为MIT，具体集成方式见来源索引，未完成许可确认的组件不直接打包。

## 3. 作者侧九步流水线

| 阶段 | 输入与操作 | 必需输出 | 失败时怎样处理 |
|---|---|---|---|
| 1 定位来源 | 原笔记具体节、工作表行、图像、配置 | 来源快照哈希、局面身份 | 课程规则未定，停止动作题 |
| 2 核对事实 | 牌、前序、位置、底池、后手 | 合法快照、双方起始范围来源 | 只保留已核对事实 |
| 3 定义参考树 | 范围、抽水、下注／加注菜单、全下与机会规则 | 固定配置和输入指纹 | 不启动不完整请求 |
| 4 取得参考 | 固定求解器版本，记录精度、资源与停止原因 | 原始组合频率／EV／到达权重、树或可重载文件 | 局部输出只作对应范围研究 |
| 5 声明课程规则 | 明确尺寸、组合与频率简化、对手条件 | 独立课程政策与指纹 | 不从参考自动臆造课程 |
| 6 比较影响 | 同配置比较参考与课程；改菜单需重解 | 动作差、范围差、收益差、边界牌 | 无校准则不声称损失可接受 |
| 7 编译后继 | 课程动作后的双方范围、回应、新牌、结算 | 节点图、停止原因、连续快照 | 缺支路就结束该练习段 |
| 8 编写课与变式 | 主问题、图、答案、解释、反例、迁移 | 具体可教课包 | 卡位不能代替内容 |
| 9 发布校验 | 牌钱范围、来源、版本、后继、题面 | 只读发布包及报告 | 不通过的节点不入策略题池 |

此流程是作者工作顺序，不是用户看见的九个菜单。

## 4. 判断“究竟简化了什么”

每条课程规定只允许明确采用以下变换：

| 变换 | 示例 | 必须检验 |
|---|---|---|
| 展示简化 | 先显示主尺寸，细节放抽屉 | 不能丢失实际判分输入 |
| 频率简化 | 将已支持的部分混合编为课程0／50／100 | 支持动作、边缘牌、策略价值和后继 |
| 尺寸缩减 | 多尺寸参考保留一个课程主尺寸 | 不等同把被删尺寸频率相加；重解相应受限树 |
| 组合选择规则 | 以明确后门／牌力条件组织候选 | 不误推广到另一纹理、角色或历史 |
| 条件剥削 | 对已声明对手回应模型提高某动作频率 | 触发条件、对手模型、反向偏差风险与失效界限 |

“对手少加注”不等于“对手弃得多”，两种响应都要保存。更宽下注以后自己的转牌范围和对手跟注后的范围都变了，不能接回原均衡树假装没有变化。

Nevir2.1的A72材料既有基础选牌讨论，也有调整对手后全范围小注的建议；分别登记为课程基础／条件调整，不能只摘最后一句盖掉条件。Nevir2.4的高低转牌口诀有前序尺寸和上下文差异，暂不作为所有转牌的统一处方。

## 5. 频率与损失怎样计算

原始参考每个组合动作向量p；课程向量q。翻前按最终图读取，不再优化。翻后若明确批准0／50／100量化，枚举合计1的合法q，且每个非零动作必须在当前菜单合法。

```text
局部频率差(h) = 1/2 × Σ_a |p(h,a) − q(h,a)|
给定后续的局部价值差(h) = Σ_a [p(h,a) − q(h,a)] × Q_ref(h,a)
```

第二式只比较参考后续保持不变时的局部影响，不是整个课程政策的不可剥削性或全局损失。完整课程改变多处策略时，需要重评整条课程策略，计算对固定回应的价值；若要讨论可被利用程度，还需最佳回应或对应求解质量指标。删菜单时要重算受影响的上游和后继，不宣称所有局部差简单相加就是总损失。

阈值按课程版本、节点、边缘层和参考噪声预先确定。目前没有已校准的通用阈值，因此本设计不填“损失小于0.01BB就都算正确”。先用同输入更高精度／重复参考估计误差，再由独立复核选择容忍线。不能因为两个动作EV很近就把所有动作都视为100%正确；课程频率答案仍按所选课程规则判。

## 6. 一条差异记录至少写这些

```text
来源节与适用范围
参考输入、求解版本、菜单、精度和输出哈希
课程规则身份、规则版本、允许动作与组合选择条件
每组合参考向量／课程向量／局部价值差
按真实到达质量加权的整体差与分层边缘报告
每个动作后的双方范围与后继
哪些结果需重解、哪些仅属给定后续估算
可开放题目、不可开放节点、原因
```

边缘牌在练习里多抽，与评估策略时按真实范围质量加权是两件事。不得因为某题难、出现得多，就把它在总体策略价值里放大。

## 7. 课包数据合同

```ts
type LessonPackage = {
  packageId: string; version: string;
  config: FrozenConfig; sourceRefs: SourceRef[];
  nodes: Record<NodeId, NodeSnapshot>;
  ranges: Record<RangeStateId, RangeState>;
  referencePolicies: Record<NodeId, Policy|null>;
  coursePolicies: Record<NodeId, CoursePolicy|null>;
  teachingFrames: Frame[]; variants: VariantSpec[];
  answerKeys: AnswerKey[]; // 首答界面只接收题面投影
  differences: DifferenceRecord[];
  successors: SuccessorEdge[];
  availability: AvailabilityRecord[];
};
```

规则身份至少分事实、给定实验、课程规则、匹配参考、条件调整、未知；各有判分权限。不把`sourceKind=solver`自动变成`courseRule=true`。发布哈希覆盖配置、范围、规则、菜单与依赖版本；同一个显示标题不是数据身份。

## 8. 当前可复用的研究与实际缺口

现有QQQ研究有达到内部停止线的求解候选、保存重载与选定节点核对；导出仍缺后继，且没有完整课程政策与迁移数据。它可复用为作者工具验证，不能替代A72、其他纹理或全部35项。具体历史证据：[QQQ桥接审计](../../research/nevir-system/qqq-v2-course-bridge-audit.json)。

当前122条课程／条件候选只是材料筛选结果，不是122条已编译规则；374行材料也不是374道有效策略题。新课包逐条语义复核，原始行哈希用于追溯，不用关键词识别结果直接生成正确答案。原始材料权限、具体引用见[来源与决策](../05_交付与依据/02_来源与决策.md)。

## 9. 本轮翻后数据闭环

本轮没有把缺少逐组合策略的来源行“补成GTO答案”，而是把来源全集编译成明确的开放登记：[翻后覆盖登记](../../src/postflop-registry.js)。登记结果固定为58个节点：41个课程规则、12个条件规则、5个关闭节点。每个节点都同时有答案权限、来源、可判分任务、范围更新契约和后继状态。

因此，翻后目前的“已明确”有两层含义：

1. **策略题层**：开放节点可以按课程规则或声明的条件判分；资料待补节点不进入题池。
2. **范围／连续层**：所有节点都知道应从哪个到达范围更新、需要哪些逐组合和回应数据、何时必须停止；只有已登记教学路线才继续到下一个具体节点。

第二层是实施前置条件，不冒充已经拥有全部solver后继。后续若导入匹配参考，必须把`referencePolicies`、`ranges`、`successors`和`differences`填入同一课包并重新跑登记测试，不能只改显示文本或把“方向”字段当成范围图。
