# 牌局状态、范围与计算公式

上层：[设计入口](../00_从这里开始.md)。消费者：[范围图](../04_界面与软件/01_界面与交互.md)、[判分](03_自动出题与判分.md)。

## 1. 唯一牌局状态

每题绑定不可变的节点快照；操作通过事件产生下一快照。显示用的字符串不能成为计算源。

```ts
type NodeSnapshot = {
  nodeId: string; configId: string; historyHash: string;
  street: 'preflop'|'flop'|'turn'|'river';
  seats: Seat[]; button: string; activePlayers: string[];
  board: CardId[]; heroSeat: string; heroHole?: [CardId, CardId];
  actor: string|null; lastAggressor: string|null;
  potTotal: number; // 含当前已投入筹码，不含尚未匹配但将退回的金额修正
  stackBySeat: Record<string, number>;
  paidStreetBySeat: Record<string, number>;
  toCall: number; legalActions: ActionSpec[];
  history: Event[]; rangeStateId: string;
  terminal: null|'fold'|'showdown'|'segment_end';
};
```

内部金额用整数筹码单位或精确有理数，渲染才转BB；不能让显示四舍五入改变合法金额。`segment_end`是教学段结束，不是扑克终局，不能分配底池。六人座位存在但只允许已匹配的活跃人数进入精确策略题。

角色由历史推导：翻前最后加注者、翻前跟注者、当前街最后进攻者分开存。IP／OOP由当前仍在底池的座位行动顺序求得，不用hero固定标签。

## 2. 钱怎样算

### 2.1 跟注

令`P`为当前已经在底池里的全部钱，包含对手已下注额；`C`为自己还需补的钱。跟后底池为`P+C`，自己后手减少`C`。河牌最后行动、无抽水且无后续下注时：

```text
跟注权益门槛 = C / (P + C)
跟注净收益   = equity × (P + C) − C
弃牌净收益   = 0（从当前决策点起）
```

如果改用“对手下注前底池P0、对手下注B”的命名，则P=P0+B、C=B，分母为P0+2B。两种写法不能在同一题里混用。

抽水要按课包的终局规则扣除，不能一律扣下注额百分比。有未来行动时，上式只解释价格，不足以直接推出动作。

### 2.2 加注

界面分别显示“加到R”“本街已经投入H”“本次新增R−H”。对手之后待补额按双方本街投入差计算。全下按可投入金额限制，未匹配筹码退回；多方边池不是简单两人主池公式。

例：自己本街已下4，对手加到12，自己待补8。若再加到30，本次新增26，不是30，也不是18。当前底池已含自己的4和对手12，后续每笔只加一次。

合法加注与重开行动权要保留最近完整加注幅度、剩余筹码与此前行动标记；不得只用`minRaise = currentBet * 2`覆盖所有局面。不能可靠支持的特殊状态退出策略题池，不用错误按钮代替。

### 2.3 无加注、直接结算的河牌下注实验

令P为下注前底池，B为下注额，F为对手弃牌概率，e为被跟注后的分池权益：

```text
EV(bet) = F×P + (1−F)×[e×(P+2B)−B]
```

这需要无加注、无抽水、无未来行动等明确条件。e不是原范围权益，必须对**跟注后的范围**求得。零权益诈唬在此模型的盈亏平衡弃牌率是B/(P+B)，不是整套翻后自动下注标准。

一般动作价值为所有对手回应与后续终局的概率加权净收益；存在加注或转河牌时，不能删掉那些分支。求解器导出的EV须先确认是当前节点净值、包含底池的价值还是其他口径，再转换，不能与上述数字直接拼接。

## 3. 牌力与权益

德州用可见牌中的最佳五张；比较以牌型和踢脚排名为准。评估器返回排名与可选最佳五张集合；策略算法不能从排名直接推出下注。

权益是最终分池份额的期望：单独赢计1，平分k人计1/k，输计0。对指定合法对手底牌和所有合法跑牌枚举，再按相应权重求和。

```text
equity = Σ legalStates probability(state) × potShare(state)
```

若仅在“自己底牌+翻牌”已知且其余牌均匀的物理实验中，未知牌47张，下一张命中某9张花色为9/47；连续两张至少命中一张为1−(38×37)/(47×46)。这只描述事件，不保证成花后获胜。已知对手两张牌时剩45张；未知对手有加权范围时，须对相容组合和跑牌一起积分，不能继续套均匀47张。

## 4. 范围最小单位是具体两张牌

169格是展示索引，底层是1326个无序实体组合。未被占牌时，对子6种、同花4种、非同花12种。格子50%表示每个该类组合按课程规定继承相应行动权重；若来源在花色间不同，必须保存具体组合，不能用一个平均格覆盖。

```ts
type ComboWeight = { combo: [CardId, CardId]; weight: number };
type ActionPolicy = {
  nodeId: string; owner: string; sourceIdentity: string;
  byCombo: Record<ComboId, Record<ActionId, number>>;
};
```

每个可达合法组合的动作频率非负且合计1。不可达组合不是默认全弃；`unknown`、`unreachable`、`physically_impossible`、合法0%分别存。

## 5. 物理移除与行动更新

### 5.1 单方给定范围的演示

```text
w_legal(h) = w_before(h) × I(h与已知牌不冲突)
w_after(h,a) = w_legal(h) × P(a | h,node)
M_after(a) = Σ_h w_after(h,a)
q_after(h,a) = w_after(h,a) / M_after(a)
```

这套公式适合“已给单方范围和响应”的教学，不代表完整双边后验已经正确计算。M=0时该动作在该范围下不可达，不能除零或生成一题。

### 5.2 双方相容性与联合权重

两人的底牌不能重复。完整课包至少保留或能重建联合质量：

```text
J(h,v) ∝ rHero(h) × rVillain(v) × I(h,v,board互不冲突)
观察hero动作a：J1(h,v) = J(h,v) × πHero(a|h,node)
观察villain动作b：J2(h,v) = J1(h,v) × πVillain(b|v,nodeAfterA)
```

自己的范围边际对v求和，对手范围边际对h求和，再归一化。带弃牌玩家bunching时还需相应的合法发牌条件，不能继续当简单乘积独立模型。实际导出优先使用求解器能证明口径的到达权重，独立算法负责核对。

对于用户已知的一手h*，其所见对手范围是J(h*,v)的条件分布；不能一边使用hero全范围边际，一边声称已按h*准确阻挡。

**重要视角差别**：用户知道自己h*时，单看自己已经选择下注，不会新增关于对手底牌的行为信息；全范围旁观视角下，自己的动作可以经牌张相容性改变对手边际。图表必须说明在看“自己的这手牌”还是“双方整体范围”，不把这两种结论互相否定。

### 5.3 新公共牌

从上一行动后的联合／条件范围出发，乘以合法发出新牌的条件概率，移除冲突组合，再求新边际和新策略节点。无bunching且给定双方具体底牌时，每张剩余合法牌的机会相同；按范围边际看则不一定均匀。不能先清空历史取翻前范围，再只删新牌。

## 6. 图表的分母、强端与范围差

两种视图都需要：

| 视图 | 数值 | 回答的问题 |
|---|---|---|
| 组合质量 | 每组合w或相对同一原始基准的w/M0 | 有多少份组合留下，具体减少在哪里？ |
| 相对构成 | 当前q=w/Σw | 已留下的范围里，这类牌占多少？ |

动作前后质量视图保持同一坐标和基准M0；相对构成视图分别归一化，标题直接写分母。不能要求两图共用旧分母同时每张又合计100%。

牌力结构按指定公共牌和对手范围计算。平均权益、最强部分的质量、被继续后的权益与未来实现分开显示；“坚果优势”不硬编码成“有超对就有坚果优势”。真实坚果随公共牌变化，强端统计必须声明比较阈值。

参考与课程的范围差在相同输入、同视角、同动作语义下比较；同时报告质量差与相对构成差，避免小范围归一化后看似巨大变化。

## 7. 一次干预与派生重算

对照题写出：`intervention`、`heldInputs`、`derivedChanges`。例如改变对手下注额，其余独立范围假设固定，派生待补、跟后池、后手与门槛全重算。改变一张转牌，需要重算物理合法性、最佳五张、范围条件和对应参考节点。

动作目的、最终EV、跟后权益等通常是分析结果，不应随意作为独立输入去拨滑条。给定实验确实外生规定对手响应时，标明“实验条件”；真实策略对照须重新求解或取得对应参考。

## 8. 最低计算验收

独立核对：重复牌、最佳五张同分、顺子A低、行动向量、金额守恒、未匹配退回、范围过滤、联合相容性、零质量节点、条件发牌、视图分母、求解EV口径。例题答案需有独立枚举或手算样本，不能只让生成器再跑自己证明自己。

底层参考接口与精度说明见[求解器官方文档](https://b-inary.github.io/postflop_solver/postflop_solver/)、[权益计算器README](https://github.com/gto-wizard/equity-calculator#readme)。本章代数为当前决策点和明示条件下的推导，不能超出条件解释成普遍策略。

## 9. 本轮软件模块核验

当前代码已经用独立样本核对了可以在本地运行的公式模块：

| 模块 | 已核对内容 |
|---|---|
| 牌力引擎 | 重复牌拒绝、A2345、同花顺、四条、葫芦、踢脚和公共牌平分 |
| 听牌引擎 | 卡顺、两头顺、直接同花听牌、后门同花、去重后的具体补牌 |
| 金额 | `potOdds(P,C)=C/(P+C)`，其中P已经含对手下注；河牌实验的所有回应分支与过牌基线 |
| 范围更新 | 旧质量乘行动概率，再按本次行动总质量归一化；零质量行动拒绝生成 |
| 判分 | 频率向量、最佳五张等价解、顺序题、数据无效和“我不知道”的不同处理 |
| 会话计数 | 模块／位置／尺度／节点／任务隔离；首答只计一次；无数据库、网络或长期保存 |
