# 界面、视觉对象与交互细节

上层：[产品定义](../01_产品与总结构/01_产品定义.md)。状态：[软件改型](02_软件改型.md)。范围语义：[计算规范](../03_数据与算法/01_状态范围与公式.md)。

## 1. 整体气质

以现有用户认可的极简圆润方向继续：浅暖灰背景、近白训练面、深灰正文、柔和边界、大圆角、少量阴影。苹果感体现在克制和一致，不是到处玻璃模糊。瑞士排版只保留清晰对齐、层级与留白，不做巨大海报标题或官网首屏。

基础设计变量：8px间距网格；普通控件圆角12px，训练面20px，卡牌10px；正文16px起，解释16—18px；主要操作目标至少44px高。具体数值作为第一轮实现基线，按截图与慢操作试读调整，不声称单靠数值就可访问。

## 2. 固定布局与宽屏利用

```text
┌─────────────────────────────────────────────────────────┐
│ 返回   当前练习／步骤                  本组 8对 2错  设置 │
├──────────────┬───────────────────────────┬───────────────┤
│ 六人小桌子    │      一个中心训练对象       │ 答后解释／帮助 │
│ 当前历史摘要  │  牌面／范围图／一次变化      │ 默认可收起     │
│ 路线当前位置  │                           │               │
├──────────────┴───────────────────────────┴───────────────┤
│        当前一句问题 → 动作按钮 → 我不知道／下一题         │
└─────────────────────────────────────────────────────────┘
```

这张图表示区域归属，左侧不是永久满高导航栏。答题前右侧没有解析时，中心区扩展；答错后范围图占主要高度，解释在右侧。不能把重要答案图放在页面最下方让用户滚动寻找。

布局采用可用宽高驱动的CSS grid与卡牌／矩阵尺寸，不以整体`transform:scale()`扩大固定页面。根容器使用动态视口高度；中心区`min-height:0`，只有内容溢出的解释面板独立滚动。题面与动作栏保持可达。

| 视口参考 | 布局策略 |
|---|---|
| 1366×768 | 桌面与历史收成紧凑摘要；中心约占可用宽度70%；解释侧栏可展开；必要时只让解释内部滚动 |
| 1920×1080 | 中心区随可用高度扩大，范围矩阵格约38—48px，卡牌约80—110px高，解释侧栏可并列 |
| 2560×1440及以上 | 增大中心视觉、卡牌与字号，中心约占可用宽度60—70%；正文行宽保持约28—38个汉字；不只增加四周空白 |
| 窄窗口／系统200%缩放 | 收起两侧，桌面摘要顶部，解析用侧面抽屉／覆盖面板；动作可换行，绝不缩到不可点击 |

13×13矩阵优先取可用宽高较小者形成正方形，整体居中。不能为占满屏幕把169格拉成极窄长方形。系统缩放下用CSS像素检查，4K物理像素不等于需要四倍界面大小。

## 3. 扑克牌

统一用代码绘制卡面，点数、花色均可读；红桃方片红，黑桃梅花深灰，花色符号和点数保证颜色以外的辨识。角标、中心花色、阴影适度，不使用复杂照片纹理。公共牌与手牌有明确文字标签和位置，不靠尺寸猜角色。

新牌只短暂突出一次，最佳五张用轮廓和编号；原牌不重排到别处。未来牌在首答前不显示；对照实验使用独立标记，避免用户以为已经发出后街。对手明牌只用于明确的事实／实验，不泄露真实策略题隐藏信息。

## 4. 六人小桌子

六座位固定几何位置，按钮D可见，自己用双轮廓与“你”，当前行动者用箭头和“轮到他／你”。已弃玩家变淡并标“弃”，还在池里的两人保留。每座位可显示一行最近动作，长历史进入可展开摘要。

座位显示UTG／HJ／CO／BTN／SB／BB并支持白话名称；当前IP／OOP由实际两人关系解释。若题目是综合压缩图且无精确对手，只显示明确资料，不补一个假想座位制造确定感。

回放按钮按时间播前序，默认约500—700ms一动作，可暂停、跳过、减弱动画；回放不自动改题、不重计分、不引入资料未写的行动。用户可直接读文字摘要，动画不是唯一信息来源。

## 5. 范围图是中心教学对象

### 5.1 默认图

13×13固定坐标，AA左上、22右下，上三角同花、下三角非同花。格中写手牌类别，边界或分区有语义图例。点击格子打开当前局部组合面板；看完关闭回原格和原问题。

切换对象必须显示标题：“你的整体范围／你拿这手时对手的可能牌／对手整体范围”，不可只写“范围”。同时显示街次、最近历史节点、数据身份和当前分母说明。

### 5.2 四种状态不能同色

| 状态 | 视觉 | 意义 |
|---|---|---|
| 物理不可能 | 斜线或叉，低对比底色 | 与公共牌／已知底牌冲突 |
| 动作减少 | 填充变薄或份额条缩短 | 按已知动作频率减少 |
| 合法0% | 明确0与空填充 | 当前动作在该组合中不采用 |
| 未知 | 点纹与“未提供” | 没有依据，不能画成弃牌 |

颜色映射在全应用一致；动作可用低饱和蓝／琥珀／灰等方案，最终以用户原图映射为准。判对绿色、判错红色不复用为战略动作语义，避免“红色下注”被误读成错误。

### 5.3 前后对照

默认同一矩阵原位变换，上方“动作前／动作后”切换；高分辨率可并列两图，但坐标与格尺寸完全相同。主视图先用组合质量；“看留下的牌里各占多少”切换到相对构成，标出新总量。箭头只表示已发生的一次筛选，不能同时演示回应与新牌。

用户必须看见当前动作、动作后总质量以及选中格的变化。点击某格时，旁边只显示该格的“原份量×动作频率=留下份量”；完整公式收进详情。

### 5.4 原图定位与明显高亮

答错时目标格用黑白双描边、四角定位标、行列引导与轻微呼吸光，不依赖挑一个原图里没用过的新颜色。减弱动态模式关闭呼吸，保留轮廓。混合格保留原填色，不遮掉50／50信息。

原SVG只有在存在准确`cellId→path/bounds`映射时才可定位。嵌入位图要登记原尺寸和网格矩形；窗口缩放时按viewBox变换，不凭169等分猜整张截图。没有可靠坐标时使用核对后的代码矩阵为主图，原图留作来源，不假装已高亮正确格。

### 5.5 GTO 图表的分层显示

策略题的中心图按四层展开，但一次只突出一层，避免把求解器输出变成信息墙：

| 层 | 显示什么 | 用户要回答的问题 |
|---|---|---|
| 策略 | 当前节点13×13组合的动作频率／课程动作覆盖 | 这个组合在当前条件下怎么处理？ |
| 到达 | 动作前与动作后的双方范围质量 | 这次动作让哪些组合留下或减少？ |
| 差异 | 选中格的组合、频率、EV或质量变化 | 为什么是这些牌受到影响？ |
| 后继 | 对手回应、新牌或终止节点 | 下一步状态从哪里来？ |

答错后先展示“正确动作＋策略层”，用户点击“看范围变化”才展开到达层，点击具体格才进入差异层；下一步再进入后继。图表顶端固定显示节点、配置指纹、参考／课程身份和数据日期。求解器策略、课程覆盖和给定实验用不同标签与纹理，不能只用红绿区分。事实题只显示牌力／补牌／最佳五张图，实验题只显示其给定模型与公式，不假装是GTO策略。

## 6. 动作按钮与反馈

按钮视觉轻、边界清楚；主问题下只显示当前合法动作和“我不知道”。需要频率时按钮写完整组合，例如“跟注50%／弃牌50%”，不要求用户分别点两次。

| 事件 | 界面行为 |
|---|---|
| 快练答对 | 按钮绿色勾与“正确”，约650ms后下一题；可选手动推进 |
| 教学小操作答对 | 展示当前变化，保留“继续” |
| 答错 | 红色叉与“本题答案…”，中心显示相关图，右侧局部解析，按钮“下一题／这一步没懂” |
| 我不知道 | 按错题计数，解释以“先从这里看”开头，不真的执行弃牌 |
| 数据不足 | 不计分，显示“本段到这里”和缺失信息，允许换段 |
| 完成一轮 | 显示本轮对／错与“继续练／返回”，无排行榜和成绩仪表盘 |

解释默认三小段：正确操作 → 本题关键关系 → 条件变了先重查哪一步。引用与原始资料放“依据”抽屉；原始资料不能承担主要解释。

## 7. 设置与导航

设置只显示当前练习相关项：图表／场景、单项／混合、边缘比例、动画与自动推进。本轮计数范围在应用时更新，草稿改动不会在半途改变当前题。打开设置取消自动计时，关闭可回原题，应用才开始新配置题。

翻后首页先显示“专项训练／连贯训练”两个平级入口。进入专项后按能力列表逐层展开，顶部路径可退回上一级；进入连贯后才显示当前站和相邻方向，可展开整条路线。两者不混成七个强制永久按钮，也不把35项清单平铺给用户。

## 8. 键盘与可访问性

数字键对应当前可见选项，0或问号对应“我不知道”，Enter只在允许推进时下一题，Escape关闭当前抽屉／补习。输入框聚焦时不拦截数字；长按不重复提交。

所有按钮有文字或可读标签，焦点轮廓可见；打开抽屉焦点移入并限制，关闭回到触发控件；新题朗读一句问题与牌面，不重复播整张169格。颜色不作为唯一反馈，正文与控件对比度在实现时按WCAG相关标准实测。无倒计时和速度惩罚。

验收基线按[WCAG 2.2](https://www.w3.org/TR/WCAG22/)的相应条件检查：普通文字至少4.5:1，大字号文字至少3:1；表达控件与状态所必需的非文字视觉至少3:1，并检查键盘可操作、焦点可见和不被遮挡。44px目标是本产品偏向慢操作用户的设计值，不宣称它就是所有WCAG条款的统一尺寸要求。

## 9. 页面验收场景

同一题依次验证正常、答对、答错、未知、子练习、返回、设置、来源、窗口缩放与无后继。宽屏和小屏都截完整视口，确认图表没有落到下方、按钮没有被遮挡、焦点不丢、统计能刷新。静态好看不能替代完整交互检查。
