# 软件改型、状态流程与模块职责

上层：[界面与交互](01_界面与交互.md)。数据：[课包流水线](../03_数据与算法/02_参考策略与课程简化.md)。交付：[实施与验收](../05_交付与依据/01_实施与验收.md)。

## 1. 改型范围

本文件定义改型如何落地。沿用React、Vite与Electron；不引入云服务、账户、数据库或另一套网页托管。用户已认可的圆润基础视觉可复用，但课程结构与数据流重新组织。

当前实际入口为 src/range-trainer.jsx，计算在 src/postflop-model.js，原生求解进程由 desktop/solver-service.cjs 管理，Electron preload只暴露受限的配置与节点查询。已接入两套普通A72有限三街树。旧GoldenPath、专项列表与QQQ局部工作区不再作为翻后入口。状态、证据和缺口统一见[求解工作区实施状态](03_求解工作区实施状态.md)。

## 2. 当前代码如何处理

| 当前文件 | 可复用部分 | 改型要求 |
|---|---|---|
| `src/main.jsx` | 应用壳、基础快捷键、范围设置入口 | 翻后首页只负责选择专项／连贯；两种模式分别进入自己的题序和会话计分，不互相伪装 |
| `src/learning-ui.jsx` | 卡牌、部分机制可视化、题内互动 | 拆出渲染组件；现有skill选择器改为父层专项路径；不得继续以组件内大量局部状态决定课程 |
| `src/preflop.js` | 动作向量、格子与实体牌映射思路 | 核对图的动作语义；拆分边缘分类与抽样；禁止虚构对手位置 |
| `src/poker.js` | 牌力、牌张解析等函数候选 | 独立交叉验证、支持等价最佳五张；不将牌型分类变成策略公式 |
| `src/questions.js`、`learning.js`、`curriculum.js`、`rules.js` | 来源清楚的事实实验与明确课程条款 | 逐项归入新课包；未证实策略不直接搬到答案键；避免保留三套生成器同时可见 |
| `src/session.js` | 会话内计分思路 | 统一范围键、首答锁、未知／无效区分、定时器管理 |
| `desktop/main.cjs` | 本地协议、打包、临时profile及退出清理 | 验证离线资源和无长期学习记录；不因迁移增加持久用户状态 |

这里只根据读取代码确定迁移方向，不宣称已经逐行审完或通过所有运行测试。

## 3. 推荐职责边界

```text
AppShell                 页面框架、路由、模态层
SessionController        当前父层、题序、模式、首答、计数、定时器
CurriculumNavigator      七步循环与当前专项路径
PackageRepository        只读静态课包与可用性索引
QuestionFactory          筛选、抽样、合法题面投影
Grader                   按答案身份核对，不直接操作UI
PokerStateEngine         牌、钱、行动与后继
RangeEngine              组合权重、相容性、过滤和图表投影
ExplanationPresenter     结构化解释与相关对象定位
ViewComponents           卡牌、桌子、矩阵、行动栏、子层、设置
```

作者侧求解与编译在独立脚本／工具中运行，生成带版本静态文件。练习进程只读数据和做轻量事实计算，不调用网络语言模型补答案。

## 4. 两个正交状态

### 4.1 牌局状态

`nodeId + snapshot + rangeStateId + history`决定真实事件和下节点。`APPLY_ACTION`、`OBSERVE_RESPONSE`、`DEAL_CARD`、`SETTLE`必须通过引擎合法性检查。

### 4.2 学习界面状态

```ts
type LearningSession = {
  mode: 'guided'|'practice'|'continuous';
  step: 'context'|'read'|'range'|'compare'|'execute'|'update'|'review';
  questionKey: string;
  status: 'presenting'|'answering'|'feedback'|'explanation'|'segmentEnd';
  selected: unknown; firstAttempt: Attempt|null;
  scoreScope: string; scopeScores: Record<string, {right:number,wrong:number}>;
  panel: null|'settings'|'source'|'remedial';
  parentSnapshot: ParentLearningSnapshot|null;
  currentVisualState: VisualState;
};
```

打开来源、看对照和重放动画不修改真实牌局；点“我不知道”也不向牌局提交弃牌。指导课的“看一次正确示范”不是一次用户首答。

## 5. 核心事件转换

| 事件 | 前置条件 | 状态变化 |
|---|---|---|
| START_SCOPE | 已选配置有合法题 | 新题、空首答，读取本会话对应计数 |
| SUBMIT | 当前可答、没有首答、无覆盖层 | 判分一次，锁首答，进入反馈 |
| SHOW_EXPLANATION | 已作答或示范模式 | 显示相关事实与范围；不重新计数 |
| NEXT | 已答／示范已完成，允许推进 | 取消定时器，按题序／后继取下一题 |
| OPEN_REMEDIAL | 有父题且无其他面板 | 保存父快照，打开补习 |
| CLOSE_REMEDIAL | 父快照仍有效 | 恢复原题、首答、焦点、视图，清空子层临时牌 |
| APPLY_SETTINGS | 草稿校验通过 | 建新scope，重建题序，不修改旧题答案 |
| OBSERVE_EVENT | 当前后继存在且事件合法 | 更新牌局，再进入对应学习步骤 |
| MISSING_DATA | 课包缺需要的证据 | 教学段结束，不判错、不填默认动作 |

禁止通过React渲染时的副作用反复生成下一题。题序和计分交给明确事件，组件只显示派生结果。

## 6. 定时器、竞态与返回

每次题目有不可变generation token。自动下一题回调先验证token、当前题、面板关闭和反馈状态；题目切换、打开面板、模式改变、卸载时取消。重复点击或键盘长按由首答锁拒绝。

后台窗口隐藏时暂停自动推进与回放，恢复后保持原题，不把已经消失的反馈连跳两题。连贯练下一节点只能从已提交事件查询，不能以随机题替代。

父快照恢复逐字段比较：牌、范围视角、题目ID、首答、计分、历史、滚动／焦点。子层练习的对错不污染父题计分；如要显示子层小计，须有独立scope。

## 7. 无长期保存怎样实现

课程静态文件、源图和程序资源可以存磁盘，它们不是学习记录。成绩、设置草稿、题序seen集合、推荐进阶和作答记录只放内存；禁用localStorage、IndexedDB、用户文件、分析上报等持久学习状态。

Electron临时profile可以有运行必需的缓存文件，退出清理；不能对用户承诺操作系统绝无任何临时文件。产品承诺是“不建立或保存学习档案”。异常退出后的临时残留不应包含作答正文；下一次启动不自动恢复旧记录。

可离线安装课程更新属于内容分发，不是用户进度保存。首次改型不增加导入／导出成绩功能。

## 8. 逐步替换而不丢有效内容

先冻结现有版本备份和有效素材索引；在新壳中接入翻前与读牌，再接一个有完整数据的教学段，之后迁移真实翻后课包。旧翻后页面仅在开发分支对照，不在发布版保留两个相互矛盾入口。

每段旧内容记录“保留／改写／待证／退出发布”，特别是模型题改名“给定实验”，未恢复的GTO动作不沿用。后台35项清单保留兼容ID，不要求用户看到旧编号。

## 9. 错误处理

缺包、哈希不匹配、非法牌、空题池、不可达节点、未知后继分别有可读错误与开发原因码。用户可返回上一级或选择其他段；不白屏、不把异常堆栈放成教学解释。

发布前验证网络断开仍能读卡牌／SVG／课包，EXE移动目录后可启动，中文路径正常；打包不能依赖工作区绝对路径。设计文档中的绝对来源链接只服务作者，不放入用户运行时路径。
