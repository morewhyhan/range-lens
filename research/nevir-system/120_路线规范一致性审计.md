## 审计目的

路线文档很多，不能因为每份都写了“嵌套”就假定它们的顺序完全一致。这份审计只检查规范之间的结构关系，不检查页面，也不把通过 JSON 检查当作学习效果。

当前唯一的顺序真源是 [119号目标级单一路径运行蓝图](119_目标级单一路径运行蓝图.md)：

```text
p1_context → p2_board → p3_range → p4_compare
→ p5_execute → p6_update → p7_close
```

内部 ID 也已经统一。历史合同里出现的 `p2_board_and_hand`、`p3_range_and_blockers`、`p7_close_and_transfer` 只保留为读取别名，运行时必须先归一化为 `p2_board`、`p3_range`、`p7_close`；“牌面和自己的牌”“范围和阻挡牌”“收口和迁移”是这些节点里的白话标题或子内容，不是新的顶层步骤。

其他文件中的 `children` 表示“可以从当前父层按需打开的内容集合”，不表示这些内容要同时显示，也不取代 `next` 链。

## 已确认一致的部分

- `first-run-route-contract.json`、`first-pass-experience-map.json` 和 `parent-step-mastery-contract.json` 的七个 p1—p7 节点顺序相同；
- 规范L0—L4的翻前入口接着p1—p7翻后链推进；旧L5—L8只作为作者侧映射，不能作为第二套学习者顺序；
- 五个35项后台组仍然挂在 p4 或 p6，不产生新的顶层入口；
- 子层均要求返回父帧，且父帧需要恢复牌面、历史、金额、范围和首次答案；
- 资料不足时，旧合同和新合同都要求停在事实/示范层，不编造策略。
- 首遍交接审计逐项检查七条主链边和八个行动链节点；p3 首遍必须可见动作前范围、物理排除、行动筛选状态和固定分母。

## 已识别并已迁移的旧合同差异

部分旧合同的首遍检查只有三项，使用不同名称：

| 旧写法 | 规范化含义 |
|---|---|
| `one_transfer` | `one_variable_transfer` |
| `one_field_transfer` | `one_variable_transfer` |
| `one_variable_transfer` | 保持原名 |
| 没有 `error_recovery` | 只代表旧版最低检查，不足以发布“建立路线” |

`layer_location` 已经包含“说出下一步要查看的唯一输入”，不再单独增加一个并列按钮。`one_variable_transfer` 同时要求慢速完成一次动作或更新，并把金额、范围和行动权接上。

这些旧写法已经在机器合同中统一为四项规范：`order_recall`、`layer_location`、`error_recovery`、`one_variable_transfer`。历史别名仍保留在本审计的兼容映射中，便于读取旧快照；运行时不再使用三项检查作为完整首遍证据。

## 发布阻断条件

以下任意一项存在，运行时路线不能发布：

1. p1—p7 的 `next` 顺序与规范主链不一致；
2. 某个子层没有明确 `returnTo` 或关闭后不能恢复父帧；
3. 将 `children` 直接渲染成同时可见的首页菜单；
4. 首遍只记录按钮点击，没有 `error_recovery` 或单变量迁移证据；
5. 缺少策略参考或后继时仍让用户继续精确判分。
6. 任何文件把兼容别名当作新的 p 步骤，或把 p3 的范围交接字段藏到独立练习才显示。

机器审计结果见 [route-consistency-audit.json](route-consistency-audit.json)。当前结果是“主链一致、主要检查合同已统一”，不是运行时已通过。

## 下一步

下一步让运行时只读取规范化主链，并用低基础成人试读观察：用户是否真的知道下一步、答错后是否能回到最近缺失层、是否能在单变量变化后慢速完成一次动作。只有这些证据出现，才能把“文档路线一致”提升为“用户形成路线”。
