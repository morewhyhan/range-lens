## 这份合同解决什么问题

`postflop-solver`能回答“在一组明确输入和有限行动树下，每个具体组合的动作频率、EV和后继节点是什么”。训练器需要回答的是另一件事：“学习者在这一屏先看什么、点击什么、为什么、动作后范围怎么变、下一步如何继续”。两者之间不能直接相连，必须先把求解器快照编译成可追溯的课包。

本合同以本地保存的 `b-inary/postflop-solver` 快照为依据：

```text
commit: 9d1509fe5077d019825f833eed04b16d342dfda1
snapshot time: 2023-10-01T21:59:55+09:00
license: AGPL-3.0-or-later
```

这只是接口和字段的事实核对，不代表已经得到与课程条件匹配的完整求解结果，也不代表可以把引擎直接放进可分发的 EXE。许可、源码提供义务、构建方式和运行时分发仍要单独过闸。

## 一、求解器真正需要的输入

### 1. 牌与范围输入

`CardConfig`固定两名活跃玩家的初始加权范围，以及翻牌、转牌、河牌。范围不是一个“百分比标签”，而是按具体两张底牌组合保存的权重。当前快照只求解 OOP 与 IP 两个活跃玩家；六人桌中已弃牌玩家的 `bunching` 影响是额外修正，不能被描述为六名仍在底池玩家的翻后均衡。

课包必须保存：

| 字段 | 必须记录的内容 | 不能省略的原因 |
|---|---|---|
| `sourceCommit` | 求解器提交号、Cargo features、构建版本 | 同一仓库可能有破坏性 API 或数值变化 |
| `rangeBefore[oop/ip]` | 每个组合的原始权重、解析文本、组合枚举顺序 | 只能用聚合百分比无法复原范围图和分母 |
| `flop/turn/river` | 卡牌 ID 与人类可读牌面；未发牌必须显式标记 | 牌面、阻挡和后继牌依赖精确卡身份 |
| `deadCards/bunching` | 已弃牌玩家数据、死牌数、是否启用 bunching | 影响到达权重和权益，不能默认当作零 |
| `privateCardIndex` | 求解器组合索引到具体两张牌的映射 | `strategy`、`equity`、`EV` 都只返回索引向量 |

### 2. 行动树输入

`TreeConfig`会改变答案本身。必须记录起始底池、有效后手、抽水、每个位置每条街的下注尺寸、raise/donk 尺寸、全下阈值、强制全下阈值和尺寸合并阈值。尺寸字符串中的 `%`、`x`、`c`、`e`、`a`含义不同，不能在导出时只保留一个显示用的“半池/满池”标签。

同一牌面如果行动菜单不同，就是不同参考问题。因而以下两条快照不能合并：

```text
同一范围 + 同一牌面 + 60% bet
同一范围 + 同一牌面 + 33% / 75% / all-in
```

课程简化可以删除动作，但必须保留“原始菜单、删除理由、剩余动作、简化误差和适用边界”。没有这些字段，后续无法判断是求解器策略，还是课程作者临时改写。

### 3. 求解与存储输入

求解流程是：构造 `ActionTree` → `PostFlopGame::with_config` → 分配内存 → 可选节点锁定 → `solve` 或逐步 `solve_step` → `finalize`。发布包必须保存迭代次数、目标 exploitability、实际停止原因、最终 exploitability、是否锁定节点、是否启用压缩，以及目标存储层级。

`set_target_storage_mode` 只改变序列化时保留的深度。若只保存到 flop 或 turn，后继河牌节点和连续练习所需的策略可能已经不存在；因此“文件能成功保存和重载”不是“连续课包闭合”的证据。

## 二、求解器输出如何对应课包字段

### 1. 当前节点身份

每道题必须能从快照重建当前节点：

```text
nodeId
street / currentBoard
currentPlayer (OOP 或 IP)
actionHistory（动作的实际语义和实际金额）
totalBetAmount / pot / effectiveStack
availableActions（动作类型 + 实际金额）
isChanceNode / isTerminalNode
```

只存 `actionIndex=2` 不够。`available_actions()` 的顺序属于当前树的局部索引；换一组尺寸后，索引 2 可能已经不是同一个动作。课包必须同时写入 `actionId`、动作类型、金额、相对底池比例、前置动作和显示名称。

### 2. 范围、策略、权益与 EV

求解器输出的向量都是“动作块 × 具体组合”的扁平数组：第 `i` 个动作、第 `j` 个组合位于 `i * numHands + j`。编译器必须按 `privateCardIndex` 还原成可画在 13×13 范围图上的组合，否则会出现图上牌格与答案错位。

| 求解器输出 | 课包字段 | 允许的教学用途 |
|---|---|---|
| `weights` | `rangeBeforeRaw` | 记录原始到达权重；不能当成动作后范围 |
| `normalized_weights` | `rangeBeforeReach` | 显示在当前牌面和对手范围下仍可到达的组合质量 |
| `strategy()` | `referenceActionFrequencyByCombo` | 生成逐手动作频率和范围聚合 |
| `expected_values()` | `referenceActionValueByCombo` | 比较动作价值；必须注明玩家、节点和求解状态 |
| `expected_values_detail()` | `referenceActionValueDetail` | 需要保留每个动作的 EV 时使用 |
| `equity()` | `referenceEquityByCombo` | 牌力/权益事实层；不能单独生成行动答案 |
| `available_actions()` | `referenceActionMenu` | 生成按钮和动作后的后继索引 |
| `possible_cards()` | `legalSuccessorCards` | 生成转牌/河牌后继；必须展开同构花色映射 |
| `history()` / `current_board()` | `nodeIdentity` | 复核节点和连续路线 |
| `compute_exploitability()` | `solverQuality` | 记录求解质量；不能单独证明课程简化正确 |

其中 `strategy()` 在终局节点和 chance 节点不可调用；`expected_values()` 要求游戏已完成求解；范围改变后必须重新缓存 `normalized_weights`。这些状态前置条件应成为导出器的硬错误，而不是静默填零。

### 3. 动作后的范围变化

训练器真正需要的不是一张“最终正确率图”，而是每个动作的范围变化账本。对动作 `a`，课包至少保存：

```text
R_before[c]                 # 当前组合 c 的进入权重
P(a | c)                    # 当前组合选择动作 a 的频率
R_after[a][c] = R_before[c] * P(a | c)
massBefore                  # 固定分母下的总质量
massAfter[a]                # 动作后的质量
delta[a][c] = R_after[a][c] - R_before[c]
aggregateByHandClass[a]     # 13×13 格子聚合
```

`R_after`不是把“选择该动作的组合全部涂成绿色”，也不是把当前图做一次物理发牌过滤。物理冲突、动作过滤、未知和零频必须分开。每个动作还要有`differenceLedger`，指出哪些组合减少、哪些保留、哪些只是被牌面阻挡。

### 4. 后继节点闭合

每个可发布动作都必须指向一个可重建的后继：

```text
successorId
parentNodeId
triggerActionId
nextBoard / chanceCardSet
nextPlayer
nextActionMenu
rangeAfterForBothPlayers
stopReason（若没有可用后继）
```

求解器的同构机会合并只提供代表牌和交换映射。训练器不能把代表牌直接显示成唯一真实后继；导出器必须展开到人类可见的合法牌集合，并保存花色交换与逆映射。否则转牌/河牌练习会出现“图显示一张牌，实际代表多张牌”的不可解释状态。

## 三、从参考策略到课程简化的编译顺序

```text
固定配置与源码身份
  ↓
求解器原始快照
  ↓
牌力/权益/金额独立复核
  ↓
动作菜单与每手频率展开
  ↓
只按已有课程规则删动作或量化频率
  ↓
计算 R_before → R_after → delta
  ↓
生成白话解释、图表、后继和停止原因
  ↓
静态课包验收
  ↓
训练器只读已验收课包
```

课程简化的每一行都必须有：`simplificationRuleId`、`sourceReference`、`rawActionMenu`、`keptActions`、`removedActions`、`quantizationRule`、`maxFrequencyError`、`scope`。如果没有明确资料或匹配参考，编译器必须输出`unknown`并停止该节点，不能用邻近牌面、权益高低或作者直觉补答案。

翻后的“阻挡牌”也必须处于正确层级：它先改变具体组合是否存在和组合权重，再进入范围变化解释；它不能直接替代行动策略，也不能单独推出“这手应该下注”。

## 四、最小可发布课包

一份题目要进入训练器，至少要同时拥有：

1. 完整输入身份：配置、范围、牌面、行动树、源码提交号和许可证记录；
2. 牌力事实：最佳五张、牌型、冲突牌、合法后继牌；
3. 原始参考：每个动作的实际金额、逐组合频率、EV/权益、收敛信息；
4. 课程政策：保留动作、量化规则、未知项和简化损失；
5. 范围闭合：`R_before`、每个动作的`R_after`和差异账本；
6. 后继闭合：动作后下一节点、下一牌面或明确停止原因；
7. 教学字段：当前问题、唯一主要动作、白话解释、错误返回父层、复述检查；
8. 证据身份：引用的资料、来源快照、复核脚本和发布闸门结果。

缺少第3项时，不能判“动作正确”；缺少第5项时，不能教“动作后范围如何变化”；缺少第6项时，不能进入连续三街练习；缺少第8项时，不能说答案与 GTO 或课程资料一致。

## 五、对当前项目的决定

- `postflop-solver`只作为作者侧离线参考生成器，第一阶段不放入答题时的浏览器运行时。
- `holdem-hand-evaluator`和`equity-calculator`只负责牌力/权益事实校验，不能从权益直接生成行动答案。
- `wasm-postflop`和`desktop-postflop`可参考节点与范围的表达方式，但不把求解器控制台暴露给低基础学习者。
- 课包必须保留原始策略、课程策略和展示答案三层；训练器只对展示答案判分，并能回溯到前两层。
- 任何“参考输入不匹配”“动作菜单不完整”“动作后范围缺失”“后继缺失”“许可证未确认”的节点都停止发布。

因此，仓库的价值不是让训练器临时“算出一个看起来合理的按钮”，而是提供一条可审计的证据链：**固定输入 → 可复算参考 → 明确简化 → 范围变化 → 后继节点 → 低负荷教学**。只有这条链闭合，翻后才有可能从“找规律”变成可以看见、可以复述、可以执行的结构化练习。

本合同完成的是本地源码接口与课包字段的研究闭合；当前仍未完成匹配课程配置的完整参考求解、编译器运行接入、学习者试读或 NL50 能力验证。
