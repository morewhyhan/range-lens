# 135｜35项字段补齐队列与停止矩阵

35个单元已经有编号、父层和局部材料，但仍不是可运行题包。此前的字段审计说明“缺什么”，本合同进一步规定“先补什么、补到哪一步才能进入下一步、缺时停在哪里”。它把作者工作排成一条依赖队列，避免先凭标题写动作答案，再事后补身份、范围和后继。

## 一、补齐必须按依赖顺序

```text
来源身份
  → canonical gameFrame
  → 事实输入与来源指纹
  → 课程政策
  → 匹配参考策略
  → 动作前后范围
  → 合法回应／新牌／终局后继
  → 解析与单变量迁移
  → 发布身份
```

顺序不能倒置。没有街次、角色和行动状态，不能判断题目属于哪一类；没有课程政策或匹配参考，不能给精确动作；没有动作后范围，不能画行动筛选；没有后继，不能把单步题接成连续练习。

## 二、当前队列的真实分布

当前35项中，19项有来源范围内的完整身份候选，16项仍有街次、角色、位置或牌面缺口。规范字段审计仍显示35项的`coursePolicy`、`referencePolicy`、`rangeBefore`、`rangeAfter`和`legalSuccessors`均未迁移到可发布课包，因此当前队列的第一动作是身份迁移或补身份，而不是批量出策略题。

| 队列阶段 | 当前数量 | 允许做什么 | 不能做什么 |
|---|---:|---|---|
| `identity_source` | 16 | 回到来源补街次、角色、位置、牌面或历史 | 不猜动作，不复制相邻单元身份 |
| `identity_canonical` | 19 | 把已核对候选迁移到规范`gameFrame` | 不把迁移写成策略证据 |
| `fact_frame` | 0 | 冻结牌、钱、合法性和来源哈希 | 不把事实自动升级为课程答案 |
| `course_policy`及以后 | 0 | 等身份和事实闭合后按顺序推进 | 不跳过政策、参考、范围或后继 |

这不是完成率。它只是当前作者队列的入口状态；19项身份候选也不代表19项策略准备好。

机器队列现在额外保存 `authorFrontier`：当前作者阶段是 `identity_source`，先处理16个来源身份缺口，再处理19个规范迁移；学习者在结构四项证据之前仍只看到五个代表单元 `1.5、2.1、3.1、4.5、5.7`，之后按组内顺序一次打开一个。作者队列可以全面，用户入口仍然不能平铺。

## 三、五组怎样进入队列

35项仍按五组挂回父帧：

| 组 | 父帧 | 首遍代表 | 完整队列何时开放 |
|---|---|---|---|
| `compare.unopened` | p4 | 1.5 | 结构回放四项检查通过后，按组内顺序 |
| `compare.bet` | p4 | 2.1 | 同上 |
| `compare.raise` | p4 | 3.1 | 同上 |
| `update.response` | p6 | 4.5 | 同上 |
| `update.card` | p6 | 5.7 | 同上 |

首遍只显示五个代表，不显示35个单元首页。代表题本身也必须遵守当前资料身份；例如`5.7`只能先教新牌造成的物理移除，不能从物理移除直接推导对手行动策略。

## 四、每个单元的停止身份

队列中的每一行都记录：当前父帧、组内顺序、首遍代表身份、来源证据、身份缺口、规范字段缺口、下一阶段、停止原因、最低学习结果和精确判分所需条件。

- 身份缺失：停在`identity_only_not_practice_ready`；只允许补资料或做已声明事实。
- 事实未冻结：停在`fact`；只允许牌张、金额、合法性和物理组合题。
- 课程政策未声明：不生成课程动作答案。
- 匹配参考未取得：不开放精确策略判分，保持`demonstration`或停止。
- 动作前后范围未闭合：不画“对手弃掉了这些牌”，只能显示物理过滤或未知。
- 合法后继未闭合：不进入连续转牌、河牌或终局路线。
- 迁移题未冻结：不把同题重答当作独立能力。

## 五、执行时的验收规则

补齐一个字段后，必须重新检查依赖它的祖先和子节点：

1. 身份改变，重建事实快照和父帧指纹；
2. 课程政策改变，重新评估受影响祖先动作；
3. 参考策略改变，重新生成动作后范围和后继；
4. 范围改变，重新检查联合分母、价格和可达性；
5. 后继改变，重新检查连续账本和错误返回；
6. 发布身份改变，旧的未见题和学习者证据不能自动转移。

脚本不会因为某字段存在就判断其内容正确；它只检查队列是否从当前审计真实生成、35项是否逐项挂接、五个代表是否唯一以及未知字段没有被伪装成策略答案。

机器可读队列见[`unit-field-completion-queue.json`](unit-field-completion-queue.json)，生成和校验脚本见[`research-nevir-unit-field-queue.mjs`](../../scripts/research-nevir-unit-field-queue.mjs)。

为避免“字段队列”和“参考请求队列”各自解释，现将它们合并成作者侧[编译前沿合同](author-course-compilation-frontier.json)。该合同逐项记录当前阶段、下一阶段、缺失字段、停止原因、下一动作和学习者是否可见；作者可以同时准备全部35项，但精确策略只能沿身份→事实→课程政策→匹配参考→范围→后继→迁移→发布的顺序开放。当前前沿仍是16项身份来源补齐、19项规范身份迁移，其余阶段为0。
