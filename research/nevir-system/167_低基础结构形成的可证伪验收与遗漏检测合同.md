## 这份合同补的不是新课程，而是“已经形成结构”的证据

目标要求低基础学习者跟完一遍以后，脑中知道“先做什么、再做什么、变化后回哪里”。仅有一条写好的路线还不够；作者可以看着路线走通，学习者却可能只是跟着按钮点击。因此本合同把结构定义成一张必须被学习者重新调用的有向图，并把“遗漏了一步”和“连错了一条边”分别检查。

它只验收四件事：

1. 学习者能找回主节点和顺序；
2. 学习者能把当前父帧交给下一层；
3. 学习者出错时能回到最近缺失层；
4. 学习者在只改一个字段的陌生题上，能找到受影响层。

它不把结构证据升级成策略正确、连续三街或NL50证据。

## 一、结构不是菜单，而是一张有向图

首遍的用户图固定为：

```text
p1 局面 → p2 牌面与手牌 → p3 范围 → p4 比较
→ p5 执行 → p6 更新 → p7 收口
```

每个节点必须有一条正常边和一个错误回退边。`p6`不能默认进入下一街：有真实后继时回到新的`p1`，没有后继时进入停止卡；`p7`才负责结算和回放。35个后台单元是这些节点的子内容，不是额外节点，也不能从首页绕过父节点进入。

每个父节点的最小闭合字段如下：

| 字段 | 学习者看到的意思 | 缺失时的处理 |
|---|---|---|
| `entryCondition` | 为什么现在来到这一层 | 停在当前层并说明缺什么 |
| `visibleInputs` | 完成当前问题必须看见什么 | 不要求用户反推隐藏信息 |
| `question` | 这一层只问哪一个问题 | 拆成多个父层，不加按钮 |
| `primaryAction` | 用户这一步实际点什么 | 不允许多个同等主按钮 |
| `requiredOutput` | 这一层交付什么结果 | 不能用下一层答案代填 |
| `nextOrStop` | 下一层或停止原因 | 缺后继就停止 |
| `errorReturn` | 错了回到哪里 | 只回最近缺失层 |

后台覆盖的最低字段和学习者可见内容必须分开保存。后台可以完整登记参考、EV、组合权重和后继；首遍只显示当前父层完成问题所需的部分。

## 二、首遍结构闸门

首遍完成后隐藏步骤标题，记录用户第一次回答，再执行以下四个检查。主持者可以读题，但不能代替用户说出下一步；任何展示完整答案后的重答都不计为首答证据。

### 1. 顺序回忆 `orderRecall`

要求学习者在不看标题时说出七个节点，并把六条正常连接按顺序连起来：

```text
局面 → 牌面与手牌 → 范围 → 比较 → 执行 → 更新 → 收口
```

最低通过条件是节点7/7、连接6/6。只说出“看牌、下注、结算”而不能说明范围、更新和回退，记为未形成结构。

### 2. 当前层定位 `layerLocation`

给三个没有见过的父帧，分别改动一个当前状态字段，要求学习者说出：

- 现在属于哪个节点；
- 该节点先看什么；
- 完成后交给哪一层。

最低通过条件是三帧都定位正确，并且下一层不靠页面标题提示。只点对按钮但说不出当前层，不能通过。

### 3. 错误回退 `errorRecovery`

在两个父帧中各注入一个单字段错误，例如把`toCall`改错或移除`rangeBefore`。要求学习者指出“这里缺什么”，返回同一父帧，修正后继续；不能回首页，也不能跳到新专题。

最低通过条件是两次都保留父帧的牌面、历史、首答和返回点。若用户知道答案却不知道回哪里，记录为结构错误。

### 4. 单变量迁移 `oneVariableTransfer`

给一题未见题，只改变位置、牌面、价格、回应或新牌中的一个字段，并在题面中保存变化清单。学习者必须先指出受影响层，再完成该层判断。第一轮最低要求一题；后续释放到相邻迁移时，至少重复两种不同字段。

迁移题不得同时改变前序、范围、牌面和金额。若题面改变了两个字段，题目本身无效，不把失败归因给学习者。

## 三、怎样检查“每一步都没有落下”

结构闸门只检查学习者能否调用路线；遗漏检测检查作者课包是否真的把所有内容挂回路线。每个35项单元必须满足：

```text
有唯一 parentFrame
有 sourceIdentity
有当前层 factInputs
有 coursePolicy 或明确的 stopReason
有 question、primaryAction、requiredOutput
有 errorReturn 和 transferVariant
有 legalSuccessors 或 successorOrStop
```

检查结果分为四种：

| 状态 | 含义 | 用户可见行为 |
|---|---|---|
| `attached` | 已挂到父层，但尚未有完整策略依据 | 可做结构或事实题 |
| `fact_ready` | 牌张、金额、合法性等事实已核对 | 可做事实练习 |
| `policy_ready` | 课程规则和参考身份都已闭合 | 才能精确判动作 |
| `released` | 后继、范围变化、教师答案和试读都通过 | 才能进入对应练习队列 |

`attached`不能伪装成`released`。同一组题量再多，也不能补齐另一个角色、街次或行动状态。未登记的组合格必须进入停止清单，而不是由相邻牌面推断。

## 四、一次首遍的记录格式

训练器不需要长期数据库，只需在当前会话保留以下证据：

```text
courseVersion
taskId
firstAnswer
helpLevel
routeNodeBefore
routeNodeAfter
nextStepVerbalized
handoffPayload
errorLayer
returnTo
changedField
passStatus
```

记录的目的不是给用户建立排行榜，而是区分四种情况：

- 跟着提示完成；
- 首答独立完成；
- 看了解析后修正；
- 主持者代答后继续。

只有第二种才能作为结构闸门的独立证据。第三种可以用于修课，第四种只能说明页面继续运行，不能说明学习者已经学会。

## 五、失败时的修订顺序

同一错误在两个未见任务中重复时，按以下顺序修订：

1. 检查是否一屏问了两个父层问题；
2. 检查必要输入是否被隐藏或必须反推；
3. 检查子层关闭后父帧是否恢复；
4. 检查解析是否越级给出动作口诀；
5. 检查当前单元是否其实缺来源、范围或后继；
6. 最后才增加同机制题量。

增加题目不能修复路线断裂、资料缺口或错误归因。若资料不足，应该让用户练“知道这里停下并说明缺什么”，不能把未知答案算作用户错。

## 六、与释放等级的关系

```text
A0 跟随主线
  ↓ 顺序回忆、层定位、错误回退、单变量迁移
A1 结构建立
  ↓ 资料充分的未见单步
A2 慢速执行
  ↓ 相邻变化与延迟回忆
A3 迁移
  ↓ 三街后继和独立复核
A4 连续路线
  ↓ 冻结目标配置与外部审查
A5 目标级评估
```

任何一层只证明本层证据。A1不证明策略正确，A2不证明连续三街，A4不自动证明NL50。目标仍保持为最终设计方向，但必须在匹配参考、真实试读、未见迁移和目标配置审查全部出现后才可以讨论准备度。

## 七、当前状态

本合同已经把“跟完一次后脑中有结构”变成节点、边、交接、回退和单变量迁移的可检查条件，并把后台35项的完整性和用户首遍可见性分开。当前状态仍是：纸面合同已写，运行时未接入，低基础试读未进行，完整匹配参考和35项后继未闭合，NL50证据为零。
