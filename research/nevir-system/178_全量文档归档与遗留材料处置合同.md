## 为什么要单独做这份合同

研究过程中会产生三种材料：当前用户路线、作者侧编译与判分合同、早期探索稿。如果三种材料都能直接成为入口，训练器最后会出现多条互相竞争的课程。用户会看到很多说法相似但顺序不同的文档，页面实现也会重新选择一条路线，最终破坏“跟一遍就知道下一步”的目标。

本合同不删除早期材料，也不把它们假装成已经验证的课程。它先盘点整个研究目录，再给没有进入正式元数据路由的文件指定父文档、用途和禁止用途。只有当前元数据路由中的文件，才可以成为主路线、课包编译输入或用户首页入口。

## 当前盘点结果

当前研究目录共有 195 份 Markdown，其中 113 份已有正式元数据，82 份是早期材料。82 份全部记录在[机器可读处置清单](legacy-document-disposition-audit.json)中；每一份都有：

- 所属证据层：用户路线、课程编译、参考判分、学习者验证或混合层；
- 当前主父文档；
- 是否允许成为主入口；
- 允许的作者侧用途；
- 与当前 canonical 主线冲突时采用的处理规则。

早期材料默认进入 `legacy_evidence_drawer`。它们可以帮助查找原始想法、公式、案例和历史决策，但不能绕过当前主线生成答案。若其中一段内容被重新核对、补齐来源并通过发布闸门，必须复制为新的正式文档或课包版本，不能仅靠修改处置清单把它升级。

## 主路线与遗留材料的关系

当前唯一的学习者路线仍是：

```text
L0 桌面与目标
→ L1 局面与行动权
→ L2 翻前图表坐标
→ L3 翻前动作确认
→ L4 起始范围交接
→ p1 局面
→ p2 牌面和自己的牌
→ p3 范围和阻挡
→ p4 比较动作
→ p5 执行与金额
→ p6 更新范围和后继
→ p7 收口
→ 回放与单变量迁移
```

早期文档只能从当前父文档的证据抽屉按需打开，并在读完后返回父文档。它们不能创建新的同级入口、不能重新定义 `p1—p7` 的顺序、不能把局部公式升级成GTO策略，也不能把未取得的后继补成默认过牌或默认下注。

## 重新启用一份早期材料的条件

一份早期材料要回到主路线，必须同时完成：

1. 明确它服务于哪个父步骤和哪个学习者交付字段；
2. 绑定原始来源、版本、配置和计算身份；
3. 与当前路线的前一状态、后一状态和错误返回一致；
4. 如果涉及策略，取得匹配参考并分开保存课程政策与原始参考；
5. 通过事实、范围、金额、后继和来源的机器检查；
6. 在低基础首遍、隐藏路线回放和单变量迁移中实际试读。

缺任一项时，它继续保持证据抽屉身份。这样“文档全部保留”和“用户只面对一条清晰路线”可以同时成立。

## 当前边界

这份合同证明的是目录治理和路线唯一性，不证明早期材料的语义已经全部重新验证，也不证明运行时、完整匹配策略、低基础学习效果或NL50能力。机器清单当前明确保留这些未完成状态，不能用目录数量代替课程证据。
