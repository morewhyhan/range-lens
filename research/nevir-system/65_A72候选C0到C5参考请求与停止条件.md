# A72候选C0到C5参考请求与停止条件

2026年10月21日。本文件把A72课程匹配候选从“已经准备了输入”推进到“可以检查每一街参考是否真的存在”。它只定义研究闭环，不把预检图、物理牌张枚举或固定模型误写成GTO策略。

## 1. 当前候选身份

候选请求见[BTN对BB A72参考请求](reference-request-btn-bb-a72.json)。它固定为六人现金桌、100BB有效筹码、零抽水研究管线、BTN开2.5BB、BB跟注、翻牌 As 7h 2d、BB先行动。BTN和BB的起始范围来自当前翻前简化图，但这两个范围的0/50/100权重只是课程输入，不等于原求解器的频率。

候选的当前状态是 prepared_reference_inputs_not_solved。也就是说，输入清单、牌张和账本配置已经写下来了，求解尚未开始，不能给出任何精确的过牌、下注、加注、弃牌频率。

## 2. C0—C5依赖链

每一门都必须同时登记证据路径、状态和停止原因。状态只能使用：

~~~text
prepared                 输入或结构已准备，尚未证明策略
independent_fact_ready   物理事实或账本已独立复核
reference_missing        需要匹配的原始策略输出尚未取得
ready_for_next_gate      本门所有硬字段已齐，可进入下一门
blocked                  有配置、哈希、动作或后继不一致
~~~

### C0 配置冻结与身份

目标是让任何后续输出都能追溯到同一配置。必须保存候选ID、求解器版本、完整输入哈希、抽水身份、已知公共牌、位置、先行动者、底池、后手、行动菜单和研究范围。

当前证据：

- 输入文件：reference-request-btn-bb-a72.json；
- 候选ID：REF_BTN_BB_A72_100_zero_rake_research_v1；
- 输入指纹：9a16cd816771d45689df3ad2941a28659eedb1b5f54a41eea66cc87e2eb18acf；
- 求解器候选只记录了 b-inary/postflop-solver 的版本，实际构建版本仍为空；
- 行动适配器尚未构建和测试。

停止条件：任一源文件哈希改变、实际抽水不是零抽水、实际玩家数或牌面改变、求解器版本未固定、动作树由适配器擅自合并，均停止，不进入C1。

准入条件：配置和哈希逐项重载通过，实际生成的动作ID和金额与请求相符，才标记 ready_for_next_gate。

### C1 翻前范围快照与物理过滤

目标是保存两名活跃玩家的有序实体组合、翻前类权重、已知牌过滤和联合先验。这里的联合先验是：

~~~text
两方声明权重的乘积
→ 删除与翻牌冲突的实体组合
→ 删除双方重复占用的私人牌
→ 记录未归一化质量和兼容组合数
~~~

当前参考请求已经保存BB的完整类权重和实体组合，也记录了兼容组合数164251、未归一化质量124335.25。这个事实可以独立复算，但它只证明“哪些牌仍可能存在”，不证明“某个动作更常见”。

独立检查必须包括：13×13坐标和实体组合一一对应；每一方的牌不与 As、7h、2d 冲突；双方组合不撞牌；权重分母和物理过滤分开；双方顺序不会因排序改变。

停止条件：出现重复牌、范围字符串与实体列表不一致、把物理删除写成行动筛选、把翻前权重当成翻后策略，均停止。

准入条件：独立组合和质量复算通过，且C0身份一致，可标记 independent_fact_ready；只有求解器真正接受同一快照时，才可进入C2。

### C2 翻牌动作参考

目标是取得 As 7h 2d、BB先行动、尚未观察BB动作时的原始策略输出。每个可达节点至少必须有：

- 实际合法动作ID和金额；
- BB每个实体组合对每个动作的频率和EV；
- BTN响应的频率和EV；
- 两方到达权重；
- 节点的收敛指标、停止原因和单位；
- 每个动作的后继索引和零到达节点说明。

所需动作树来自请求文件：翻牌33%和全下，转牌75%和全下，河牌75%和全下，并允许BB在声明菜单内领打。实际引擎动作必须以导出结果为准，不能把菜单文字当作已生成动作。

当前状态：reference_missing。flop-tree-preflight.json 只证明完整原始翻牌图已建立、内存已估算，状态仍是 full_original_flop_graph_built_memory_estimated_not_solved；flop-tree-preflight-verification.json 也明确 not_solved。它们不能填入任何翻牌策略答案。

停止条件：没有逐手策略、没有动作金额、没有双方到达权重、没有收敛定义或动作树与请求不一致，均停止；不能用固定“1/3下注”或现有课程案例代替。

### C3 动作后范围变化

目标是对每个公开动作建立同一坐标、同一分母的前后范围图：

~~~text
R_before(hand)
R_after(action, hand)
= R_before(hand) × action_frequency(hand, action)
-----------------------------------------------
  Σhand R_before(hand) × action_frequency(hand, action)
~~~

输出必须同时写明物理过滤和行动筛选。行动后的范围要能按动作、玩家、节点、父节点和后继牌重载；不能只保存一张混合颜色图。每个动作至少要有支持质量、归一化分母、零支持组合和与父范围的差异。

当前没有A72匹配动作输出，因此C3为 reference_missing。任何现有范围图只能作为输入快照或课程示例，不能宣称是A72的行动后范围。

停止条件：动作后图无法追溯到逐手频率、分母改变未声明、不同动作共用同一图、只给静态总体频率，均停止精确练习。

### C4 转牌条件分布与后继闭合

目标是把C3每个已发布动作连接到合法转牌，并在每张新牌上保留条件化父节点：

~~~text
父节点历史 + 当前动作
→ 删除已知牌
→ 生成合法转牌
→ 记录牌张概率与双方剩余范围
→ 进入实际可达的转牌动作节点
~~~

每个转牌后继必须有牌张身份、条件概率分母、父节点、双方范围、实际动作菜单、逐手策略和下一步河牌索引。没有后继的动作必须明确标记 closed 或 unsupported，训练器不得自行补过牌或随机新牌。

当前只有物理转牌枚举和结构性预检，尚无A72求解后的动作后继，因此C4为 reference_missing。物理上有47张转牌，不代表47张都已有策略。

停止条件：父动作无法定位、转牌条件概率混用未过滤牌数、某动作无 successor-index、只保存牌面类别不保存具体牌，均停止进入连续线路教学。

### C5 河牌结算与账本闭合

目标是对已开放的转牌线路继续到河牌，并同时闭合策略和筹码账本。每个河牌终点必须能重放：

- 具体公共牌和双方实体手牌；
- 每街行动序列和实际金额；
- 底池、双方投入、后手和未跟注退回；
- 终局动作和摊牌结果；
- 参考动作、EV、频率、后继终点；
- 物理检查、账本检查和来源身份。

当前无A72匹配河牌策略、终局策略或三街完整账本，因此C5为 reference_missing。已有账本脚本只能证明金额守恒和牌力事实，不能替代原始策略。

停止条件：河牌没有结算动作、底池守恒失败、终局依赖隐藏信息、只能从结果倒推动作，均停止。完整三街课不能在C5前开放。

## 4. 与训练器的关系

在C2之前，训练器只能开放配置识别、牌张合法性、范围快照和账本事实题，并把题目身份写成 fact 或 demonstration。C2通过后，才可练“翻牌这一节点的动作”；C3通过后，才可练“做完动作后范围怎样变”；C4通过后，才可练“新牌怎样继承前序”；C5通过后，才可练完整三街线路。

这样做的意义是把“GTO参考已经给了”拆成可验证的交付物：输入、动作、范围更新、后继和结算必须逐层闭合。任何一层缺失，都只显示资料缺口，不用课程口诀或随机题目补齐。
