# 一遍完整感与后台全面性的分层合同

## 1. 这份合同解决什么矛盾

最终标准同时要求两件事：学习者第一次跟练就能形成完整的整手牌架构；系统又必须覆盖所有位置、牌面、动作状态、转牌、河牌和后继。若把后台所有题直接放到首页，学习者会被平铺选项淹没；若只保留一条示范线路，系统又会漏掉真实牌局中的重要步骤。

因此“完整”分成两个层级：

1. **首遍结构完整**：第一次只走一条路线，但路线中的每个必要父步骤都有一个可见锚点，学习者知道先后顺序、每一步看什么、答错回哪里、下一步在哪里。
2. **后台覆盖完整**：35个能力单元继续按五组、三条街、角色、行动状态和合法后继登记，逐项经过参考、课程政策、题面、范围图和迁移闸门；它们不在首遍首页平铺。

首遍结构完整不等于35项都已学会；后台覆盖完整也不等于学习者已经形成结构。两者必须分别验收，再通过嵌套入口连接起来。

## 2. 首遍必须看见的九个外层锚点

本节保留早期作者侧的 `L0—L8` 宏观编号，便于追溯旧合同。学习者主线以 [first-pass-screen-coverage-matrix.json](first-pass-screen-coverage-matrix.json) 为准：`L0—L4 → p1—p7 → 回放`；旧 `L5—L8` 不得作为平铺入口。

| 锚点 | 学习者必须看到 | 必须做的一个动作 | 完成后唯一去向 |
|---|---|---|---|
| L0 | 六人桌、100BB、座位、行动顺序 | 点出当前行动者和有效筹码 | L1 |
| L1 | 位置、前序和翻前表格类型 | 选出唯一适用的图表 | L2 |
| L2 | 169格、对子／同花／不同花和当前牌 | 在图表中定位当前格 | L3 |
| L3 | 0／50／100或声明的BB尺度动作 | 读出当前格动作身份 | L4 |
| L4 | 翻前动作如何形成翻后双方起始范围 | 确认范围拥有者和物理过滤 | L5 |
| L5 | 街、行动权、面对的动作、价格和后手 | 说出当前局面的下一层 | L6 |
| L6 | 牌面、最佳五张、牌力顺序、范围和动作比较 | 按顺序完成一个当前比较 | L7 |
| L7 | 动作后范围、新牌、金额、行动权和后继 | 更新一个字段 | 有合法后继回到L5；终局进入L8 |
| L8 | 结算、错误层、顺序恢复和单变量迁移 | 复述路线并完成一次迁移 | 退出或下一轮 |

每个锚点都必须有：进入条件、一个主要问题、一个视觉对象、一个主要按钮、错误返回点和由状态决定的下一步。下一步不能由用户随意挑选：有合法后继就回到当前状态层，只有终局才进入结算层。缺少任何一项时，该锚点只能作为纸面规格，不能标作首遍可用。

## 3. 翻后内层必须按七步出现

L5进入翻后后，首遍内层固定为：

```text
p1 当前状态 → p2 牌面类型 → p3 起始范围
→ p4 当前动作比较 → p5 执行动作
→ p6 行动或新牌后的更新 → p7 结算与返回
```

这七步不是七个菜单，而是同一父帧里的连续问题。p1—p7各只开放一个当前问题；打开阻挡、牌力顺序、听牌、范围图或尺寸解释时，子层关闭后回到原父题，保留首次答案和原局面。

首遍至少要让学习者看到以下七种变化：当前行动者变化、牌面类别变化、可持有范围变化、价格变化、动作后范围变化、新牌后范围变化、结算后结构恢复。没有后继依据的节点停在事实或示范层，不伪造连续动作。

## 4. 后台35项怎样保持全面而不平铺

后台覆盖登记五组：

1. 无人下注时的比较；
2. 面对下注时的比较；
3. 面对加注时的比较；
4. 行动回应后的范围更新；
5. 新牌后的范围更新。

每个单元都挂回最近的L5、L6或L7父层，并保存以下字段：

```text
unitId
parentFrame
street
role
actionState
sourceIdentity
factInputs
coursePolicy
referencePolicy
rangeBefore
rangeAfter
legalSuccessors
question
explanation
errorReturn
transferVariant
releaseStatus
```

首遍只从五组各选一个代表题作为子层锚点；代表题完成后仍返回原父帧，不能解锁同组全部单元。第二遍才按组内确定性顺序展开，第三遍再做相邻变化、延迟回忆和连续陌生路线。

## 5. “每一步不遗漏”的判定方式

以下四种检查必须同时通过：

| 检查 | 证明什么 | 不能替代什么 |
|---|---|---|
| 路线检查 | 规范L0—L4→p1—p7→回放都有入口、问题、返回和下一步；作者侧L0—L8映射可追踪 | 不能证明页面好用 |
| 覆盖检查 | 35项的街、角色、行动状态和后继都有登记 | 不能证明每项策略已取得 |
| 证据检查 | 每个精确答案有来源、配置、版本和动作后范围 | 不能证明学习者会做 |
| 学习检查 | 首答、错误回退、顺序恢复和未见迁移可观察 | 不能证明NL50准备度 |

任何一项只完成纸面合同，都必须在课包状态中保留 `not_trialed` 或 `not_verified`，不能写成“已覆盖”。

## 6. 首遍、第二遍、连续练习的解锁顺序

```text
首遍：规范L0—L4→p1—p7→回放 + 五组各一题；L0—L8只作作者宏观覆盖
  ↓ 顺序恢复、层级定位、一个单变量迁移
第二遍：五组按顺序逐项打开，仍回到父帧
  ↓ 相邻牌面／位置／行动变化
第三遍：撤去标题和帮助，练未见单步与延迟回忆
  ↓ 连续后继、范围更新、金额和结算
目标验收：冻结条件下的独立连续三街与外部对标
```

题目数量、边缘牌比例和重复次数只能改变同一层的曝光顺序，不能跳过父步骤、提升证据身份或替代未见迁移。

## 7. 当前状态

这份合同把“首遍完整感”和“后台全面覆盖”分开并接回同一条嵌套路由。它目前是纸面路线合同；真实页面、完整匹配参考、全部35项后继和低基础学习者试读仍未通过，不能据此宣称学习者已建立结构或达到NL50。
