## 这份合同解决什么

“系统全面”不能只等于有35个单元，也不能用题目数量证明。每个单元都要有三种不同作用的题：

1. **基准卡**：看懂这个单元到底在观察什么；
2. **单变量对照卡**：只改一个字段，看见为什么层级或答案变化；
3. **迁移卡**：隐藏单元名称，先指出受影响层，再完成陌生题。

每一类题还要分别覆盖定位、纯事实/纯规则、适用的混合题、边缘牌、内部牌、保持动作的对照和单字段迁移。缺少某个池时显示“资料不可用/暂不开放”，不能从邻近单元复制题目填空。

## 用户实际看到的释放顺序

```text
首遍：只见 1.5、2.1、3.1、4.5、5.7 五个代表
→ 先建立 p4/p6 父帧和完整路线
→ 35项逐个进入 map → guided
→ 每项完成基准、对照、迁移三卡
→ 通过延迟回忆后，才进入连续后继
```

用户可以调整边缘牌、内部牌、纯事实、混合题和迁移题的比例，但这些参数只改变抽样，不改变课程政策、范围、EV或后继。默认比例在真实试读和题池校准前保持为空，避免拍脑袋设置一个看似科学的数字。

## 当前真实状态

35个单元、父帧和三卡身份已经列出，但105张具体卡、题池、比例校准、匹配参考和真人试读尚未完成。当前合同只能证明“系统应该怎样全面覆盖和逐级释放”，不能证明题目已经足够多、策略已经正确或学习者已经达到NL50。

机器计划见 [full-course-coverage-and-release-contract.json](full-course-coverage-and-release-contract.json)。

35项的“覆盖计划”还必须服从唯一用户路线，而不是单独形成课程菜单。它的结构性闭合由 [user-first-complete-route-contract.json](user-first-complete-route-contract.json) 复核：35项均有唯一父帧、返回点、一个问题、一个主要动作、交接输出、错误回退和停止边界；首遍只显示五个代表，剩余题在同一父帧内释放。当前结构检查通过，但精确策略、后继、运行时和真人证据仍全部未通过。

自动出题合同、会话队列、35项覆盖计划和用户阶段脚本的交叉一致性由 [question-generation-cross-contract-audit.json](question-generation-cross-contract-audit.json) 审计。该审计确认：首遍只取五个代表、全部单元留在父帧内部、比例只影响抽样不改变策略、空题池不由邻近题替代、错误回原父帧，缺少匹配参考或真实后继时不开放精确判分。它仍只是纸面一致性证据，不能替代运行时题目生成器或学习者试读。

35项的三卡结构已经展开为 [unit-three-card-skeleton.json](unit-three-card-skeleton.json) 中的105个明确卡位：每个单元固定有基准、单变量对照和未见迁移三张卡，并登记父帧、返回点、输出字段和停止边界。当前只是结构骨架，答案、匹配参考、课程政策、动作后范围、后继和真人试读仍为空；105个卡位全部补齐前，不能把“全量覆盖”说成“全量可练”。

105个卡位的作者侧补齐顺序见 [unit-three-card-compilation-frontier.json](unit-three-card-compilation-frontier.json)。它把每张卡接到 `identity_source → identity_canonical → fact_frame → course_policy → reference_policy → range_snapshots → successors → teaching_transfer → release` 阶段，并分别记录下一项作者动作。当前48张卡仍在来源身份阶段、57张卡在规范身份阶段，答案编译数为0；这表示下一步应该补来源和身份，而不是继续增加平行题面。

身份候选的具体补齐边界见 [unit-identity-promotion-frontier.json](unit-identity-promotion-frontier.json)：19项可以迁移为“规范身份候选”，16项仍阻塞，其中5项只缺双方筹码映射、6项只缺角色、5项缺局面字段。即使身份候选补齐，也只能进入事实和作者编译阶段，不能直接开放动作策略或学习者判分。
