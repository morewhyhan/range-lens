## 为什么要单独做交叉表

目前有三种不同的描述：

- `p1—p7`：用户第一次跟练时看到的七层问题；
- `O1—O8`：独立执行时必须交付的八类输出；
- canonical fields：课包和编译器保存的字段。

它们不能简单按编号一一对应：p2 同时覆盖牌面和手牌，所以对应 O2、O3；p7负责结算、错误定位和下一轮入口，对应O8。若没有交叉合同，页面会出现同一个字段换名字、一个步骤漏掉一个输出、或第一遍一下子暴露独立练习的全部技术字段。

## 用户路线与运行输出的固定对应

```text
p1_context  → O1_context
p2_board    → O2_board + O3_hand
p3_range    → O4_range
p4_compare  → O5_compare
p5_execute  → O6_execute
p6_update   → O7_update
p7_close    → O8_close
```

第一遍不是把O1—O8的所有字段同时展示，而是每层先交付一组低负荷的`firstPassRequired`字段；用户进入独立练习后，再开放`fullExecutionRequired`字段。隐藏字段仍由课包保留和校验，不能因为首遍隐藏就删除。

## 字段命名统一规则

| 旧写法 | 规范写法 | 统一理由 |
|---|---|---|
| `toCallOrZero` | `toCallBB` | 没有跟注时明确为0，避免“没有字段”和“价格为0”混淆 |
| `handCategory` | `handClass` | 与牌力分类合同统一 |
| `rangeUpdate` | `rangeAfter` | 与动作前后范围公式统一 |
| `ledgerUpdate` | `ledgerAfter` | 与连续状态账本统一 |
| `allowedIdentity` | `answerIdentity` | 说明这是事实、课程规则或参考策略身份 |
| `errorLayerOrNone` | `errorLayer` | 正确时取`none`，错误时取具体层 |
| `stack` | `stacksBB` | 保留双方／有效筹码的明确对象，不用单数模糊代替 |

适配层可以读取旧别名，但不能把缺失字段猜成默认值。无法转换时，单元降级或停止。

## 七层每一遍到底要求什么

| 用户层 | 运行层 | 首遍必须交付 | 独立练习再展开 | 失败回退 |
|---|---|---|---|---|
| p1 情境 | O1 | 轮到谁、历史、补多少钱、底池、筹码 | 街次、面对的动作、有效后手 | p1 |
| p2 牌面/手牌 | O2+O3 | 最好五张、牌力类别、改善牌 | 牌面六类、直接听牌、后门、阻挡事实 | p2 |
| p3 范围 | O4 | 范围是谁的、哪些不可能、行动筛选是否未知、分母 | 动作前后格子、视角、变化分类 | p3 |
| p4 比较 | O5 | 合法动作、价格、动作目的、答案身份 | 更差牌继续、更好牌弃牌、未来分支 | p4 |
| p5 执行 | O6 | 选哪个动作、投入多少、动作后底池/筹码、下一个行动者 | 不增加新的判断，只核对金额和合法性 | p5 |
| p6 更新 | O7 | 是回应还是新牌、改变了哪个字段、范围/账本怎样更新、新牌效果、下一行动者和后继 | 更完整的新范围快照与后继细节 | p6 |
| p7 收束 | O8 | 结果、决策与结果分开、错在哪一层、下一轮从哪开始 | 结算细节、路线回忆、单变量迁移入口 | 最近缺失层 |

首遍字段少，是为了让用户先建立路线；不是删掉理论。所有独立字段仍保存在课包中，并在后续阶段逐层展开。

## 从字段交接到实际动作

交叉表现在还绑定一条独立的行动证据链：

```text
A0锁定局面 → A1找入口 → A2读事实 → A3看范围差异
→ A4比较 → A5执行 → A6更新/停止 → A7迁移收口
```

这八步不是新的首页菜单，而是对 p1—p7 的运行时检查。每一步都要把一个可见结果交给下一步；例如没有`rangeDeltaOrStop`就不能进入精确动作判分，没有`ledgerAfter`和`successorOrStop`就不能进入连续练习。首答、帮助后答、重答和迁移答必须分开保存，不能用最终按钮或总分替代结构证据。机器映射见 `first-pass-runtime-output-crosswalk.json` 的 `actionChainOrder`，详细字段见 `slow-single-step-execution-contract.json`。

## 交接不变量

1. 每个 p 步骤必须映射到至少一个 O 步骤；p2可以映射到两个，但不能把O3藏掉不登记。
2. 每个首遍输出必须能写回一个 canonical 字段或一个明确的事实结果。
3. `firstPassRequired`不能包含参考策略才有的字段；资料不足时必须显示未知或停止身份。
4. `fullExecutionRequired`不能在首遍题面中提前泄露答案。
5. p5不能重算p4的比较；p6不能静默改写p5的金额；p7不能把结果好坏当作动作正确的证明。
6. 子单元仍从p4或p6打开，关闭后恢复父帧，不能因为字段交叉表而生成新的首页入口。

## 当前状态

机器合同还要求每个 p 步骤的 canonical 字段，必须等于其对应 O 步骤在`course-unit-field-schema-map.json`中的运行投影并集。这样交叉表不会形成另一套孤立字段。它仍是纸面合同，尚未接入页面，也没有低基础学习者试读证据；它解决的是实现时的字段漏项风险，不证明任何策略参考已经取得。
