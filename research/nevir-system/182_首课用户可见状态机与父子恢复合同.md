## 这份合同为什么还要单独存在

170、177和150号文档已经写清楚“先做什么、后做什么”，但路线仍可能在实现时被误写成一组按钮：子题打开后覆盖父题，错误后直接跳下一题，范围图换了分母，或资料不足时系统默认给出一个动作。

182号把用户真正经历的东西写成一个小型状态机。它只回答四个问题：

1. 当前屏幕是什么状态；
2. 用户必须交付什么才允许前进；
3. 错了、缺资料或点开子题时怎样保持原父帧；
4. 下一屏继承哪些字段，哪些字段绝不能被悄悄改写。

它是页面和课包编译器共用的行为合同，不是新的学习内容，也不把35项变成新的首页菜单。

## 一、用户看到的是12个连续停点

外层翻前定位与翻后七步合成一条连续状态链：

```text
L0 桌面目标
 → L1 翻前局面
 → L2 翻前范围图
 → L3 翻前动作
 → L4 范围交接
 → p1 局面
 → p2 牌面与手牌
 → p3 范围
 → p4 比较
 → p5 执行
 → p6 更新
 → p7 收口
```

每个停点只显示一条普通话问题、一个中心视觉和一个主要交付。顶部路线条只显示上一步、当前一步和下一步；35项、求解器参数和所有资料入口不在路线条上。

外层的五条交接边也必须闭合：`L0桌面目标 → L1翻前局面 → L2图表坐标 → L3翻前动作 → L4翻后起始范围 → p1翻后局面`。每条边都登记生产字段、下一状态的必需输入和使用目的；L4交给p1的范围快照、物理过滤和固定分母不能在进入翻后时重新生成或丢失。机器检查见 `handoff-consumption-audit.json` 的 `outerHandoffRows`。

## 二、每个状态的固定契约

每个状态都必须有以下字段：

```text
stateId
parentStateId
plainQuestion
centerVisual
primaryAction
visibleInputs
requiredInputs
requiredOutput
nextState
errorReturn
stopReasons
stopCondition
openChildren
snapshotFields
```

其中 `requiredInputs` 是上一状态的交接消费清单。它不是后台备注：如果当前状态缺少其中任何字段，页面必须停在当前状态并说明缺口，不能用相邻牌面、默认动作或重新抽题补齐。

### 1. 必须交付后才能前进

- `L0`：确认六人桌、训练目标和100BB背景；
- `L1`：指出位置、前序、当前行动者、底池、有效筹码和待补金额；
- `L2`：在翻前图找到当前坐标和范围来源；
- `L3`：确认当前格子的课程动作身份；
- `L4`：保存动作前范围、物理过滤、分母和父快照哈希；
- `p1`：确认翻后行动权、历史、底池、后手和待补金额；
- `p2`：确认公共牌、底牌、最佳五张、牌型和改善牌；
- `p3`：同时指出动作前范围、物理排除、行动筛选是否未知、动作后范围状态和固定分母；
- `p4`：在合法动作中作出比较或选择停止，并给出当前层原因和策略身份；
- `p5`：同时交付动作、金额、账本和下一行动者；
- `p6`：先指出是回应还是新牌，再指出唯一变化字段，选择真实后继或明确停止；
- `p7`：保留结算、决策与结果分离、错误层和下一入口，再用一句话说明结束原因和下一次只改变的字段。

缺少任何必需字段时，状态保持原地并显示停止卡；不能用默认过牌、默认跟注或邻近题答案补齐。

### 2. 错误怎样处理

第一次答案必须在解析前保存。答错时：

```text
记录 firstAnswer
→ 判断错误层（事实/范围/价格/策略/执行/更新/收口）
→ 返回该层所属父状态
→ 保留当前牌面、历史、分母和问题
→ 只增加一个帮助字段
→ 用户重新回答
```

错误不会推进主路线。解析只能解释当前层，不能一次把后面所有动作和后继全部泄露出来。用户重新答对后，系统恢复原定交接字段，再进入下一状态。

## 三、子题必须是覆盖层，不是新路线

打开子题时，系统保存一个不可变的 `parentSnapshot`：

```text
parentStateId
currentQuestion
holeCards
board
actionHistory
potBB
stacksBB
toCallBB
rangeSnapshotHash
rangeDenominator
firstAnswer
currentUnit
```

子题只允许改变自己声明的 `childChangeField`。关闭子题必须逐字段恢复上述快照；若子题改变了父帧的行动历史、范围分母或下一张牌，却没有明确写入后继，视为状态机错误。

允许的子层只有：

| 父状态 | 子层 | 作用 |
|---|---|---|
| `p2` | 牌面六类、牌力顺序 | 事实导航和牌力识别，完成后回到 p2 |
| `p4` | 无人下注、面对下注、面对加注 | 在当前比较问题中练一个动作关系，完成后回到 p4 |
| `p6` | 回应更新、新牌更新 | 练范围/账本/后继变化，完成后回到 p6 |

任何子题都不能从首页直接打开，也不能在子题中跳到另一个父状态。

## 四、四类转移和两个终止

### 正常转移

```text
answer_valid
→ 写入当前状态的 handoff
→ 校验下一状态的 requiredInputs
→ 移动到 nextState
```

### 错误转移

```text
answer_wrong
→ 留在当前状态或回到最近缺失层
→ 保存 firstAnswer
→ 增加一个帮助层级
```

### 子题转移

```text
open_child
→ 保存 parentSnapshot
→ 进入一个 child overlay
child_complete / child_close
→ 精确恢复 parentSnapshot
```

### 资料停止

```text
missing_evidence
→ 显示缺什么、为什么不能继续、回到哪里
→ 当前状态完成“识别缺口”的交付
→ 不生成下一动作或默认后继
```

### 两个终止结果

1. `successor`：存在真实后继，带着范围、金额、行动权和历史进入下一状态；
2. `stop`：没有足够资料或边界已到，明确停在当前父状态。

“没有后继”不是“默认过牌”，而是必须记录的停止身份。

## 五、状态机的不变量

这些不变量比页面动画更重要：

1. 同一屏只有一个主要问题和一个主要动作；
2. 当前屏幕的所有牌、范围、金额和账本来自同一 `snapshotHash`；
3. `p3`的物理过滤不能被标成策略过滤；
4. `p4`没有匹配参考时不能判精确策略；
5. `p5`动作、金额和下一行动者必须一起校验；
6. `p6`没有真实范围后继或停止原因时不能进入下一街；
7. `p7`没有隔离的单变量迁移字段时不能开放陌生题；
8. 子题关闭后，父帧的首答、历史、分母和当前问题必须恢复；
9. “我不知道”按错误处理，但不会删除或覆盖首答；
10. 解析、原始资料和技术术语只能按需打开，不改变路线状态。

## 六、怎样验证“跟一遍后脑中有架构”

状态机运行后，首遍验收不看总分，而看四种行为：

1. 隐藏状态标题，用户仍能说出当前属于哪一层；
2. 给出一个未见父帧，用户能指出下一层和所需交接；
3. 打开并关闭一个子题，父帧的牌面、范围、历史和问题完全恢复；
4. 故意改变一个字段，用户能指出该回到哪一层，而不是重新从头猜。

这些检查先证明路线结构，再逐步增加真实策略、范围后继和连续三街。没有真实低基础试读时，状态机只能标为纸面合同。

## 七、发布边界

状态机本身不能制造策略。要把某一状态开放为精确动作题，仍需要：

- 匹配输入指纹；
- 原始逐组合参考；
- 课程政策和差异账本；
- 动作前后范围；
- 合法后继或明确停止；
- 独立复核与学习者试读。

因此，本合同让“结构不乱、一步不漏、父子不串线”变得可测试，但不把纸面状态机误写成已完成的 NL50 训练器。

机器可读版本见 [first-lesson-visible-state-machine.json](first-lesson-visible-state-machine.json)。状态机的交接字段直接引用 [handoff-consumption-audit.json](handoff-consumption-audit.json)，因此“答对后前进”必须同时满足下一层能消费字段；只点中按钮但丢掉待补金额、分母或未知状态，不算合法转移。
