# 课程单元字段规范统一映射

## 1. 为什么必须统一字段

当前系统有三份不同用途的字段合同：

- [104号分层合同](104_一遍完整感与后台全面性的分层合同.md)描述学习单元必须具备的概念字段；
- [67号编译合同](67_课程单元自动编译与出题合同.md)描述编译器应生成的课包字段；
- [105号输出合同](105_七步可执行输出与判分接口合同.md)描述学习者在屏幕上交付的结果。

它们的层级不同，但不能对同一事实使用不同含义。否则“动作前范围”“行动状态”或“后继”在研究表里存在，编译器或页面却读不到，最终仍会形成看似完整、实际断裂的题目。

## 2. 规范层级

```text
概念层：系统要知道什么
  ↓ canonical schema
编译层：课包如何保存它
  ↓ projection
运行层：学习者在当前屏幕交付什么
```

规范映射不增加策略内容，也不把缺失资料填成默认值。它只规定同一字段的唯一含义和别名。

## 3. 唯一映射

| 概念字段 | 编译字段 | 运行输出 | 说明 |
|---|---|---|---|
| `unitId` | `unitId` | `stepId`或当前题的`unitId` | 同一单元身份不可改写 |
| `parentFrame` | `parentRouteNode`、`returnTo` | 当前父题快照 | 父帧不是菜单分类 |
| `street` | `gameFrame.street` | O1 `street` | 必须明确翻牌、转牌、河牌或结算 |
| `role` | `gameFrame.role` | O1 `actor`和范围拥有者 | 角色不能从牌面推断 |
| `actionState` | `gameFrame.actionState`、`allowedActions` | O1 `facingAction`、O5 `legalActions` | 状态先于动作比较 |
| `sourceIdentity` | `sourceIdentity`、`SourceSpec` | 解析中的来源标签 | 来源版本和指纹必须保留 |
| `factInputs` | `entryCondition`、`gameFrame`、`visibleInputs` | O1—O4事实输入 | 事实输入不等于策略答案 |
| `coursePolicy` | `coursePolicyIdentity`、`policyAnswer` | O5/O6课程规则 | 课程简化不能命名为原始GTO |
| `referencePolicy` | `referenceIdentity`、`referenceAnswer` | O5/O6/O7参考策略 | 只有匹配参考才允许使用 |
| `rangeBefore` | `rangeBefore` | O4行动前范围 | 固定拥有者、视角和分母 |
| `rangeAfter` | `rangeAfterByAction` | O4/O7行动后范围 | 必须按动作和逐手权重生成 |
| `legalSuccessors` | `successorIds`、`SuccessorGraph` | O5/O7后继或终局 | 缺少后继就停止连续策略题 |
| `question` | `question`、`questionKinds` | 当前一个主要问题 | 不在题面泄露答案 |
| `explanation` | `explanation`（必须新增到课包） | 答后当前层解析 | 解析只解释当前层因果 |
| `errorReturn` | `errorLayer`、`returnTo` | 当前错误回退 | 首答不能被重答覆盖 |
| `transferVariant` | `transferVariants` | 未见相邻／连续题 | 只允许已验证单变量变化 |
| `releaseStatus` | `releaseStatus` | 当前发布身份 | 事实、示范、课程规则、参考策略分开 |

## 4. 必须新增的编译字段

现有编译合同的`unitMinimumFields`没有单独列出`explanation`，也没有把`street`、`role`、`actionState`从`gameFrame`中显式暴露给字段审计。为了让编译器和审计使用同一语义，规范版本要求：

1. `gameFrame`必须包含`street`、`role`和`actionState`三个可读取字段；
2. 每个已生成课包必须有`explanation`，即使内容是“资料不足，停在事实层”；
3. `rangeAfterByAction`必须能指向具体动作、拥有者、分母和计算版本；
4. `successorIds`为空时必须同时保存`stopReason`，不能把空数组解释为“没有后继但可以继续”；
5. `releaseStatus`改变或任何祖先输入改变时，必须重新编译祖先。

## 5. 兼容旧记录的规则

旧记录可以暂时保留`parent`、`evidence`、`returnRule`等简写，但只能在导入适配层转换为规范字段；适配层不得从文字标签猜出街次、角色、动作状态、策略或后继。转换失败时，单元降级为`fact`、`demonstration`或`not_open`。

## 6. 当前状态

本文件完成的是字段语义统一和缺口登记，不代表35项已经迁移到规范课包。当前仍需补齐明确的`gameFrame`、课程政策、匹配参考、范围前后快照、合法后继和解析，再进行编译器迁移与未见题验证。

机器可读映射见 [course-unit-field-schema-map.json](course-unit-field-schema-map.json)。
