# 翻前起始范围快照合同与A72实例

## 1. 快照不是一个按钮文字

翻前选择要交给翻后，必须保存一份可以重新计算的 `PreflopSnapshot`。只保存“BTN开池”或“SB 3bet”会丢失位置、前序、尺度、来源、组合质量和视角；后续范围图就无法解释，更不能在陌生前序中复用。

快照的作用是把翻前的课程政策和翻后的事实过滤接起来。它不等于原始GTO策略：如果图表是0／50／100简化图，快照必须标出这是课程动作权重；如果动作来自题设历史，必须标出“历史输入”，不能写成求解器答案。

## 2. 必填字段

```text
snapshotId
gameIdentity                 # 六人现金桌、有效筹码、抽水身份
seatState                   # 座位、弃牌、学习者视角
fullHistory                 # 每个动作、金额、行动者和总投入
chartIdentity               # 图表名称、版本、来源哈希
scenarioIdentity            # 开池/3bet防守/大盲防守及尺度
selectedAction              # 选择的动作、动作权重和身份
rangeOwner                  # 当前正在构造哪一方范围
perComboWeights             # 实体两张牌质量；未知时明确为空
normalizationDenominator    # 归一化分母或未归一质量
jointCompatibilityStatus    # 双方联合相容检查状态
knownCards                  # 私人牌、公共牌、死牌
physicalFilterStatus        # 已知牌冲突过滤状态
parentSnapshot              # 从哪个父快照进入
changeReason                # 本次新增动作或新牌改变了什么
successorBoundary           # 下一街或停止原因
inputFingerprint            # 配置、来源和映射的指纹
releaseIdentity             # fact / demonstration / course_policy / reference_policy
```

## 3. 计算关系

当目标只是物理事实时，先对每个实体组合做合法性过滤：

```text
w_legal(h) = w_pre(h) × I(h 与已知牌不冲突)
mass_legal = Σ_h w_legal(h)
```

当已有明确的动作筛选政策，才可以继续计算：

```text
w_after(h | a) = w_before(h) × p(a | h, node)
q_after(h | a) = w_after(h | a) / Σ_h w_after(h | a)
```

双方有公共牌和撞牌约束时，先在合法联合私牌对上计算，再按学习者视角边缘化。不能分别把两边独立归一后相乘，也不能把物理过滤当成对手主动弃牌。

## 4. A72当前实例

A72候选使用：六人、100BB、零抽水研究身份、BTN开池、SB 3bet、BTN跟注，翻牌 `A♥ 9♣ 2♥`，学习者视角为SB、底牌 `A♣Q♦`。输入图表记录为 `open-BTN` 与 `threebet-SB`，输入指纹沿用A72参考请求。

当前实例只证明输入身份和物理过滤准备：

- `A♣` 已在学习者手里，因此对手不能持有含 `A♣` 的实体组合；
- 起始范围每格的动作来源仍需按图表版本读取；
- BTN跟注和SB 3bet的实际动作后范围尚未取得匹配参考；
- `perComboWeights`、联合质量和后继仍标为未生成或未验证；
- 当前发布身份只能是 `starting_range_fact` 或 `postflop_demonstration`，不能是 `reference_policy`。

## 5. 快照的返回和失效

打开p3范围子层时，系统保存父快照哈希；关闭后必须恢复同一牌面、历史、金额、视角和来源版本。若图表版本、动作政策、公共牌、有效筹码或来源哈希发生变化，原快照失效，所有子题降级或重新编译，不能静默沿用旧范围。

机器可读合同和A72实例见 [preflop-snapshot-contract.json](preflop-snapshot-contract.json)。
