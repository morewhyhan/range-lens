## 这份合同补的不是新题，而是整条学习路线的“骨架规则”

已有文档分别规定了首遍、七步路线、35项单元、帮助撤除、题队列和简化校准。187号把它们收成一个递归结构，回答一个必须能验收的问题：**用户第一次跟练时为什么不会被后台的完整性淹没，之后又怎样从同一条主线逐层获得全部能力？**

目标不是让用户记住35个分类，而是让用户先形成一条可以慢慢运行的思考程序：

```text
看清局面 → 读牌与牌面 → 看范围 → 比较选择 → 执行动作 → 更新状态 → 收口并迁移
```

任何更细的知识都只能挂在这条程序的当前节点下面。完成子节点后，必须回到原来的父节点；没有依据的节点必须停住，不能靠相似例子填空。

## 一、唯一的递归结构

课程只承认四类运行对象：

| 对象 | 作用 | 用户是否直接看到 |
|---|---|---|
| `spine` 主线 | 决定下一步，固定为 `p1→p2→p3→p4→p5→p6→p7` | 是，只显示当前位置和相邻方向 |
| `parentFrame` 父帧 | 保存当前局面、问题、已交付字段和返回点 | 是，当前屏幕的主体 |
| `childUnit` 子单元 | 在一个父帧内补一个具体原理、动作或更新关系 | 只在父帧中按需出现 |
| `evidenceCard` 证据卡 | 记录首答、帮助、错误层、范围、账本、后继和释放阶段 | 主要在答后和后台出现 |

所有可见题面都必须能够写成：

```text
Frame = 输入 → 一句问题 → 一个主要动作 → 一个交付字段
        → 变化/交接 → 返回父帧或真实后继/停止
```

如果一个题面需要同时回答两个没有先后关系的问题，就拆成父帧和子帧；如果子帧完成后不能恢复进入前的父帧快照，就不能发布。

## 二、首遍的实际路径

首遍不是35项的缩略目录，而是一条带代表子题的完整路径。用户可见停点固定为：

```text
L0 目标与六人桌
 → L1 位置与前序动作
 → L2 翻前图表入口
 → L3 起始范围交接
 → L4 翻后局面进入
 → p1 局面定位
 → p2 牌面与手牌
 → p3 范围与阻挡
 → p4 选择比较
 → p5 动作执行
 → p6 回应/新牌更新
 → p7 收口与下一入口
```

`p4` 和 `p6` 才允许打开子单元。首遍每个组只看一个代表题，顺序固定为：

```text
比较无人下注 → 比较面对下注 → 比较面对加注
→ 更新对手回应 → 更新新公共牌
```

代表题的目的只有两个：让用户看见“这类问题在主线的哪里”，并亲手完成一次进入、判断、返回。它不证明同组其他题已经学会，也不能用来替代匹配策略参考。

旧材料中的九个宏观停点 `L0—L8` 与这里的十二个可见状态不是两套用户菜单。九停点是验收和课程编译用的宏观摘要；首课运行时把其中的翻后宏观段展开为 `p1—p7`，具体对齐为：`L0—L4` 保持原样，`L5` 对应 `p1`，`L6` 展开为 `p2—p4`，`L7` 展开为 `p5—p6`，`L8` 对应 `p7` 之后的回放与迁移。实现时只读取一条规范状态机，不能把九停点和十二状态同时显示成两条导航。

## 三、十条不可破坏的不变量

1. **单主线不变量**：任何时刻只有一个当前父帧；下一帧由规范 `next` 链决定，不能由题库菜单决定。
2. **单子帧不变量**：父帧最多打开一个子单元；子单元关闭后恢复同一个父帧快照。
3. **交付不变量**：当前帧的必需输出必须成为下一帧的输入；空字段不能用默认值、相邻题或解析答案填补。
4. **单变化不变量**：首遍和相邻迁移一次只改变一个教学字段；同时改位置、牌面、价格和历史的题不能称为单变量迁移。
5. **事实身份不变量**：最佳五张、牌型、阻挡、底池、金额和行动权与策略结论分开判定。
6. **策略身份不变量**：动作、尺寸、频率和动作后范围必须绑定匹配参考或明确课程政策，不能从牌面事实单独推导。
7. **后继不变量**：开放节点必须有真实后继或可复核的停止原因；没有后继就不生成下一街。
8. **错误归因不变量**：一次错误只归因一个层，回到最近缺失层；不能用整段解析或跳到新专题掩盖断点。
9. **覆盖与掌握分离不变量**：后台覆盖35项不等于用户掌握35项；总正确率、题量和连续答对数不能绕过单元释放闸门。
10. **目标声明不变量**：连续三街通过仍不等于NL50；目标级声明必须额外具备冻结配置、未见题、独立复核和真实决策证据。

## 四、从“一遍”到“会用”的释放顺序

每一阶段只增加一种负荷，且必须保留同一父子结构：

| 阶段 | 用户体验 | 新增负荷 | 必须证明的结果 |
|---|---|---|---|
| `P0` 首遍跟练 | 系统带着走完整 `L0→p7` | 只认识路线和交接 | 能说出下一步和返回点 |
| `P1` 结构回放 | 隐藏步骤标题，保留必要事实 | 取回路线 | 能定位当前层、恢复父帧 |
| `P2` 同父单元 | 在同一父帧补练35项 | 增加同类变化 | 单元首答、错误层和输出完整 |
| `P3` 相邻迁移 | 只改一个字段 | 增加条件变化 | 先指出变化层，再完成同类判断 |
| `P4` 延迟回忆 | 插入其他题后回到原单元 | 增加间隔和回忆 | 不靠标题仍能找回父帧和交接 |
| `P5` 陌生慢速单步 | 新牌局但只开放一个节点 | 减少提示 | 首次作答前能沿七步找到入口 |
| `P6` 连续三街 | 保存范围、账本、行动权和后继 | 增加时间连续性 | 每个开放节点都有后继或停止 |
| `P7` 目标级审计 | 冻结配置下的未曝光题包 | 增加外部复核 | 才能讨论目标条件准备度 |

阶段不能跳跃。上一阶段的必要证据缺失时，调度器只能补原阶段的同类问题，不能用更难题目或总体分数强行推进。

## 五、每个父帧必须留下的最小交接

| 父帧 | 用户用白话交付 | 后台交接字段 |
|---|---|---|
| `p1` | 谁行动、发生了什么、要付多少 | `contextFrame` |
| `p2` | 最佳五张、当前牌力、哪些牌会改变它 | `handFrame` |
| `p3` | 哪些组合不可能、哪些是行动留下 | `rangeFrame` |
| `p4` | 合法选择、价格和目的 | `decisionFrame` |
| `p5` | 动作、金额、下一行动者 | `ledgerFrame` |
| `p6` | 只改变了哪一项、下一步或停止 | `updateFrame` |
| `p7` | 当时依据、结果、下一次重查哪一层 | `reviewFrame` |

交接卡必须同时保存 `firstAnswer`、`helpLevel`、`errorLayer`、`returnTo`、`successorOrStop`。答对按钮但交接字段为空，只记为“跟随完成”，不能升级为结构掌握。

## 六、怎样证明“一遍后脑中有架构”

首遍结束后，不用总分，而用一组必须全部出现的结构证据：

1. 隐藏标题后，按顺序说出七个翻后父步骤；
2. 在三个未见父帧中指出当前层和下一层；
3. 关闭一个子单元后，找回原父帧的牌、金额、范围和行动者；
4. 给出两个交接错误时，回到最近缺失层，而不是回首页；
5. 只改变一个字段时，先指出受影响层，再完成同类交付；
6. 能说出“资料不足时停在哪里”，不把未知猜成策略答案。

缺少任何一项，首遍只算完成导览，不算已经建立可迁移结构。这个判定不因答题速度、题目数量或解析后正确而放宽。

## 七、为什么这条结构能承载完整性

完整性放在后台的覆盖账本中：35项、六类牌面、牌力顺序、阻挡、范围变化、动作比较、执行账本、回应更新和新牌更新，都必须挂到某个父帧和某个交接字段。用户前台只沿主线走；后台调度器依据学习证据逐项释放。这样同时满足：

- **第一次不乱**：只看一条路线和一个当前问题；
- **内容不漏**：每个后台单元都有父帧、字段、来源和释放闸门；
- **能够迁移**：变化先定位到某一层，再复用同一交接结构；
- **能够判真**：范围、策略、后继和简化损失分别有独立证据；
- **能够停止**：资料不充分时停在具体节点，不用“看起来合理”填空。

## 八、与NL50目标的关系

这份合同只定义达到目标所需的学习架构和证据顺序。它不能凭纸面设计保证任何人进入NL50。真正的目标级发布还必须依次通过：匹配参考、课程简化校准、真实首遍低基础试读、未见单变量迁移、连续三街、独立复核和真实决策审计。当前这些运行时和学习者证据仍未完成，因此 `goalCompletionVerified` 必须保持 `false`。

机器可读合同见 [nested-release-architecture-contract.json](nested-release-architecture-contract.json)。

用户真正体验到的阶段顺序另由 [learner-session-progression-contract.json](learner-session-progression-contract.json) 固定：首遍、路线回放、同父引导、同父独立、相邻单变量、延迟回忆、连续三街，最后才进入未曝光目标级审计。每个阶段只增加一种负荷；阶段失败时回到最近缺失层，不用总分、题量或短期结果强行升级。该文件把题队列的后台阶段翻译成了用户能实际跟着做的动作脚本，当前仍只有纸面合同，尚未接入运行时或真人试读。

所有用户短标签、后端节点、首遍帧和作者父层的对应关系由 [canonical-identifiers-registry.json](canonical-identifiers-registry.json) 统一登记。`p4` 与 `p4_compare` 是同一节点的表面/后端名称，`L6/L7` 只保留为作者侧旧别名；别名不会生成额外步骤，也不能出现在用户首页。当前注册表已通过纸面一致性审计，但运行时尚未真正读取它。
