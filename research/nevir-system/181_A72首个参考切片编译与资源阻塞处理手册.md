## 这份手册要防止什么

A72 的完整三街行动树目前估算压缩后约 5.19GB，高于当前保守预算约 4.08GB。资源不足时最容易出现三种偷换：删掉动作、把下注尺寸改成相近值、只求一个较小的局部树却仍然称为原始 A72 参考。

本手册把“下一步要怎样继续”拆成可以检查的分支：

1. 先完成同一 A72 输入的 C0/C1；其中C1的独立物理快照已经由脚本重算并核对，C0适配器身份仍待固定；
2. 核对引擎是否真的支持固定父节点的精确子树求解；
3. 如果支持，发布带边界的 T1/T2 切片；
4. 如果不支持，保留完整目标身份，扩大资源或改用明确的新研究配置；
5. 任何改变行动树的版本只能作为示范或课程研究，不得伪装成目标参考。

## 一、A72目标身份不能改变

首个切片仍然使用以下身份：

```text
六人现金桌背景；翻后仅 BTN 与 BB 活跃
BTN 开 2.5BB；BB 跟注
初始有效筹码 100BB；翻牌后底池 5.5BB；双方后手 97.5BB
OOP = BB，IP = BTN；翻牌 A♠ 7♥ 2♦；BB 先行动
零抽水研究配置；关闭 bunching
翻牌：check、33% pot、all-in
转牌：check、75% pot、all-in
河牌：check、75% pot、all-in
面对下注：fold、call、2.5x raise、all-in
不自动合并动作；实际金额来自构建后的行动树
```

只改变“求解边界”或“资源分块”才仍属于同一个候选。下面任何改变都必须生成新的 `candidateId`，不能和 A72 的切片合并：

- 翻前范围、组合权重或范围来源；
- 牌面花色、位置、前序、底池、后手或抽水；
- 下注/加注尺寸、全下规则、动作合并阈值；
- bunching 或死牌处理；
- 将 BB 先行动改成 BTN 先行动；
- 把完整三街树改成只允许过牌或单一下注的树。

## 二、先判定“切片”在引擎里是否真实存在

### 1. 不能把三个概念混在一起

| 身份 | 实际含义 | 能否称为 A72 匹配参考 |
|---|---|---|
| 完整目标求解 | 原行动树、原范围、原牌面和完整后继都保留 | 可以，仍需质量闸门 |
| 固定父节点的精确切片 | 输入身份相同，只截取一个已定义的父节点及其真实后继边界 | 可以，但必须标注 T1/T2 边界 |
| 缩短后的新行动树 | 删除动作、减少街次或改变尺寸后重新求解 | 不可以；是新的研究配置 |
| 只显示一个节点的导出 | 完整求解后只导出一个节点 | 可以作为导出物，但不是节省求解资源的办法 |
| 只保存到 flop/turn | 序列化时丢失更深节点 | 不能证明连续后继闭合 |

### 2. 当前快照的真实边界

`ActionTree`可以构造、增加或删除动作线；`PostFlopGame`可以设置目标存储层级、保存和重载。现有源码证据并不足以证明“把存储层级设为 flop”就能在不构建/不求解深层树的情况下完成一个独立的根节点精确求解。

因此，适配器在进入 T1 前必须做一个能力测试：

```text
同一输入、同一动作树、同一根节点
→ 记录完整树节点数与内存估算
→ 尝试目标存储模式或官方支持的子树边界
→ 验证根节点输出是否仍能回放到合法后继
→ 对比完整小树的根频率与切片频率
```

若没有官方或源码级证据证明子树边界保持了同一博弈问题，适配器必须返回 `subtreeCapability = unverified`，不得把结果升为 T1。`targetStorageMode` 只是文件保留深度，不自动意味着求解边界。

## 三、C0：固定引擎和适配器

C0先做身份，不运行长时间求解。输出：

```text
candidateId
inputFingerprint
solverCommit = 9d1509fe5077d019825f833eed04b16d342dfda1
Cargo features / target / build mode
adapterRevision
licenseIdentity
treeConfigHash
cardConfigHash
actualActionIdsAndAmounts
subtreeCapability
storageCapability
```

适配器测试至少包括：

1. 33%与1/3的实际金额和动作ID不能被静默合并；
2. 75%、前次下注倍数和全下必须分别保留语义；
3. `available_actions()` 的顺序改变时，课包仍依靠动作ID和实际金额识别动作；
4. `history()` 回放后，当前行动者、底池和后手一致；
5. 保存/重载后，输入指纹和动作菜单一致；
6. 目标存储模式减少深度时，课包明确标出不可访问的后继。

C0没有通过时，只能显示输入预检，不能出现“GTO答案”按钮。

## 四、C1：独立生成动作前物理快照

C1不需要求解器长时间运行。它用现有翻前简化图展开1326个实体组合，应用 A♠、7♥、2♦ 和双方私牌互不重复的物理过滤，保存：

```text
orderedPrivateHands[oop/ip]
classWeight
entityWeight
knownCardMask
jointCompatiblePairs
jointPriorMass
fixedDenominator
coordinateIdentity
parentSnapshotHash
```

物理过滤和行动过滤必须在结构上分开：

```text
physicalLegalWeight(h) = preflopWeight(h) × noKnownCardConflict(h)
actionConditionedWeight(h,a) = physicalLegalWeight(h) × referenceFrequency(h,a)
```

C1只能产生“哪些牌不可能”和“动作前范围是什么”。它不产生 BB 过牌范围、下注范围或下注后的范围。

## 五、C2：三种资源路径

### 路径 A：完整目标求解

适配器确认完整行动树可在可接受资源内运行时，直接执行：

```text
CardConfig → ActionTree → PostFlopGame::with_config
→ allocate_memory → optional node locking
→ solve(maxIterations, targetExploitability)
→ finalize / quality check
→ export all required nodes
```

必须保存原始逐组合策略、EV、权益、到达权重、动作菜单、后继和收敛记录。只有完整树和 C0—C5 都通过，才进入 T3。

### 路径 B：源码证明过的固定父节点切片

只有在 C0 的 `subtreeCapability = verified_exact` 时才允许。每个切片必须有：

```text
sliceId
parentNodeId
solveBoundary
parentSnapshotHash
sameInputFingerprint
sameActionIdsAndAmounts
perHandStrategy
perActionEV
reachWeight
rangeBefore
rangeAfterByAction
successorIdsWithinBoundary
boundaryStopReason
resourceUsage
artifactHash
```

T1只能开放当前父节点；T2才可以开放一个已经取得参考的后继。切片之外的节点必须显示“参考边界”，不能默认过牌或复制相邻牌面。

### 路径 C：资源不足或子树能力未证明

此时不能删除动作来“做出一个小版本”。正确输出是：

```text
referenceStatus = resource_blocked_or_subtree_unverified
releaseIdentity = fact_or_demonstration_only
stopReason = exact_reference_not_available
```

可以继续做 C0/C1、牌力顺序、六类牌面、物理冲突和金额账本教学；不能开放逐手下注判分、动作后范围或连续三街题。

## 六、参考输出到课包的固定顺序

当 C2 得到真实逐组合策略后，按下面顺序编译，不能跳步：

1. 保存原始动作菜单和真实金额；
2. 按 `privateCardIndex` 还原每个组合；
3. 计算 `R_before`、每个动作的 `R_after` 和固定分母；
4. 分离物理移除、行动筛选、未知和零支持；
5. 按课程规则生成 `courseActionByCombo`，保留原始参考；
6. 记录逐手动作差、范围差、EV差和简化边界；
7. 为所有开放动作建立真实后继或停止原因；
8. 再生成 p1—p7 中的一屏一问一主动作；
9. 最后才生成单变量迁移题。

课程前端永远不直接读取原始 solver 向量，也不在用户答题时临时调用求解器。它只读取通过上述顺序和哈希检查的静态课包。

## 七、当前可执行的最小交付

在完整 A72 资源问题解决前，下一份真正值得做的作者侧交付不是“更多示例”，而是完成C0适配器并把已经通过的C1快照接上：

```text
A72-C0-input-preflight
A72-C1-physical-range-snapshot (verified)
A72-adapter-action-identity-test
A72-subtree-capability-test

```

这五个产物能回答：输入是否锁定、起始范围是否可复核、动作金额是否稳定、引擎是否真的支持精确切片、为什么当前不能继续。当前C1已回答了起始范围事实：164251个兼容组合对，未归一质量124335.25；但它没有产生任何动作频率或动作后范围。下一步仍是固定C0，再重新评估资源和子树能力。

## 八、发布和教学边界

| 当前通过层 | 用户可以练 | 用户不能被要求相信 |
|---|---|---|
| C0 | 位置、牌面、历史、金额和输入身份 | 任何策略答案 |
| C1 | 牌力、最佳五张、物理冲突、动作前范围 | 过牌/下注筛选 |
| T1 | 已闭合父节点的一步动作和范围变化 | 未取得的转牌/河牌后继 |
| T2 | 指定后继和单变量变化 | 边界以外连续路线 |
| T3 | 完整三街训练候选 | “因此一定能进 NL50” |

目标没有因为资源阻塞而降低。相反，边界越清楚，未来拿到完整参考后越容易把每一步安全地接入同一套嵌套教学路线。
