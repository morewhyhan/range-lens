# 首遍一手牌逐屏运行合同

2026年10月21日。本合同把单一路径、七步慢想、翻前入口和35项后台覆盖编排成一次真实可跟随的首遍运行。它回答的不是“后台有多少题”，而是一个第一次打开训练器的人每一屏看到什么、做什么、什么时候进入子层、做完后回到哪里。

它仍然是课程运行规格，不是页面已经实现的证明，也不把纸面路线当作低基础学习者已经学会。

## 1. 首遍的唯一目标

首遍结束时，用户不需要记住所有下注频率，也不需要一次学完全部边缘牌。首遍只要形成一张能复述的结构图：

~~~text
先确认桌面和前序
→ 找到翻前对应表格
→ 从格子得到自己的起始范围
→ 翻后先定位行动者和价格
→ 再读牌和牌力
→ 再看双方范围关系
→ 比较动作并执行
→ 动作或新牌后更新范围和账本
→ 结束后回看错误发生在哪一层
~~~

任何一个深层内容都必须服务于这条顺序。它不能把用户送到另一个没有父步骤的专题首页。

## 2. 外层路线和屏幕职责

本表沿用旧材料的 `L0—L8` 宏观编号，便于和历史截图及字段对照；实现时不得把它渲染成第二套用户导航。学习者表面使用 `L0—L4 → p1—p7 → 回放`，`L5—L8` 只用于作者侧屏幕覆盖审计。

| 外层 | 当前屏幕只显示 | 用户只做一件事 | 可按需打开的子层 | 完成后返回 |
|---|---|---|---|---|
| L0 进入 | 六人桌、100BB、当前训练目标 | 点“开始这手牌” | 桌面说明 | L0 |
| L1 翻前定位 | 位置、前序、动作类型、表格入口 | 指出应查哪张表 | 场景定位 | L1 |
| L2 翻前读格 | 169格、自己的两张牌、格子坐标 | 点出当前格及颜色含义 | 格子读法、边界牌 | L2 |
| L3 翻前执行 | 允许动作、混合权重、若为BB则显示尺度 | 选择动作或权重 | 精确动作、边界对照 | L3 |
| L4 范围交接 | 双方实体范围和物理过滤 | 指出翻后起始范围从哪里来 | 撞牌、已知牌移除、范围图 | L4 |
| L5 翻牌定位 | 公共牌、行动历史、底池、后手、行动者 | 说出“轮到谁、面对什么” | 桌面、金额、历史 | L5 |
| L6 当前判断 | 牌力、范围关系、可用动作 | 完成当前一个动作判断 | 读牌、范围、比较 | L6 |
| L7 继续推进 | 回应、新牌、动作后范围、金额变化 | 更新一项并进入下一街 | 行动后范围、新牌 | L7 |
| L8 结算回看 | 账本、结果、错误层、下一次帮助 | 复述本手路线并定位错误 | 结构恢复、相邻迁移 | L8 |

每个外层屏幕只有一个主要按钮。回看图、原始资料和完整参考都是当前父层的抽屉，不成为新的主线入口。

## 3. L5—L7的七步内层顺序

翻后内容永远使用下列顺序。若某一步资料不足，停在该步的事实或示范，不跳过它假装已经完成：

| 步骤 | 真实问题 | 必须先出现的输入 | 用户操作 | 下一步 |
|---|---|---|---|---|
| p1 看清局面 | 现在轮到谁？面对什么动作？ | 座位、历史、公共牌、底池、后手 | 点行动者和待补 | p2 |
| p2 读牌和牌力 | 我成了什么牌？有哪些改善牌？ | 具体牌面、自己的牌、最佳五张 | 选牌型或补牌 | p3 |
| p3 看范围关系 | 谁的范围更强？哪些组合还在？ | 双方范围、物理过滤、视角 | 指出一组留下／退出的组合 | p4 |
| p4 比较动作 | 过、下注、跟、弃、加注分别解决什么问题？ | 价格、动作菜单、后续 | 选课程政策允许的动作 | p5 |
| p5 执行金额 | 按钮是否合法？投入多少？ | 当前投入、底池、后手、金额规则 | 点动作并确认金额 | p6 |
| p6 更新状态 | 动作或新牌具体改变了什么？ | 动作后范围图、条件新牌、下一行动者 | 点一个范围／金额／牌面变化 | p7或下一街p1 |
| p7 结算回看 | 我在哪一层出错？ | 完整账本、结果、首答与重答 | 选错误层并复述关系 | L8 |

“阻挡牌”“后门”“下注尺寸”不单列成首页栏目。它们在p2、p3、p4或p6当前需要时，以一个子层进入，完成后返回原步骤。

## 4. 一个子层怎样打开

子层打开前，训练器保存父帧快照：

~~~text
parentFrameId
routeNode
publicCards
heroCards
visibleInformation
history
actor
pot
stacks
streetPaid
rangeOwner
rangeView
sourceIdentity
coursePolicyIdentity
assistanceLevel
~~~

子层只允许完成一个局部操作，例如：

- p2中点出“这是顶对还是听牌”；
- p3中比较一个动作前后的同一手牌；
- p4中按价格算出继续所需的最低权益；
- p6中指出一张转牌把哪些组合变成成牌。

子层完成或退出后，必须把公共牌、历史、金额、行动者、范围视角和来源版本恢复成父帧的值。子层中新获得的对手底牌、未来结果或另一条分支不能带回主线。

## 5. 首遍的帮助安排

同一父步骤只撤掉一种帮助：

1. 第一次显示步骤标题、当前行动者、正确关系和按钮；
2. 第二次保留必要输入，隐藏正确关系；
3. 第三次隐藏步骤标题和答案颜色，但保留桌面、牌、金额、范围和合法动作；
4. 第四次换一个未见但同机制的局面，让用户自己指出应该进入哪一层。

帮助不可以删除完成判断所需的信息。若目标策略参考缺失，帮助可以教事实、计算和路线，但不能把没有依据的动作答案包装成“困难题”。

## 6. 错误处理不改变路线

错误反馈固定为四段：

~~~text
标出错误发生层
→ 只高亮一个必要事实
→ 给一个最小对照
→ 在原父帧重答
~~~

典型回退：

| 错误 | 返回层 |
|---|---|
| 不知道现在轮到谁 | p1 |
| 把顶对、两对或听牌看错 | p2 |
| 把物理移除当成行动筛选 | p3 |
| 没算价格就点跟或弃 | p4 |
| 金额或底池不守恒 | p5 |
| 忘记动作后范围或新牌影响 | p6 |
| 用结果改写当时判断 | p7 |

重答正确只能记为“在帮助下完成”，不能覆盖首答。用户继续沿原路线走，不跳去另一套题。

## 7. 35项如何嵌入而不平铺

35项后台单元按当前父层的条件懒加载：

~~~text
L6/p4 比较
  ├─ 无人下注：1.1—1.8
  ├─ 面对下注：2.1—2.7
  └─ 面对加注：3.1—3.6
L7/p6 更新
  ├─ 行动后更新：4.1—4.6
  └─ 新牌后更新：5.1—5.8
~~~

用户只会看到当前条件命中的一个单元。每个单元从事实、给定模型、课程政策到目标参考逐级发布；没有后继、动作频率或匹配配置时，训练器停止在较低身份。后台覆盖表可以完整，首页仍只有一条路径。

## 8. 首遍结束的三项结构检查

L8不显示“已掌握”或NL50徽章，只执行：

1. **顺序恢复**：把七步打乱，用户重新排列；
2. **入口定位**：给未见局面，用户只指出应该进入p1、p2、p3、p4、p5、p6还是p7；
3. **一处迁移**：只改变位置、牌面或前序中的一个字段，用户指出哪个层受影响。

三项都通过，只能证明主线进入脑中。之后仍需R2—R6的帮助撤除、相邻交错、延迟回忆和连续陌生路线。

## 9. 发布前验收

这份运行合同只有在以下检查都通过时才能变成可试读课包：

- 每个屏幕只有一个主要问题和一个主要动作；
- 每个子层有父帧、返回点和恢复字段；
- 每个策略按钮都能追到课程政策或匹配参考；
- 每个动作后范围、新牌和金额都有真实后继，或明确标为停止；
- 未知和资料缺口按错误／停止处理，不猜答案；
- 首答、帮助、重答分开；
- 结构检查使用未见局面；
- 真实低基础学习者能沿路线完成，而不是设计者自己走通。

当前这份合同可以作为课包编译输入，但页面、完整匹配策略和真实试读仍未通过。
