# 简化策略编译与顺序课程合同

2026年10月21日。本文把“完整 GTO 参考如何变成小学生或老奶奶也能顺着练的课程”写成一个作者侧合同。它接[35项出题合同](46_完整参考怎样变成顺序教学与练习_35项出题合同.md)、[后续政策约束](42_简化教学怎样不改错答案_后续政策与当前选择.md)、[行动后范围图合同](43_行动后范围怎么变_具体图表与开源参考.md)和[开源仓库能力审查](44_开源仓库能力审查_从GTO参考到课程简化训练.md)。本文只规定数据和准入，不表示应用已经实现，也不把任何一个 QQQ 案例当作完整 NL50 策略。

## 1. 先把“教什么”与“算什么”分开

训练器面对学习者只呈现一条顺序路线：看清局面 → 识别牌面与牌力 → 看谁有范围优势 → 看尺寸和行动 → 更新双方范围 → 继续到下一街 → 结算并回看。后台必须同时保留四种东西：

| 数据层 | 作用 | 学习者是否直接看到 |
|---|---|---|
| `ReferenceSpec` | 完整游戏条件、范围、行动树、抽水、后手与求解版本 | 默认不看到；解析时可展开 |
| `CoursePolicy` | 课程真正要求用户执行的动作和频率 | 看到当前一步的简化规则 |
| `RangeSnapshot` | 当前视角下的实体组合、质量、动作条件概率和父节点 | 按需看到前后图 |
| `LessonFrame` | 当前题面、已知信息、操作按钮、帮助、返回位置 | 直接操作 |

`ReferenceSpec` 不是 `CoursePolicy`。如果课程把 33%／67%／全下压成一个小注，或把混合频率压成 0／50／100，必须生成一份新的 `CoursePolicy`，不能给旧参考换一个标题。课程政策改变了可选动作或后续，就必须重新计算受影响祖先节点的价值和范围。

## 2. 五种状态，决定能不能开放一道题

每条候选路线必须带一个机器可读的 `status`，不能只凭作者感觉开放：

1. `fact`：牌、金额、合法性、牌力、物理冲突等可独立计算的事实。
2. `demonstration`：完整输入明确、由作者固定的一条示范路线；允许帮助完成，不计独立策略通过。
3. `course_policy`：资料明确采用的简化操作，判分依据是这份课程政策，不冒充原始 GTO 频率。
4. `reference_policy`：匹配的完整配置、后续和策略质量均已通过准入，可以问精确动作或频率。
5. `not_open`：资料、后继、策略质量或许可证仍不足；显示缺什么，不给学习者猜。

`fact` 可以在没有完整策略时开放；`course_policy` 必须有来源和版本；`reference_policy` 还要有完整后续与质量证据。一个节点不能因为有 `ReferenceSpec` 文件就自动从 `demonstration` 升为 `reference_policy`。

## 3. 从参考到课包的编译流水线

编译器按以下顺序运行，任何一步失败都停止该节点的精确判分：

### 3.1 输入准入

锁定座位、有效筹码、底池、抽水、所有仍在牌局中的玩家、前序行动、公共牌、双方起始范围、下注／加注菜单、发牌规则和参考版本。六人桌背景不能写成六个活跃玩家；未知的对手底牌不能被当作真实底牌传入。

### 3.2 完整参考

用作者侧翻后引擎求解声明的行动树，保存原始逐手动作频率、EV、到达权重、后继公共牌和终局结算。用独立牌力／权益代码检查合法牌、最佳五张、平分和金额账本。参考文件必须有输入指纹和固定源码版本。

### 3.3 课程政策变换

将每个课程规则记录为一个显式变换，而不是在显示层偷偷改：

| 变换 | 例子 | 必须重算什么 |
|---|---|---|
| 仅视觉变换 | 隐藏高级参数、一步一步展开 | 不改策略；只核对帮助撤除和返回 |
| 频率量化 | 0／50／100 代替原混合 | 当前节点及其祖先价值、动作后范围 |
| 菜单限制 | 删除一个下注尺寸或再加动作 | 全条路线价值、对手后续、可利用度 |
| 路线包装 | 先示范后让用户独立做下游一步 | 不改策略；标记帮助完成的节点 |

量化不能按“最接近的视觉颜色”决定；要在共同输入和共同后续下计算每个候选政策的价值，并记录误差和未包含的动作。菜单限制不能沿用原 GTO 答案，因为删掉后续动作可能改变上游最优选择。

### 3.4 范围和机会分布

对固定行动者的单边范围，动作后未经归一的组合质量为：

`q_after(h,a) = q_before(h) × p(a | h,node)`

进入该分支的范围占比再除以 `Σ_h q_after(h,a)`。双方未知底牌时要先在合法联合底牌对上乘双方行动概率，再取边缘；不能把两张单边图独立相乘。新公共牌按联合到达质量排除双方底牌后重新条件化，不能把每张未知牌强行当作均匀 1／47 或 1／49。

每个 `RangeSnapshot` 必须保存：拥有者、视角、已知牌、公共牌、完整历史、输入指纹、参考／课程版本、逐手原始质量、动作条件概率、未归一质量、归一分母、父快照、变化类型和后继边界。

### 3.5 课包编译

只把声明过的 `LessonFrame` 写入轻量课包。每一帧至少有：

```text
frameId
parentFrameId / returnTo
status
publicState / privateState
questionKind
visibleFacts
allowedAnswers
coursePolicyVersion
rangeSnapshotBefore / rangeSnapshotAfter
explanationBlocks
successorFrames
unknownCountsAsError
```

如果一条行动边或一张后继公共牌没有对应的 `successorFrame`，它不能继续作为连续策略题；可以作为示范的终点，但要明确停止，不能猜对手回应。

## 4. 顺序课程不是 35 个平铺按钮

35 项能力是后台覆盖检查，不是用户首页。每个父单元只有一条主线和少量按需子层：

```text
当前局面
  ├─ 读牌：牌面类别、牌力、听牌、有效后手
  ├─ 范围：谁有优势、哪些组合留下、阻挡改变什么
  ├─ 当前动作：过牌 / 下注 / 跟注 / 加注 / 弃牌
  ├─ 动作后：底池、价格、双方范围、下一街任务
  └─ 结算：摊牌或弃牌、账本、错误发生在哪一步
```

首次跟练只走主线。用户在“当前动作”处答错时，解析只展开这一层；需要理解为什么时，再进入牌力、范围或价格子层；关闭后回到原父帧，恢复牌、钱和历史。不能因为打开一个解释就重新开始一手，也不能让用户记住 35 个分类名称。

一条真正完整的整手路线至少经过：起始范围 → 翻牌识别 → 当前动作 → 对手回应 → 新牌更新 → 转牌动作 → 河牌动作或摊牌。每一段都要有“输入仍然是什么、此步改变了什么、下一步为什么出现”的短句，按钮只承载当前决策。

## 5. 题目生成规则

题目生成器先选已开放的父路线，再从该路线的有效 `LessonFrame` 中取题；不能先随机发牌再寻找一个看似相近的答案。抽题权重可以提高边缘组合，但评估范围质量仍使用真实组合权重，不能把“70% 训练边缘牌”解释成现实牌局 70%。

每道题记录：题目身份、可见输入、隐藏输入、当前要回答的一个问题、正确答案集合、判分容差、错误解释、下一帧、是否允许帮助和证据指针。未知按钮始终按错处理，并显示解析；答对当前一步才自动进入下一步。解析中必须说明“这是事实、课程处方、还是参考策略”，避免把相关性讲成因果口诀。

边缘题优先使用：课程明确的混合牌、同一节点相邻动作确实改变的组合、或动作 EV 在已验证范围内接近的组合。没有完整后续或参考身份的边缘牌不能进入精确策略题，只能进入事实或示范题。

## 6. 发布前的硬性检查

课包编译完成后，发布器必须逐项检查：

- 每个精确策略题都有匹配的完整参考、版本和输入指纹；
- 课程政策与参考政策分开存储，动作菜单和频率变换有重算结果；
- 前后范围图可由逐手质量重新汇总，固定坐标和共同尺度；
- 每个可继续的动作与新牌都有后继，缺项自动降级为示范或关闭；
- 物理不可能、模型中为零、资料未知使用不同状态；
- 终局金额、弃牌未跟注款、平分和筹码守恒独立核对；
- 题面不泄露答案图，帮助后的再次作答不计作整手独立通过；
- 任何“达到 NL50”或“学会”声明都有陌生题、连续整手、成人弱基础试读和迁移证据。

这些是发布门槛，不是建议项。当前 [QQQ 第二轮验证](44_开源仓库能力审查_从GTO参考到课程简化训练.md#19-第二轮全树参考已经完成对照链可以开始落地但仍不是课程答案)已经覆盖参考重载、选定范围节点、终局算术和前向账本，但仍没有 A72 完整课程参考、课程政策损失、连续课包发布或学习者证据，因此只能登记为参考层通过，不能登记为完整课程通过。

## 7. 当前状态与下一步

本合同补齐了“求解器输出如何经过筛选、政策重算、范围图和顺序帧才成为课包”的中间层。当前 35 项合同仍是规格，自动选择器、完整 A72 参考、真实课程政策编译和成人试读尚未完成。下一项研究工作应优先取得一个与原材料完全匹配的三街节点，按本合同同时生成 `ReferenceSpec`、`CoursePolicy`、`RangeSnapshot` 和 `LessonFrame`，再检查能否从第一帧一路返回和继续，而不是继续增加孤立案例数量。
