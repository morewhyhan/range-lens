## 这份合同解决什么

35项全部挂到 `p4_compare` 或 `p6_update`，只证明它们有父位置。要满足“每一步都不漏”，还必须知道每一项从资料到练习要经过哪些作者阶段，以及学习者要经过哪些释放闸门。

198号为每个单元登记同一条必要链：

```text
C0身份
→ C1物理事实
→ C2匹配参考
→ C3参考质量
→ C4课程政策
→ C5差异账本
→ C6真实后继
→ C7教学帧
→ C8未见迁移
→ C9发布审计
```

学习者释放则固定为：

```text
map → guided → independent → adjacent → delayed → continuous
```

任何单元都不能用总分、同组其它题或邻近牌面跳过自己的缺口。

## 35项怎样保持父子结构

| 单元组 | 数量 | 用户父步骤 | 关闭子题后返回 |
|---|---:|---|---|
| `compare.unopened` | 8 | `p4_compare` | `p4_compare` |
| `compare.bet` | 7 | `p4_compare` | `p4_compare` |
| `compare.raise` | 6 | `p4_compare` | `p4_compare` |
| `update.response` | 6 | `p6_update` | `p6_update` |
| `update.card` | 8 | `p6_update` | `p6_update` |

每个单元都必须保持 `opensOnlyFromParent=true`，不能在首页生成35项平铺入口。首遍只开放五个代表：`1.5 → 2.1 → 3.1 → 4.5 → 5.7`；代表题建立父层位置，不能替代同组其它单元的掌握证据。

## 每个阶段缺失时用户能练到哪里

| 缺失阶段 | 用户可以做 | 用户不能做 |
|---|---|---|
| C0 | 确认局面身份 | 进入精确题 |
| C1 | 读牌、牌力、物理冲突和金额 | 从牌面直接推出下注 |
| C2 | 看参考示范 | 判唯一动作 |
| C3 | 看作者侧质量缺口 | 把参考当可信策略 |
| C4 | 按明确课程规则跟练 | 把课程规则叫作原始GTO |
| C5 | 看动作和范围差异 | 声称课程无损 |
| C6 | 练当前节点并看停止原因 | 继续转牌或河牌 |
| C7 | 进入一屏一题一动作的教学帧 | 使用多问题平铺题面 |
| C8 | 在同父帧重做单变量迁移 | 声称已经会陌生题 |
| C9 | 由作者决定发布身份 | 由按钮正确自动升级 |

如果资料缺失，系统停在当前单元并返回原父步骤；它不会把 `referenceQuality`、`rangeSnapshots` 或邻近单元的结果悄悄填进当前题。

## 当前审计结论

35个单元已经全部具备单元ID、父步骤、C0–C9阶段清单和六级学习者闸门清单；五个代表的顺序也与首遍路线一致。当前所有单元仍未达到完整匹配策略、运行时挂接或真人试读发布条件，因此 `all35ExactStrategyReady`、`all35RuntimeAttached` 和 `learnerTrial` 必须保持 `false`。

作者补齐的实际前沿由[35项字段补齐队列](unit-field-completion-queue.json)冻结：35/35项已进入同一队列，其中19项有可核对的身份候选但尚未迁移到规范字段，16项仍缺来源身份字段；`coursePolicy`、`referencePolicy`、`rangeBefore/rangeAfter`、`legalSuccessors`、`explanation/transferVariant` 和 `releaseStatus` 当前均为0项就绪。队列的第一阶段只能补身份，第二阶段只能做规范迁移；在这两阶段完成前，不得生成精确动作答案或把局部模型当作匹配GTO参考。队列中的五个代表仍只用于首遍结构建立，不代表五个单元已可发布。
