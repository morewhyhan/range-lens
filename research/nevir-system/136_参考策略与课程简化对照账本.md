## 这份账本解决什么问题

仓库研究只能回答“某个工具能算什么”。课程编译还必须回答另一件事：**在同一局面、同一范围、同一行动树下，原始参考是什么，课程把它压成了什么，压缩后哪些东西仍然能执行，哪些东西必须停住。**

如果没有这张逐单元账本，最容易出现四种混淆：

1. 把 `equity-calculator` 的摊牌权益写成下注策略；
2. 把 `postflop-solver` 的有限树参考写成课程原文的完整GTO；
3. 把课程的0/50/100动作写成求解器原始频率；
4. 看到一张动作后范围图，就忘了它是物理排除、行动筛选还是未知资料。

所以每个35项单元都要有一张同结构的账本。没有账本的单元可以做事实题或示范题，但不能进入精确策略判分。

## 一个单元必须按这个顺序对照

```text
来源身份
  → 同条件参考配置
  → 物理事实
  → 参考策略
  → 课程政策
  → 参考/课程差异
  → 动作后范围与后继
  → 教学题面与迁移
```

顺序不是写作顺序，而是依赖顺序。没有来源身份，不能建立配置；没有匹配配置，不能比较参考；没有参考和课程政策，不能计算差异；没有后继，不能把单步题接成连续路线。

## 账本的八个区块

| 区块 | 记录什么 | 由哪个仓库或资料提供 | 缺失时的身份 |
|---|---|---|---|
| `identity` | 六人桌背景、双方仍在底池、街次、位置、完整前序、底池、后手、抽水、公共牌、底牌域 | 用户表格、课程资料、训练器输入 | `not_open` |
| `physical` | 最佳五张、牌力类别、合法跑牌、撞牌过滤、账本金额 | `holdem-hand-evaluator`、`equity-calculator`、本地独立代码 | `fact` |
| `reference` | 每手牌动作频率、EV、到达质量、动作后范围、合法后继、求解质量 | `b-inary/postflop-solver` | `demonstration` 或 `not_open` |
| `course` | 课程规定的动作、下注尺寸、0/50/100量化、适用条件、课程解释 | 用户给的笔记和课程表 | `course_rule` |
| `difference` | 动作差、范围差、EV差、边界组合、支持是否变化、受影响祖先 | 对照计算程序 | `not_comparable` |
| `range` | 固定分母下的动作前/后范围，区分物理移除与行动筛选 | 参考/课程输出 + 编译器 | `fact_only` |
| `successor` | 跟注、加注、新牌、终局、下一父帧和账本交接 | 求解器后继、独立结算 | `stop_at_current_parent` |
| `teaching` | 一屏一个问题、解析、错误层、回退点、单变量迁移 | 训练器编译层 | `guided_only` |

`desktop-postflop` 和 `wasm-postflop`只属于表达参考：可以借鉴节点导航、范围矩阵和前后视图，不能直接把它们的舍入值或界面状态写入判分账本。

## 参考与课程必须分开保存

对一个动作 `a` 和实体组合 `h`，先保存同一个动作前权重：

```text
w_before(h) = entityWeight(h) × physicalFilter(h)
```

参考策略和课程策略分别计算：

```text
w_reference_after(h,a) = w_before(h) × P_reference(a | h,node)
w_course_after(h,a)    = w_before(h) × P_course(a | h,node)
```

图上显示的条件范围必须明确分母：

```text
view_after(h,a) = w_after(h,a) ÷ Σ_h w_after(h,a)
```

差异也必须按同一组合、同一分母比较：

```text
rangeDelta(h,a) = view_course_after(h,a) − view_reference_after(h,a)
actionDelta(h,a) = P_course(a | h,node) − P_reference(a | h,node)
```

若课程删除了一个动作尺寸，不能只把这个动作从图上藏掉；必须重新计算受影响祖先的EV、范围和后继，并记录“动作菜单已改变”。

## 学习者怎样看到这张账本的结果

账本是作者侧完整记录，学习者按当前父步骤逐层看到四个视觉对象：

1. **动作前图**：当前范围是谁的，分母是多少；
2. **物理变化图**：自己的底牌和公共牌让哪些组合不可能；
3. **课程动作图**：这次动作后哪些牌被筛掉或留下；
4. **参考差异抽屉**：课程与参考在哪些组合、EV或后继上不同。

前两张图没有匹配参考也可以显示；第三张图只有在动作筛选资料明确时显示；第四张图只有在参考和课程政策同条件时显示。颜色不能承担唯一语义，必须同时使用边框、标签、数量和“物理移除／行动筛选／未知”文字。

## 单元的发布身份

账本不允许一个单元只有“可用/不可用”两个状态，而要明确告诉训练器可以教到哪一步：

| 发布身份 | 可以练 | 不可以声称 |
|---|---|---|
| `fact` | 牌力、合法性、跑牌、金额守恒、物理移除 | 下注最优、求解器频率 |
| `demonstration` | 跟看一条明确声明的示范路线 | 随机实战、普遍盈利 |
| `course_rule` | 按资料明确写出的动作或尺寸执行 | 这是原始GTO频率 |
| `reference_frequency` | 在匹配参考下选择逐手动作频率 | 课程简化无损、目标级别 |
| `reference_policy` | 沿已闭合后继做连续策略练习 | 学习者已掌握、NL50准备度 |
| `not_open` | 只显示停止原因和返回父帧 | 任何猜测答案 |

当前35项仍处在[135号补齐队列](135_35项字段补齐队列与停止矩阵.md)的身份和字段补齐阶段。特别是A72首课，匹配参考仍停在C1事实候选，不能把本账本的空栏填成课程答案。

## 以代表单元1.5说明停止行为

单元1.5是第一遍 `compare.unopened` 的代表题，资料里有KQ过牌的课程规则候选，但还没有与同一范围、历史、行动树匹配的完整参考策略、动作后范围和后继。因此账本应写成：

```text
identity:      待把来源候选迁移到规范字段
physical:      可做事实核对
reference:     missing
course:        有明确的课程规则候选
difference:    not_comparable
range:         只开放物理过滤，不画参考后验
successor:     missing
teaching:      可做课程规则示范，不开放精确策略和连续路线
releaseStatus: course_rule_candidate_not_released
```

这不是保守过度，而是保护学习者：他可以先学“这个课程规则在什么条件下说什么”，但不会把一个孤立例子误记成“所有A72、所有位置都应该这样”。

## 这张账本怎样接回执行队列

按135号队列逐项执行：

1. 先完成16个 `identity_source` 单元；
2. 再把19个已有候选迁移到 `identity_canonical`；
3. 每个单元冻结 `fact`，并独立核对牌力、牌张和账本；
4. 只有课程资料明确时才填写 `course`；
5. 取得匹配参考后填写 `reference` 和 `difference`；
6. 生成动作前后范围，再闭合 `successor`；
7. 最后才生成教学帧、未见迁移和发布身份。

任何中间步骤失败，都回到当前父帧并登记停止原因，不使用相似牌面、相同位置或工具界面默认值补空栏。

## 当前结论

机器文件[35项账本骨架](unit-reference-course-ledgers.json)已经为每个单元建立了八个区块，并交叉核对了`parentRouteNode`、`returnTo`、`oneQuestion`和`onePrimaryAction`。当前35/35项都明确标成`reference: missing`、`successor: missing`、`releaseStatus: not_open`；生成骨架不是填充内容，也不增加任何策略答案。

这份账本把“仓库有什么”转换成“每个课程单元要怎样被核对”。它目前是对照合同和空账本规范，尚未填入A72的匹配策略，也未发布35项精确练习；机器校验只证明字段、身份和停止规则完整，不证明策略或学习效果。
