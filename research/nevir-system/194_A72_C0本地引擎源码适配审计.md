## 这次核对证明了什么

本地固定提交是 `9d1509fe5077d019825f833eed04b16d342dfda1`，crate 版本为 `0.1.0`，许可证是 `AGPL-3.0-or-later`。它不是一个只给总体下注率的表格工具，而是能把带权双方范围、公共牌、底池、后手和行动树组织成 `ActionTree`，在求解后返回具体动作、逐手策略、到达权重、权益、EV和后继状态。

我先用当前工具链执行了：

```text
cargo test --offline --all-targets
```

默认编译在 `src/action_tree.rs` 的 393、396、408 行被当前 Rust 的 `dangerous-implicit-autorefs` 默认 lint 拦住，共 3 个错误。这个旧提交不能在当前环境里把兼容旗标隐藏掉，否则“可复现构建”会被误判成无条件可构建。

随后用明确登记的兼容旗标重新执行：

```text
RUSTFLAGS=-A dangerous-implicit-autorefs cargo test --offline --all-targets
```

结果是库测试 38 个通过、4 个忽略，Kuhn 测试 1 个通过，Leduc 测试 2 个通过。这个结果只证明固定源码在记录了兼容旗标的环境下能通过自身回归测试；它没有证明 A72 的完整策略已经求出来。

## A72 根节点实际动作金额

用冻结的 A72 双方范围、`As7h2d`、550 芯片起始底池、9750 芯片有效后手和以下行动树参数构建实际 `PostFlopGame`：

```text
翻牌下注：33%, a
转牌/河牌下注：75%, a
面对下注加注：2.5x, a
add_allin_threshold = 0
force_allin_threshold = 0
merging_threshold = 0
```

根节点运行时返回：

```text
[Check, Bet(182), AllIn(9750)]
```

这里 `182` 是按 550 芯片底池构建出的实际整数筹码金额，不是页面上的约数；`AllIn(9750)` 是实际后手金额。这个探针与已有树预检的根菜单一致，因此 C0 至少已经有了“固定源码 + 固定输入 + 根菜单实际金额”的可复核证据。

同一个探针还读到未压缩内存 `10,174,073,380` 字节、压缩估算 `5,189,681,440` 字节。它仍然不能直接分配内存并沿历史调用 `play`：源码明确要求先 `allocate_memory`，而当前 A72 完整树超过保守预算。因此面对下注后的运行时菜单、求解、保存重载还没有被偷偷算成已完成。

## 源码对适配器的硬约束

1. **动作必须存实际对象和金额。** `available_actions()` 返回 `Check`、`Bet(i32)`、`Raise(i32)`、`AllIn(i32)` 等实际枚举，训练器不能只保存“33%”文字或按钮顺序。
2. **机会节点不能把 `Chance(0)` 当成一张牌。** 引擎为了花色同构会把机会动作合并，真正枚举转牌和河牌必须读取 `possible_cards()`，并在课包里保存每张合法牌的点数和花色。
3. **不能让默认合并改变课程菜单。** `merging_threshold` 会合并接近的下注金额；本次探针把它设为 `0`，并把全下阈值也设为 `0`，只保留显式行动尺寸。以后任何配置改变都必须重新检查实际菜单。
4. **策略和事实是不同层。** `strategy()`、`normalized_weights()`、`equity()`和`expected_values()`是不同接口。牌力或权益交叉核对不能替代逐手动作频率。
5. **保存重载有身份条件。** 只有已求解游戏才允许保存；`set_target_storage_mode`还能删除未来街次存储，所以保存文件必须同时带输入指纹、目标街次、压缩方式和存储模式。
6. **精度必须登记。** 源码大部分使用32位浮点，压缩模式使用16位整数加缩放因子。课程判分若需要频率边界，不能只写“引擎输出”，必须记录是否压缩和量化规则。

## C0 当前身份

现在可以开放：

- 固定提交和许可证的作者侧构建复现；
- A72 根节点真实动作金额探针；
- 内存估算和资源停止记录；
- 适配器必须保存动作对象、金额、同构机会和精度信息的开发约束。

- 把根菜单当成所有历史节点菜单；
- 让用户按求解器结果精确答下注策略；
- 声称已经有动作后的范围；
- 声称保存重载后策略身份一致；
- 声称已经具备连续三街或 NL50 证据。
