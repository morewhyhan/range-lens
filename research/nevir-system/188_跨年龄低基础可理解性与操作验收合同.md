## 这份合同把“低基础到小学生或老奶奶也能跟”变成可观察标准

这里的“小学生或老奶奶”不是按年龄推断能力，也不是对任何人的学习结果作保证。它代表一个最低设计假设：用户扑克基础很弱，阅读或反应速度较慢，工作记忆有限，可能需要较大的视觉目标和更长的停留时间。

因此不能只说“页面简洁”。必须分别验证四件事：

1. 用户看得懂当前一句话；
2. 用户看得出当前在整条路线的哪一站；
3. 用户能完成当前唯一动作；
4. 用户能把结果交给下一站，并在出错后回到正确位置。

任何一个通道失败，都会让用户从主线掉出去；平均正确率不能把某个通道的失败掩盖掉。

## 一、四个通道的最低设计规则

| 通道 | 用户必须能做什么 | 页面必须提供什么 | 不能用什么替代 |
|---|---|---|---|
| 语言 | 不看术语也知道这句话要他做什么 | 一句普通话、一个动词、一个对象 | 用 EV、GTO、CFR 或英文缩写猜题 |
| 视觉 | 一眼找到当前牌、行动者、价格和变化 | 图形与文字双重标记，稳定位置，当前变化高亮 | 只用颜色、只用微光或只靠图例 |
| 记忆 | 做完当前题后知道下一步和返回点 | 固定路线条、交接卡、父帧快照 | 把下一步藏在菜单或解析长文中 |
| 操作 | 能点到、改正和重新提交唯一动作 | 大目标、明确选中态、可撤销/可重试 | 倒计时、拖拽精度或同时填多项 |

字体放大、牌面放大、朗读或降低动画速度可以作为辅助设置；这些设置不能改变题目顺序、判分身份或父子返回关系。辅助设置失效时，核心路线仍必须可以靠文字、图形和固定位置完成。

## 二、第一次跟练的可理解性检查

首遍每个可见停点都要留下同一组观察结果：

```text
看到什么 → 这一步问什么 → 用户做了什么 → 结果交给谁 → 错了回哪里
```

用户不需要复述技术定义，但必须能用自己的话说出：

- “我现在要看什么”；
- “我这一步要点什么或填什么”；
- “做完以后下一步在哪里”；
- “如果错了，要回到哪一块”。

主持者不能用暗示答案的问题替用户补齐。若用户说“我不知道”，系统按错误记录，显示当前层解析，并沿原路线继续；主持者只记录用户卡住的地方，不能把口头讲解后的正确算作独立通过。

## 三、跨年龄首遍试读的统一任务

不把参与者分成“聪明”或“不聪明”，只观察同一条路线在不同负荷下是否仍可使用。每位参与者都按同一顺序完成：

1. `L0—L4`：说出桌面、位置、前序动作和范围交接；
2. `p1—p7`：沿翻后七步完成一手带练；
3. 关闭步骤标题：指出当前层和下一层；
4. 打开一个子题再关闭：找回原父帧；
5. 注入一个错误交接：回到最近缺失层；
6. 只改一个字段：指出受影响层并完成同类动作；
7. 走一条未见短路线：不看答案先交付当前层结果。

每项都记录首答、主持者是否说出额外提示、用户是否自己找到下一步、错误层、回退点和退出点。阅读慢或操作慢本身不是错误；只有需要主持者替他决定“看哪一层、点哪个答案、回哪里”时，才说明页面没有把结构交给用户。

## 四、通过条件不是一个总分

跨年龄可理解性必须按停点和通道分别检查：

| 检查 | 通过的可观察行为 | 失败后的修订方向 |
|---|---|---|
| 语言理解 | 用户能用自己的话说出当前问题 | 改短句、去术语、把对象写清楚 |
| 当前定位 | 用户能指出路线条中的当前站 | 强化固定位置、文字和图标双标记 |
| 主要动作 | 用户能独立完成一个点击/填值 | 拆动作、放大目标、减少同屏控件 |
| 交接记忆 | 用户能说出下一步或返回点 | 增加交接卡和上一帧小快照 |
| 父子恢复 | 子题关闭后能继续原父题 | 修复状态保存，禁止新题覆盖旧快照 |
| 错误恢复 | 错误后能回到最近缺失层 | 缩小反馈范围，明确回退按钮和原因 |
| 单变量迁移 | 用户先指出改变字段再作答 | 取消多变量混题，保持同一坐标和历史 |

任何核心停点在首答阶段都需要主持者替用户指出当前层，首遍就不能标记为“结构建立”。同一停点反复失败时，先改页面和题面，再增加题量。

## 五、首遍必须留下什么样的脑内结构

首遍的目标不是让用户当场答对很多题，而是让他能在隐藏步骤标题后复述一条可执行的路线。至少要观察六件事：

1. 能按顺序说出从进入到回放的各层；
2. 能在三个未见父帧中指出当前层和下一层；
3. 能用普通话说出每一步交给下一步的东西；
4. 遇到两个故意缺失字段时，能回到最近缺失层；
5. 只改一个字段时，能指出需要重新检查哪一层；
6. 缺少参考或后继时，能说出“为什么停”和“停在哪里”。

这六项必须发生在解释之后的第二次正确之前；速度、总分和“听完解析后答对”都不能替代首答证据。机器合同中的 `onePassArchitectureEvidence` 固定了这些检查，防止把“按钮走完一遍”误判成“脑中已经有了结构”。

## 六、页面必须保持的低负荷结构

每屏只保留五种东西：

1. 当前站和相邻方向；
2. 当前父帧的必要事实；
3. 一句普通话问题；
4. 一个主要动作和“我不知道”；
5. 一张交接卡或明确停止卡。

解析、公式、完整范围、原始资料和术语放在答后或抽屉中。它们可以帮助理解，但不能成为用户找到下一步的唯一途径。牌张、金额、行动者和范围图必须同时提供文字/数字与视觉标记，颜色不能承担唯一语义。

## 七、和学习释放的关系

这份合同只决定用户是否能进入释放链，不改变策略答案：

```text
可理解首遍 → 结构回放 → 同父单元 → 单变量迁移
→ 延迟回忆 → 陌生慢速单步 → 连续三街 → 目标级审计
```

可理解不等于会做；会做单步不等于会走连续路线；连续路线通过也不等于NL50。任何阶段都必须继续使用187号父帧、交接、后继和停止不变量，以及183号单元释放闸门。

## 八、当前证据边界

本合同规定了跨年龄低基础用户的可观察最低标准，但尚未有真实参与者试读。因此当前只能说“已经把可理解性拆成可检查的任务和字段”，不能说小学生、老年人或任何具体用户已经能够完成训练，更不能据此宣称NL50。正式发布前必须用真实首遍、错误恢复、单变量迁移和未见短路线记录来修订题面。

## 九、实际记录不能只保存“做对了几题”

每个停点都要保存一条独立记录，而不是只累计一个总分：

```text
参与者与负荷画像 → 停点与路线版本 → 首答
→ 主持者提示次数/类型 → 当前层是否自己找出
→ 主要动作 → 下一层/返回点 → 错误层
→ 父帧是否恢复 → 本题改变字段 → 后继或停止是否自己找出
```

提示类型必须区分“重复问题”“指向已显示事实”“指向路线标记”“揭示事实”和“引导答案”。最后一种提示不算独立通过；看完解析后的第二次正确只用于诊断，不覆盖首答。阅读和操作耗时可以记录，但不能拿速度淘汰低基础用户，也不能把速度当成结构掌握证据。空缺观察必须标记为未知，不能用平均分补上。

发布状态也要分开：纸面合同、正在试读、需要修订、跨年龄小规模试读通过、结构释放可用。只要任何核心停点在语言理解、当前定位、父帧恢复、错误回退或未见短路线中的一项失败，就停在“需要修订”；不能用其它停点的高分抵消。即使跨年龄小规模试读通过，也只证明页面可以进入结构释放链，不证明匹配策略准确、连续三街能力或 NL50 准备度。
