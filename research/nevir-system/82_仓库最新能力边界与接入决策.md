# 仓库最新能力边界与接入决策

## 1. 本次核对的对象与结论

本次重新核对用户指定的两个入口及其直接相关仓库：

- [gto-wizard/equity-calculator](https://github.com/gto-wizard/equity-calculator)
- [b-inary/postflop-solver](https://github.com/b-inary/postflop-solver)
- [b-inary/wasm-postflop](https://github.com/b-inary/wasm-postflop)
- [b-inary/desktop-postflop](https://github.com/b-inary/desktop-postflop)
- [b-inary/holdem-hand-evaluator](https://github.com/b-inary/holdem-hand-evaluator)

结论先写清楚：这些仓库可以组成“作者侧计算与核对管线”，不能直接组成“面向初学者的完整训练器”。其中权益计算器负责把具体手牌和公共牌算到摊牌，b-inary的求解器负责在明确的范围、历史、筹码和有限行动树下求策略参考，WASM/桌面项目负责把同一引擎做成浏览器或桌面界面，手牌评估器负责牌力判断。课程化、简化、逐题判分、视觉因果解释和学习者迁移仍必须由我们自己完成。

## 2. GTO Wizard权益计算器

README明确写的是德州扑克与奥马哈的精确权益：枚举所有合法跑牌，不使用抽样；输入是具体手牌、公共牌、死牌和至少两手牌，输出是摊牌后的胜率、平局与分池权益。[项目说明](https://github.com/gto-wizard/equity-calculator#hand-equity-calculator)也要求C++编译器和CMake 3.28以上，并以Python扩展形式测试。

这对我们的直接帮助有三项：

1. 读牌练习可以精确核对最佳五张、牌力顺序和每张未来牌的结果。
2. 听牌练习可以把合法跑牌枚举成“哪些牌改善、改善到什么牌力”的事实层。
3. 跟注收益的事实层可以用分池权益进入底池赔率公式，避免把平局事件概率误当成可分到的池份额。

它没有完成以下工作：

- 没有底池和下注历史的策略树。
- 没有下注、过牌、加注的频率或响应政策。
- 没有范围权重、前序筛选和行动后范围的课程语义。
- 没有解释为什么某个动作在一个范围对抗中成立。

因此它只能放在 `derived_fact` 层，不能单独生成“下注还是过牌”的答案。用它遍历加权范围也要由我们处理组合质量、双方撞牌、条件分母和观察视角。

当前公开仓库页面没有显示明确的许可证文件或许可证元数据。研究可以继续；在实际复制、修改、打包发布前必须重新确认许可，不把它预登记为可直接分发依赖。

## 3. b-inary求解器家族

### 3.1 postflop-solver：参考策略的核心候选

项目README把它定义为Rust翻后求解器，使用Discounted CFR；不做普通抽象，但会合并同构的转牌和河牌机会。它支持双方加权范围、行动树、筹码、抽水、节点锁定、策略与EV导出，并声明可处理六人桌中最多四名已弃牌者的bunching效应。[实现说明](https://github.com/b-inary/postflop-solver#implementation-details)同时明确主要使用32位浮点、汇总时临时使用64位，并支持压缩保存。

对我们的作用：在固定的翻前范围、公共牌、历史、尺寸和后续政策下，产出课程简化的参考基线、逐手动作频率、动作后范围和后继节点。

它的边界必须写进数据合同：

- 这是有限行动树下的近似求解，不是自动覆盖所有现实下注尺寸。
- `no abstraction`不等于“没有行动树限制”；未放进去的尺寸没有被比较。
- 求解器README明确说开发在2023年10月暂停，且库是GUI后端，接口可能在不改版本号时发生破坏性变化。[项目说明](https://github.com/b-inary/postflop-solver#postflop-solver)
- 仓库是AGPL-3.0，集成和分发必须单独做许可证评估。[许可证](https://github.com/b-inary/postflop-solver/blob/main/LICENSE)

所以它应固定提交、保存输入指纹和原始输出，不应在浏览器端每道练习实时求解，也不应把一次收敛指标直接当作课程简化无损证明。

### 3.2 WASM Postflop：浏览器运行参考

WASM项目把同一求解器放入浏览器，目标是免费、开源、跨平台和沙箱执行；官方比较中，WASM约比桌面端慢一倍，内存和计算量仍取决于行动树。[README](https://github.com/b-inary/wasm-postflop#wasm-postflop)

它能帮助我们理解如何把“范围、节点、动作、结果”呈现在浏览器，但不应直接复制成训练器页面。当前项目本身也明确标记为开发暂停，训练模式只是路线图中的未来项目，不是现成能力。

### 3.3 Desktop Postflop：桌面形态参考

桌面项目是WASM项目的Tauri原生端口，共享引擎和用户界面；优势是更快、可使用超过4GB内存，支持Windows 10/11，并提供安装包或便携EXE。[README](https://github.com/b-inary/desktop-postflop#desktop-postflop)

它对我们最有价值的是桌面信息组织、范围查看、节点导航和结果层级，而不是直接作为产品底座。它公开的路线图把“保存／加载结果、手牌筛选、节点锁定、聚合报告、GTO training mode”等列为待做项目，说明求解器界面和训练系统之间仍有明显距离。

该仓库同样是AGPL-3.0，并且项目已暂停开发。我们可以借鉴交互和数据表达，暂不复制其产品代码。

### 3.4 holdem-hand-evaluator：牌力事实组件

该仓库只做德州扑克牌力评估，README给出约1.2G次/秒的顺序评估、约212KB查表、无外部依赖和测试说明，许可证为MIT。[README](https://github.com/b-inary/holdem-hand-evaluator#holdem-hand-evaluator)

它适合放在读牌事实层：五张最佳牌、牌型排序、摊牌比较和题目生成前的合法性检查。它不产生策略、范围、下注尺寸或解释，因此不能越级进入策略判分。

## 4. 对我们的系统应怎样接

不把这些仓库直接暴露给学习者，而是分成四层：

```text
作者输入层
  → 固定翻前范围、历史、牌面、筹码、抽水、行动树和版本指纹
参考计算层
  → 求解器策略/EV/后继 + 权益枚举 + 牌力评估
课程政策层
  → 依据课程资料把参考压成可执行的0/50/100或动作集合
学习题包层
  → 一屏一个问题、范围前后图、错误分层、后继和迁移题
```

具体职责如下：

| 组件 | 放入哪一层 | 能产生什么 | 不能产生什么 |
|---|---|---|---|
| equity-calculator | 事实计算 | 摊牌权益、跑牌事实、分池份额 | 策略频率、课程答案 |
| holdem-hand-evaluator | 事实计算 | 牌力类别、最佳五张、合法性 | 下注策略 |
| postflop-solver | 参考计算 | 有限树策略、EV、动作后范围、后继 | 自动课程、全现实尺寸、学习效果 |
| wasm-postflop | 研究/浏览器参考 | 浏览器求解与结果查看的工程样式 | 我们的低认知训练流程 |
| desktop-postflop | 研究/桌面参考 | 桌面布局、节点浏览、结果呈现 | 我们的教学路径和简化判分 |

训练器只读取已经完成来源溯源、条件指纹和发布审核的静态课包。学习者答题时不等待求解，也不暴露完整控制台；答后才按需显示课程规则、参考支持、范围变化和差异边界。

## 5. 最终接入决策

当前建议采用“借鉴、隔离、静态发布”的方案：

1. 借鉴b-inary桌面/WASM的范围图、节点树和前后视图，不复制其页面为训练器。
2. 在作者侧固定提交运行postflop-solver，输出带版本、配置哈希、行动树哈希、收敛和原始输出哈希的参考包。
3. 用equity-calculator与holdem-hand-evaluator做独立事实校验，不让一个求解器同时证明自己的牌力和策略。
4. 把课程简化作为独立政策版本，同一输入下比较动作差、EV差、范围差和后继缺口。
5. 只有来源、参考和后继都闭合的单元才开放精确判分；否则降级为事实/演示或停止。

这条路径能让“GTO参考→课程简化→视觉练习”真正接起来，但当前仍没有完成全35项逐题参考绑定、完整三街课程包、学习者试读或NL50结果证据。它是下一步的技术和证据路线，不是完成声明。
