# 35项嵌套教学顺序与覆盖闭环

## 1. 为什么还要编这一层

35项是作者后台的完整能力清单，不应该成为学习者首页上的35个按钮。此前的挂接矩阵已经说明每项属于“当前比较”或“行动后更新”，但还需要一个明确的二次学习顺序：第一次先建立整手牌的骨架，第二次才从当前父问题逐项展开；每个子项完成后回到父问题，不能在子项之间平铺跳转。

这份顺序不是把35项删成少数示例，而是把它们放进一个只有一个入口、一个当前子项和一个返回点的队列。这样“全面”与“简单”同时成立：全面由后台覆盖矩阵保证，简单由前台只显示当前父子关系保证。

## 2. 学习者实际看到的两遍路线

### 第一遍：只建立骨架

学习者只走：

```text
定位桌面
→ 读牌面
→ 看自己的牌力
→ 形成对手可能范围
→ 比较当前动作
→ 执行动作并记账
→ 新行动或新牌后更新
→ 结算并回看
```

第一遍每组只出现一个代表问题。页面不显示35项编号，不要求先学习“阻挡牌”“价值牌”“保护”“再加”等专题名。子层需要时从当前父问题打开，关闭后恢复原来的牌面、历史、投入、首次答案和下一步。

### 第二遍：沿父问题逐项展开

第二遍固定按以下顺序进入：

1. **无人下注时比较（1.1—1.8）**：先比较谁会付款、谁可能反超、谁能改善、下注与过牌的增量，再处理不同尺寸；
2. **面对下注时比较（2.1—2.7）**：先读价格和对手下注范围，再比较跟、弃、加及当前赢面与改善的组合；
3. **面对加注时比较（3.1—3.6）**：先重建新价格、加注范围和合法后手，再比较跟、再加或弃；
4. **对手回应后的更新（4.1—4.6）**：逐项处理跟注、过牌、自己的行动范围、历史差异、账本顺序和结果隔离；
5. **新牌出现后的更新（5.1—5.8）**：逐项处理自己改善、对手改善、听牌完成、公共牌配对、高牌、空白牌、组合移除和河牌关闭未来机会。

每一组内部仍然一次只打开一个单元。当前单元没有匹配来源或可达后继时，显示“本题只能练事实/示范”，停止精确判分并返回父问题；程序不得自动用下一个相似单元填空。

## 3. 每个单元的统一屏幕合同

每个35项单元都具有相同的外壳：

```text
当前父问题
  → 一个必要事实
  → 一个主要问题
  → 一个主要按钮
  → 对/错或资料不足
  → 只解释本层变化
  → 必要时显示同坐标范围前后图
  → 返回原父问题
  → 打开同组下一个单元
```

这里的“范围前后图”只在题目需要时出现；事实单元可以只显示实体牌、最佳五张、补张或账本。无论显示哪一种，父帧都必须保留，且首次答案和提示后答案分开记录在当前会话中。

## 4. 全覆盖如何不变成平铺

覆盖按三层记录：

| 层 | 学习者看到什么 | 作者后台检查什么 |
|---|---|---|
| 主线层 | 7个翻后父步骤和当前所在位置 | 街次、角色、行动状态、后继是否存在 |
| 组层 | 当前父问题下的5个能力组 | 1—5组是否按顺序解锁、每组是否能返回 |
| 单元层 | 当前组中的一个35项单元 | 来源、事实、参考、课程政策、范围图、迁移和试读状态 |

因此，35项“都存在”只说明覆盖登记完成；只有每项都通过来源、匹配参考、课程编译和学习者试读，才可以从“纸面嵌套”升级为“可发布单元”。当前35项仍全部是 `paper_nested_route_not_released`。

## 5. 解锁与停止规则

- 第一遍不开放35项列表，只从父问题进入代表单元；
- 同一组内，后一个单元必须在前一个单元关闭并返回父问题后才可打开；
- 下一组必须在上一组关闭后才可进入；
- 未知答案按错误处理，但“资料不足”不能伪造为策略错误；应显示当前身份并停止精确判分；
- 没有动作后范围时，不能解释范围变化；没有合法后继时，不能继续生成下一街；
- 任何重答都不能覆盖首次答案；帮助撤除后要在相邻未见题上复用同一父子顺序。

这些规则保证学习者始终知道“我现在在哪一层、这一层只解决什么、完成后回到哪里”，同时让作者后台能够检查每一个未覆盖或未验证的能力点。

机器清单已经生成，包含35个单元的全局顺序、组内顺序、父节点、返回点、证据身份和停止条件，见 [nested-35-route.json](nested-35-route.json)。当前状态仍是：纸面嵌套队列已编译，完整匹配策略、连续课包、真实低基础试读和NL50对标均未完成。

下一步应从每一组各选一个单元，接成同一父帧下的代表性连续课包；先验证“进入→回答→解析→返回→下一项”闭环，再按同一编译规则扩展剩余单元。增加首页按钮或重复局部题不能替代这项验证。
