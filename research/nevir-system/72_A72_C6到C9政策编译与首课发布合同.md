# A72 C6到C9政策编译与首课发布合同

2026年10月21日。本合同接在65号A72 C0—C5参考请求之后，定义“拿到完整参考以后”怎样不跳步地变成首课。它不假设C2—C5已经完成，也不把QQQ工程候选替换成A72课程参考。

## 1. C6：从参考策略编译成课程政策

C6的输入必须同时有：

- C0冻结的游戏配置、范围和动作树；
- C2—C5原始逐手策略、EV、到达权重和后继；
- 用户资料明确要求的简化动作、尺寸和权重；
- 课程简化前后受影响的祖先节点。

编译器按以下顺序工作：

~~~text
保存原始ReferencePolicy
→ 写出CoursePolicy的动作菜单与频率变换
→ 在同一配置上重放CoursePolicy
→ 重新计算当前节点和受影响祖先的EV、范围和后继
→ 记录动作差、范围差、后继缺失和适用边界
→ 只有通过差异审查才进入课程题
~~~

不能把“参考有33%和75%”直接删成一个按钮后，再把受限树里的100%称为原始GTO答案。删掉尺寸、合并频率或删除加注都会改变祖先决策，必须重新评估。

C6输出：

~~~text
reference-policy.json
course-policy.json
simplification-report.json
policy-range-views.json
policy-successor-index.json
policy-release-status
~~~

若某一动作没有后继，课程政策只能发布到事实或示范；不能让训练器自动填过牌、弃牌或随机响应。

## 2. C7：编译首课帧

C7把C6的课程政策挂入规范L0—L4→p1—p7，不新增平铺栏目；旧L0—L8只作作者侧宏观映射。首课必须从一手完整局面开始，沿以下顺序走：

1. L0显示六人桌、100BB、位置和训练目标；
2. L1—L3使用用户翻前图完成场景、格子和动作；
3. L4显示翻前动作形成的双方翻后起始范围；
4. L5让用户定位行动者、历史、底池、后手和价格；
5. L6依次打开牌面、牌力、范围和动作比较；
6. L7让动作后范围、回应、新牌和金额进入下一父帧；
7. L8完成结算、错误层回看和一处迁移。

每个帧必须绑定：

~~~text
frameId
parentFrameId
returnTo
visibleState
oneQuestion
onePrimaryAction
answerPrecision
coursePolicyIdentity
rangeViews
successorIds
helpLevels
errorLayer
unknownCountsAsError
~~~

教师答案和参考原始数据不能进入公开题面。用户只看到当前需要的输入、一个问题和一个主要动作。

## 3. C8：纸面和机器验收

C8在真实试读前独立复核首课：

| 检查 | 必须证明 |
|---|---|
| 牌张 | 公共牌、底牌、最佳五张、撞牌和补牌合法 |
| 金额 | 底池、投入、后手、退款和结算守恒 |
| 范围 | 13×13坐标、实体组合、物理过滤和行动筛选分开 |
| 参考 | 动作ID、金额、频率、EV、到达权重和版本一致 |
| 后继 | 每个正支持动作和新牌能定位到下一帧或明确终点 |
| 教学 | 首答、帮助、重答、错误层和返回点齐全 |
| 题面 | 公开题不含答案、来源评语和教师字段 |

C8的机器通过不能替代学习者试读。任何一个检查失败，首课身份降级或停止。

## 4. C9：首次真实试读和冻结

C9使用69号试读脚本，主持者不提示步骤名和考点。最少需要观察：

- 用户能否从L0走到L8；
- 用户是否在p1之前直接猜动作；
- 错误后是否回到原父帧；
- 是否能恢复七步顺序；
- 是否能在未见局面指出下一层；
- 是否能完成一个单字段迁移；
- 课程解析是否使用了题面没有的资料；
- 首答和帮助后答是否保持分离。

发现理解问题时只修改一个变量，再用未曝光局面复测。发现策略或后继问题时，先退回C6或C5，不用教学文案掩盖数据缺口。

C9通过后，课包只能获得以下身份之一：

~~~text
postflop_demonstration
course_policy_practice
matched_strategy_practice
~~~

是否进入matched_strategy_practice，取决于C0—C8的参考和差异证据；C9只证明首遍可试读，不能把学习者结果升级为NL50能力。
