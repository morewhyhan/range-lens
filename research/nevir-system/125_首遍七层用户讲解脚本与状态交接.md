# 125｜首遍七层用户讲解脚本与状态交接

2026年10月22日。本稿把首遍的七个父层写成用户真正听得懂、点得明白的语言。它不把技术概念删掉，而是把技术概念放到用户已经完成当前动作之后；用户先知道“现在看什么”，再逐步理解为什么。

## 1. 一手牌只沿这一条话术走

| 层 | 页面只问一句 | 用户交付什么 | 交给下一层 |
|---|---|---|---|
| p1 现在发生什么 | “现在轮到谁？前面发生了什么？如果继续，要补多少钱？” | 行动者、历史、待补和后手 | 当前状态 |
| p2 我的牌 | “我能组成的最好五张是什么？还可能变成什么？” | 最佳五张、牌型、改善牌 | 牌面事实 |
| p3 谁可能拿什么 | “哪些组合不可能、变少或留下？” | 范围拥有者、实体冲突、行动筛选身份 | 范围快照 |
| p4 比较什么 | “现在合法的选择和价格是什么？” | 当前动作集合、价格、课程规则或参考身份 | 选择状态 |
| p5 怎么做 | “点哪个按钮？投入多少？接下来轮到谁？” | 动作、金额、下一行动者 | 账本状态 |
| p6 什么变了 | “这次回应或新牌具体改变了什么？” | 只更新的一项、动作后范围、新行动者 | 新快照 |
| p7 到哪里了 | “最后发生什么？如果错了，错在哪一层？” | 终局、结算和错误回退层 | 复习或下一手 |

用户第一次不需要背 `p1`、`p2` 这些名称。页面只显示上面的一句普通话；答后再显示技术别名和图表。下一层只有在上一层的交接字段齐全时才打开。

## 2. 每层的讲解边界

- p1 不让用户看到牌就直接猜下注；先把人、动作和钱摆好。
- p2 不从“顶对”“听牌”跳到动作；先确认最佳五张和改善牌。
- p3 先区分实体冲突、行动筛选和资料未知；没有参考时停在事实层。
- p4 只比较当前合法按钮、价格和有依据的后续；不把牌名变成口诀。
- p5 动作、金额和行动权必须同时正确；只点按钮不算完成。
- p6 一次只突出一个变化；不能把整手牌重置。
- p7 先分开当时决策和后来结果；输赢不能改写首答。

## 3. 低基础用户的反馈格式

每次反馈都按三句说：

1. **先告诉他对不对**：对／错／不知道；
2. **只指出当前层**：状态、牌面、范围、比较、金额、更新或结算；
3. **告诉他回哪里**：回到哪一层、只重新看哪一个对象。

例如：“错在范围。你把‘A♣被自己拿走’看成了‘对手因为下注弃掉’。回到范围图，只比较动作前和物理过滤后两张图。”

技术词如 `EV`、`阻挡牌`、`频率`、`范围优势` 只能作为答后别名，不能作为唯一导航。页面不能要求用户先理解这些词才知道要点哪里。

## 4. 一遍结束后不再给答案提示

首遍结束时收起七个标题，只给一张未见牌局，按以下顺序让用户自己恢复：

```text
先找谁动和钱
→ 再看牌面和自己的牌
→ 再看双方范围怎么留下
→ 再比较合法动作
→ 再填金额和行动权
→ 再更新回应或新牌
→ 最后结算并找错层
```

随后只改变一个字段做迁移。用户若不知道下一步，回到最近缺失层；不重新把全部专题平铺出来。
