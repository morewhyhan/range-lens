# 首遍代表题与19帧主线整合合同

## 1. 为什么需要整合合同

99号把p3范围桥插入了首手19帧，100—101号又选出五张代表卡。但一手真实历史不一定同时自然出现“无人下注、面对下注、面对加注”三个比较状态。若把代表卡直接追加到主线，用户会感觉牌局突然换了；若把它们做成首页按钮，又破坏了嵌套结构。

解决方式是：主线仍只走一手牌；代表卡从当前父帧按需打开。与当前历史不相同的卡片使用“教学短例子快照”，打开前保存父帧，关闭后恢复原牌、历史、金额、范围和首次答案。短例子只教当前关系，不把另一局面伪装成原牌局的连续后继。

## 2. 首遍整合路线

```text
19帧主线
  S04 → R01(p3范围事实) → S05(p4无人下注)
                         ├─ REP_1_5 同一父帧内比较过牌/下注
                         ├─ REP_2_1 打开“面对下注”的短例子
                         └─ REP_3_1 打开“面对加注”的短例子
  S06 → S07 → S08 → S09 → S10 → S11
                              ├─ REP_4_5 在回应更新父帧内算账本
                              └─ REP_5_7 在新牌更新父帧内划掉冲突组合
  S12 → S13 → S14 → S15 → S16 → S17 → S18迁移检查
```

用户不会看到这张树，也不会看到“REP”编号。屏幕只显示当前父问题下的一个“打开一个短例子”按钮；完成后回到原来的下一步。

## 3. 三种子层身份

| 子层类型 | 使用代表卡 | 进入时发生什么 | 退出时恢复什么 |
|---|---|---|---|
| 同一状态 | 1.5、4.5、5.7 | 沿用当前牌面、历史和账本，只打开本层问题 | 父帧全部字段和首次答案 |
| 教学短例子 | 2.1、3.1 | 保存父帧哈希，载入声明过的最小短例子 | 原牌局，不把短例子动作写入主线 |
| 资料抽屉 | 参考来源、公式和范围图 | 只读查看，不改变题面和行动权 | 原父帧和当前焦点 |

REP_2_1和REP_3_1必须标记为教学短例子，因为原首手主线未必处在面对下注或面对加注状态。短例子不能自动生成下一街，也不能让学习者误以为已经在原手牌执行了该动作。

## 4. 一次只开一个子层

- 子层打开前保存 `parentFrameHash`、`routeNode`、`returnTo` 和 `firstAnswer`；
- 子层中只能有一个问题和一个主要动作；
- 子层结束后恢复父帧，并显示“回到刚才的问题”；
- 子层答案不写入主线策略、不改变主线账本、不解锁下一街；
- 同一父帧的第二个子层必须在第一个关闭后才能打开；
- 资料不足时子层可以降级为事实/示范，但不能用短例子填充精确策略。

## 5. 首遍结束时的用户体验

用户只记得一条路线：先把局面看清，再看牌，再看双方可能拿什么，然后比较眼前动作，做动作，等回应或新牌，更新后继续，最后结算。代表卡让他在同一父层短暂看到“面对下注”和“面对加注”也遵循同一骨架；它们不会变成额外菜单。

首遍通过仍要另做顺序恢复、层级定位和单变量迁移。子层数量或短例子完成数不能代替真实学习者证据。

机器可读整合合同见 [first-pass-integration-contract.json](first-pass-integration-contract.json)。
