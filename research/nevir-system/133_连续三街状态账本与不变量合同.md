# 133｜连续三街状态账本与不变量合同

这份合同把“从翻牌慢慢走到河牌”从一串页面连接成一个可以逐步复核的状态账本。它规定每个事件允许改变哪些字段、哪些字段必须保持不变，以及资料或后继缺失时为什么必须停在当前父帧。

## 一、每个连续节点保存什么

把第`t`个节点写成：

```text
S_t = (street, board, heroHole, history, actor, decisionState,
       pot, stacks, committed, rangeSnapshots, denominator,
       sourceIdentity, coursePolicyIdentity, successorIdentity)
```

`heroHole`在主手内固定；对手底牌在摊牌前隐藏；`history`只能追加真实事件；`board`只能在发牌事件增加一张；`rangeSnapshots`必须带拥有者、视角和固定分母。子层打开和关闭只改变可见状态，不写回真实主线账本。

## 二、四类事件的允许变化

### 2.1 行动事件

行动事件必须满足：动作在当前菜单中、行动者正确、金额不超过后手、历史追加一次、底池和后手同步变化：

```text
pot_after = pot_before + moneyAddedToPot − uncalledRefund
stack_after(actor) = stack_before(actor) − moneyAddedByActor + refund
```

过牌不改变底池和筹码；下注、跟注、加注和全下必须记录实际金额；弃牌结束行动权，但不自动删除对手范围或生成新牌。

### 2.2 回应事件

回应事件保持街次和公共牌不变，只追加对手的真实动作和行动权变化。对手跟注后，范围才可以按动作筛选；没有匹配参考时只能记录“后继需要什么”，不能把默认回应写进范围。

### 2.3 新牌事件

新牌事件满足：公共牌长度只增加一张、新牌与所有已知牌不冲突、底池和后手不凭空变化、行动权按新街规则重置。新牌造成的物理移除先于行动筛选；行动筛选若缺参考，保留`unknown`而不是写成0。

### 2.4 结算事件

结算事件只有在弃牌终点或河牌行动结束后发生。它分配底池、记录平分和结果，随后不能再产生行动或新牌。结算结果只能验证终局，不得倒推此前动作正确。

## 三、必须持续成立的不变量

每次事件后自动检查：

1. **牌张守恒**：公共牌、自己的底牌、已知死牌和已亮对手牌互不重复；未亮牌仍在未知集合中。
2. **历史单调**：后节点历史是前节点历史加上一个真实事件，不能删除或重排。
3. **金额守恒**：零抽水研究配置下，底池、各活跃玩家后手、弃牌者已投入和已退款金额守恒；有抽水时额外记录抽水项。
4. **后手非负**：任何玩家后手不能小于0；全下后不能继续增加该玩家投入。
5. **行动权合法**：当前行动者必须是仍在牌局中的玩家，且与上一事件和当前决策状态一致。
6. **范围分母明确**：范围前后图使用同一父节点分母；公共牌物理过滤、行动筛选和重新归一化分别标记。
7. **来源稳定**：参考策略、课程政策和示范身份不会因打开解析或子层而变化。
8. **后继存在**：进入下一节点前，`successorId`存在，或者当前节点有明确停止原因。

## 四、训练器怎样展示连续变化

每次用户完成一个事件，页面只突出一项变化，同时保留上一状态的缩小版：

```text
上一状态 → 本次事件 → 下一状态
```

用户应能直接看到：谁行动、底池变多少、谁还剩多少、范围哪一格变化、下一步轮到谁。若变化来自新牌，先显示牌张的物理影响，再显示有参考时的行动筛选；若后继缺失，显示“资料到这里为止”，不自动跳到下一街。

连续练习的判分不能只看最终按钮。每个节点分别检查：状态识别、事件合法性、金额、范围分母、行动权、后继和结算；一项错误回到对应层，不清空整手牌。

## 五、三街路线的停止和恢复

- 金额不守恒：停在当前执行层，显示投入和退款差异；
- 行动者错误：停在当前局面层，恢复历史和指针；
- 范围分母不明：停在范围层，保留物理图并关闭行动筛选；
- 后继不存在：停在当前父帧，记录停止原因，不随机发牌；
- 结算与历史不匹配：停在账本层，独立重放终局，不能用结果覆盖历史；
- 子层返回丢状态：回到父帧快照，当前节点不允许进入下一步。

## 六、发布边界

不变量通过只证明状态和账本连续，不证明某个动作是GTO。动作后范围、逐手频率和后继仍需匹配参考；课程量化还需通过131号算法；学习者是否能沿路线运行还需132号协议的F2/F3证据。当前已有纸面19帧连续审计，但运行时和完整A72后继仍未闭合。
