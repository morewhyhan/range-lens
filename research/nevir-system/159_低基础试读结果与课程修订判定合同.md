## 为什么还需要一份结果判定合同

已有试读脚本规定“怎么观察”，但还需要规定“观察到什么以后如何改课程”。否则一次试读会变成主观印象：用户卡住了，就同时改按钮、颜色、文案、题目和答案；下一轮即使变好，也不知道究竟是哪一项起作用。

这份合同把一次试读变成版本化的诊断循环：冻结版本 → 观察首答 → 归因一层 → 只改一个变量 → 用未见题复测 → 保留旧版本记录。

## 一、每个停点只记录五类结果

| 结果 | 记录什么 | 不能从它推出什么 |
|---|---|---|
| 找到 | 是否找到入口和当前父层 | 不代表理解策略 |
| 首答 | 第一次未帮助答案 | 不代表路线已内化 |
| 帮助 | 使用了哪一级帮助 | 不代表独立通过 |
| 重答 | 帮助后是否修复 | 不代表首次会做 |
| 迁移 | 未见单变量题是否找对层 | 不代表连续三街或NL50 |

速度只作为描述字段，用来发现停顿和负荷，不作为低基础学习者的通过线。每次判断都必须把首答和重答分开。

## 二、错误归因优先级

同一错误先按下面顺序排查：

1. **输入缺失**：用户必须猜题面没有给出的历史、价格、范围或后继；
2. **状态交接**：父帧、行动者、账本或返回点没有保留；
3. **视觉/文案**：输入存在，但多个参与者无法找到或读懂；
4. **事实理解**：牌面、最佳五张、听牌或实体冲突错误；
5. **策略或编译**：来源、金额、范围后或课程政策互相不一致；
6. **学习者结构**：输入清楚、来源充分，但仍跳过当前层或不能迁移。

前五类必须先处理，不能把它们直接记成学习者“不会”。同一父层出现相同错误时，优先标记课程修订候选；只有数据、页面和答案身份都通过检查，才记录为学习者结构问题。

## 三、版本修订的硬规则

一次修订只能改变一个变量：

- 版面位置；
- 一句提示文案；
- 一个视觉标记；
- 一个帮助等级；
- 一个题面字段；
- 一个返回点；
- 一个来源或策略字段。

不能在同一版本同时改变题目、答案、颜色、路线和金额。修订后必须使用未见题或同父帧新实体复测；重复原题只能验证是否记住了修改，不能验证迁移。

如果修订导致答案身份、来源、范围分母或后继变化，旧版本证据不能转移到新版本，必须重新冻结课包指纹。

## 四、初步试读的决策规则

以下是启动试读时的诊断规则，不是对学习效果的统计保证：

- 一名参与者在一个停点卡住：先记录，不立即改课程；
- 两名或以上参与者在同一停点出现同一种非策略错误：进入页面／文案修订候选；
- 多人因同一缺失输入被迫猜动作：降级该节点身份并补资料；
- 同一版本修订后，未见题仍出现同一层错误：进入结构或数据复核，不再简单增加题量；
- 参与者能答对但不能说出下一层：记录为偶然正确，不能开放下一阶段；
- 帮助后答对但首答错误：只记为帮助下修正；
- 主持者代答后继续：该停点没有独立证据。

这些规则用于决定“下一步改什么”，不用于宣称课程已达到某个通过率。

## 五、怎样逐阶段开放

1. **F0纸面走查**：先确保字段、来源、父帧、金额和后继闭合；
2. **F1形成性试读**：只寻找入口、文案、视觉和归因问题；
3. **F2结构验证**：隐藏标题，检查顺序、交接、错误回退和单变量迁移；
4. **F3慢速执行**：只使用来源充分的未见单步和连续题；
5. **目标评估**：在冻结配置和独立参考完成后，才进入连续目标对标。

低阶段失败时不能跳到更复杂的题。F1没有通过，先修页面；F2没有通过，先修父帧和帮助；F3没有通过，先修数据、策略或执行字段；任何阶段都不能用题量和短期盈利掩盖失败。

## 六、记录边界

训练器只保留当前会话的首答、帮助、重答、错误层和返回点。试读研究日志可以在课包外临时保存版本化结果，但不能把真实姓名、长期成绩或能力等级写入训练器数据库。关闭会话后，产品不声称知道用户是否已经掌握。

## 七、与最终目标的关系

这份合同只能证明“课程如何根据低基础试读被修订”。它不替代匹配GTO策略、动作后范围、连续后继、独立目标评估或NL50真实决策审计。只有这些证据全部具备，才有资格讨论目标级准备度。
