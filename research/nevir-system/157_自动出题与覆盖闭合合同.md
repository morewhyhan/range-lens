## 这份合同解决什么问题

“自动出很多题”不等于从牌面随机抽样。随机抽样可能重复同一个关系、漏掉某一类边缘牌，也可能把没有来源的局面伪装成精确策略题。生成器必须先知道当前父帧、能力单元、来源身份和允许变化的字段，再按覆盖账本取题。

生成器的目标是：在不改变策略权重的前提下，让学习者看到足够多的边缘、内部、纯动作、混合动作和迁移题，并且每道题都能回到唯一父层。

## 一、一道题的身份

每道题必须拥有不可重复的身份：

```text
questionId = hash(
  routeParent,
  unitId,
  sourceFingerprint,
  configurationFingerprint,
  changedField,
  entityHand,
  board,
  actionState,
  queueStage
)
```

相同题面只要改变了帮助等级、首答身份或队列阶段，就必须显式标记为同一实体的不同训练记录，不能冒充新题。只调换按钮顺序、颜色或文案，不产生新题。

## 二、出题前的硬过滤

生成器按以下顺序工作：

1. 锁定当前父帧，不跨位置、街次或行动状态混题；
2. 检查牌张、底牌、公共牌、死牌和实体组合是否物理合法；
3. 检查行动历史、底池、后手、行动者和下注菜单是否一致；
4. 检查来源身份是事实、课程规则、有限模型还是匹配参考；
5. 检查动作后范围、金额和真实后继是否存在；
6. 检查本题允许改变的字段是否只有一个；
7. 通过后才进入边缘／内部／纯／混合分类和队列排序。

没有来源的策略答案、没有后继的连续题、没有固定分母的范围题都在过滤阶段停止，并改为“资料身份或停止理由”练习。

## 三、生成器输出的题包必须长什么样

生成器不是只返回一张牌面和几个按钮，而是返回一个可追溯的小课包：

```text
题目身份与父帧快照
→ 来源和配置指纹
→ 当前可见输入与白话问题
→ 一个主要动作和所需输出
→ 答案身份与判分规则
→ 范围前后图或停止原因
→ 真实后继或停止卡
→ 单变量迁移规格
```

学习者看不到教师答案、隐藏频率、未声明的未来行动或未解决政策。题包必须说明自己是定位题、事实题、课程规则题、匹配参考题、账本题、迁移题还是停止题；题目身份不同，判分规则也不同。这样“自动出题”不会把所有题强行压成同一种策略选择。

题包字段还必须有明确的运行时读取者：`routeParent`供父级锁和返回使用，`parentSnapshotHash`供关闭子层恢复，`unitId`供释放阶段和覆盖账本使用，`sourceIdentity`供判分与停止卡使用，`rangeViewOrStop`和`successorOrStop`供连续性闸门使用，`transferSpec`供单变量迁移使用。没有读取者的字段不能进入可答题包，否则只是“看起来完整”的元数据。

每个父层还要保存覆盖账本：已见题目、已见单元、边缘与内部首答、动作保持对照、单字段迁移、后继闭合和停止身份。题池为空时登记 `unavailable`，不拿相邻牌面冒充；覆盖完成表示“必要身份和证据已经出现”，不表示学习者已经掌握或达到了某个百分比。

## 四、采样比例和策略权重分开

用户可以调节当前父层的曝光比例：

```text
edgeRatio + internalRatio + pureRatio + mixedRatio + transferRatio = 1
```

比例只改变未曝光题面的顺序，不改变：

- 参考策略频率；
- 课程政策权重；
- 范围图分母；
- EV、权益或简化损失；
- 答案的正确性。

如果某种身份题池为空，生成器不能用相邻牌面冒充该身份；如果来源只支持事实，不能因用户选择“边缘优先”而生成动作答案。

## 五、边缘牌怎样被定义

边缘排序使用来源数据计算，而不是凭视觉猜测：

```text
margin = top1Frequency − top2Frequency
supportCount = number of materially supported actions
localEvGap = bestActionEV − secondActionEV
quantizationLoss = minimum course compression loss
```

`edgeScore`只用于排序和抽题。它不能直接作为判分阈值，除非在匹配节点上完成校准。边缘牌可以多出现，但不能因此放大它们在范围或EV中的质量。

## 六、队列如何保证系统性

一个父层的队列依次生成：

```text
定位必做题
→ 同机制题
→ 纯动作／纯事实题
→ 混合动作题
→ 边缘边界题
→ 内部典型题
→ 一个动作保持对照
→ 一个单字段迁移
→ 回到完整父路线的连续题
```

每个阶段只在前一阶段有独立首答记录后开放。题池耗尽后标记覆盖完成；不复制已曝光题面制造虚假题量。连续题必须沿真实后继运行，不能把几个互不相连的牌面拼成一手牌。

`p2`的牌力顺序属于事实子层。生成器可以调用[174号牌力顺序横向短练习](174_牌力顺序横向短练习合同.md)，但必须锁定`p2_board`父帧、隐藏策略控制、完成后返回父帧，并且不能把它混入下注、范围或迁移题池。事实子层答对只交付最佳五张、牌型和比较结果，不改变策略题的覆盖分母。

## 七、覆盖闭合的判定

一个父层只有在以下条件同时满足时才显示“当前覆盖已完成”：

- 必要定位题通过；
- pure、mixed、internal和适用的source_boundary均有题；
- 至少一题边缘牌与一题内部牌完成独立首答；
- 至少一个动作保持对照和一个单字段迁移存在；
- 所有精确策略题有来源、固定配置、动作后范围和后继；
- unavailable题全部保留停止身份，没有被计入策略正确率；
- 当前父层的所有子题完成后能返回原父帧。

“题目数量足够”不等于覆盖闭合；“边缘题比例很高”也不等于策略更接近GTO。

## 八、调度器怎样保证题目仍然属于同一条学习路线

生成器负责“哪些题有资格进入池子”，调度器负责“当前这一刻下一题是哪一题”。两者不能各自维护一套路线。调度器必须先执行同父帧修复，再按释放阶段和覆盖缺口选题；用户设置的边缘比例只能打破同级候选的平局，不能绕过错误回退、资料停止或父层交接。

固定顺序为：

```text
同一父帧与错误层修复
→ 当前释放阶段缺口
→ 当前父层覆盖缺口
→ 到期的间隔回忆
→ 同级候选的边缘/内部比例
→ 稳定题目哈希
```

`wrong`、`unknown`、缺少参考、缺少后继和关闭子层都必须有确定的下一步；跨父层修复、随机生成策略答案、题池为空时用相邻题替代都禁止。机器审计见 [question-scheduler-audit.json](question-scheduler-audit.json) 和 `research-nevir-question-scheduler-audit.mjs`。当前审计只证明两个纸面合同一致，调度器尚未接入运行时。

## 九、翻前与翻后的生成顺序

翻前生成器从场景、图表坐标、边缘格、内部格、相邻位置和大盲尺度进入；翻后生成器必须从当前状态、牌面、手牌、范围、动作、金额、回应／新牌和连续后继进入。翻后不能把牌面随机打散，再把题目标成“连续练习”。

两者共用题目身份、来源过滤、首答记录、错误回退和覆盖账本，但不共用范围政策或动作菜单。

## 十、当前状态和停止边界

这份合同补齐的是自动出题的身份、过滤、排序、覆盖和停止规则。它仍然不是一个已经运行的编译器；边缘阈值没有学习者校准，35项也没有全部匹配参考和后继。因此当前只能说“题目生成规则已经写清”，不能说题库已经足够大、足够系统或已经证明能把学习者带到NL50。
