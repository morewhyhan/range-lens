## 为什么还需要一张桥接表

35 项能力已经有分组和依赖，但“有编号”不等于“用户知道它属于哪一步”。这张合同把每项能力接回首遍八节点：

```text
p4 比较类（1.x、2.x、3.x）
  A1→A2→A3→A4→A5 → A6

p6 更新类（4.x、5.x）
  A1→A2→A3→A4→A5→A6→A7 → A8
```

用户不需要看见 A1—A8 编号。编号只用于后台验收，页面仍然只显示当前父步骤、一个问题和一个子层。每项单元必须在父帧中打开，完成或停止后返回父帧，不能从首页直接进入。

## 每个单元必须留下的桥接信息

| 字段 | 作用 |
|---|---|
| `primaryArchitectureNode` | 这项练习主要训练八节点中的哪一步 |
| `prerequisiteArchitectureNodes` | 进入前必须已经能看懂哪些上游关系 |
| `requiredOutputProjection` | 答完后交给下一步的状态，不只是一个按钮答案 |
| `teachingQuestion` / `evidenceIdentity` | 用户实际看到的问题，以及这道题属于事实、有限模型、课程规则还是参考策略 |
| `requiredOutputs` | 题目完成时必须产生的动作、范围、金额、账本或后继字段 |
| `returnTo` | 子题关闭或资料不足时回到哪个父步骤 |
| `successorOrStopReason` | 有后继才继续；没有就显示停止原因 |
| `flatHomeVisible` | 永远为假，防止 35 项重新平铺 |

比较组的答案必须同时能落到 A5（比较）和 A6（执行）；更新组必须落到 A7（只改变化字段）并把后继交给 A8。范围图、金额账本、行动后继仍然按各自身份保存，不能用“已完成单元”代替真实字段。

## 解锁顺序

1. 先完成 p1—p7 首遍和八节点结构回放；
2. 在 p4 中按 `compare.unopened → compare.bet → compare.raise` 顺序一次只开一个子单元；
3. 返回 p4 后才能进入 p6 的 `update.response`；
4. `update.response` 全部按父帧返回后，才进入 `update.card`；
5. 任何单元缺完整参考、课程后继或必要输入，都停在当前单元，不能用相邻案例填答案；
6. 单元结构解锁不等于策略解锁，匹配参考和学习者迁移仍需单独通过。

## 当前边界

这张桥接表解决“35 项怎样回到同一套脑内骨架”，不宣称 35 项已经有完整GTO策略。当前所有单元仍需逐项补齐来源、范围前后图、课程政策、后继和试读证据；机器桥接只证明覆盖关系和顺序约束已经可审计。

机器版见 [unit-architecture-bridge.json](unit-architecture-bridge.json)。
